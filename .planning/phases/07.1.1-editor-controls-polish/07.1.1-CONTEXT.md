# Phase 07.1.1: Editor Controls Polish - Context

**Gathered:** 2026-11-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Rearrange and restyle the controls of both editors (`tools/map-editor`, `tools/terrain-editor`, built on the shared `tools/editor-shell`) so a tool or setting can be found and changed without reading tooltips: logical tool groups with full-word labels, lighter tooltips, Raise/Lower as a stacked arrow pair on the left, a fixed left sidebar for the active tool's options, and compact content-sized value controls. No new editing capabilities.

</domain>

<decisions>
## Implementation Decisions

### Tool buttons: labels and grouping
- **D-01:** Tool buttons show the **full word** (Raise, Lower, Smooth, Flatten...), not 3-letter abbreviations or single letters. Buttons get wider as a result. The shortcut key stays visible as a small hint.
- **D-02:** Terrain tools are grouped **by job with dividers**: Sculpt (Raise, Lower, Smooth, Flatten) | Select (Grid select, Block, Smooth box) | Surface (Paint) | Roads (Road, Lock, Stamp). Thin separators between groups. Map editor tools are grouped the same way by job.
- **D-03:** Keep the current dock positions and tidy them: no switch to a single vertical rail or single bottom row. Only Raise/Lower leave the top row (see D-04); the remaining tools stay in the bottom toolbar, regrouped with dividers.

### Raise/Lower
- **D-04:** Raise and Lower become a **vertical pair, ▲ over ▼, on the left side of the display**, arrows only (glyphs; the name, key and how-to are in the tooltip). Same active-tool and options behaviour as today. (The user's "up/down buttons stacked vertically on the left" in ROADMAP meant these, NOT Undo/Redo.)
- **D-05:** The **history panel (Undo / Redo / Clear all) stays top-right**, unchanged in position.

### Left sidebar
- **D-06:** Add a **fixed, always-visible, narrow left sidebar**, sized to its content, showing the active tool's name, options and readouts. It replaces the floating flyout that can cover the map, so the main display is never obscured and the user always knows where to look. The canvas fills the remaining space. The Raise/Lower arrow pair sits at the top of it.
- **D-07:** The sidebar is a **shared shell component** used by both editors (consistent with 07.1 D-02). The map editor's Draw road / Select / Eraser options move there too.

### Tooltips
- **D-08:** Tooltips become **lighter and less persistent** via all four of: short by default (name + one short sentence + key; long how-to text only on a longer hover), auto-fade after about 3 s even if the pointer stays, subtle styling (smaller, translucent pill instead of a heavy box), and a longer first delay (about 700 ms, up from 400 ms). The tooltips on/off toggle and per-browser memory from 07.1 D-04 stay.

### Value controls
- **D-09:** Replace the separate −/+ buttons with a **compact value box sized to its content**, containing small ▲▼ arrows inside the box. Applies to **every stepper in both editors** (flyout/sidebar values and the New-popup fields), one shared control.
- **D-10:** The "stepped knob" is **drag-scrub on the value**: click-drag horizontally on the value box steps it (Shift = coarse), and the mouse wheel steps it too. No separate dial widget. Existing step/coarse/min/max/decimals specs and arrow-key/`[` `]` stepping are preserved.

### Claude's Discretion
- Exact pixel sizes, divider styling, icon glyphs, sidebar width, tooltip colours and fade animation.
- Exact map-editor tool grouping (by the same by-job principle as D-02).
- Drag-scrub sensitivity (pixels per step) and whether wheel-stepping needs focus/hover.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `createToolRail` / `ShellTool.dock: "top"`: existing top/bottom split; Raise/Lower are the only `dock: "top"` tools today.
- `createStepper` / `stepper.ts`: stepping, hold-repeat, Shift-coarse, parse/clamp logic can be reused under the new box UI.
- `placeTip` / `tooltips.ts`: delegated tooltip with avoidance of other controls; adjust delay/fade/style only.
- `shell.flyout`: the container the sidebar replaces.

### Established Patterns
- Every interactive control carries `data-tip`; `auditTips` warns on missing ones.
- All DOM text via `textContent`; shell is plain TS + DOM, no framework.
- Pure logic is split out and unit-tested (`dock.ts`, `stepper.ts`, `tip-place.ts`); keep new pure helpers (scrub-to-step maths, tool grouping) the same way.
- `flyoutAnchor` positions the flyout over the bottom row and will become obsolete once the sidebar replaces it.

### Integration Points
- Terrain `RAIL_TOOLS` and the map editor's tool list gain group metadata.
- Flyout content builders in both editors render into the sidebar instead.
- Canvas/viewport layout must reserve the sidebar width; cursor/overlay maths that assume full-width canvas need checking.

</code_context>
