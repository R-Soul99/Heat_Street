# Phase 07.1.1 — UI Design Contract

> Visual and interaction contract for the editor controls polish. Applies to the shared shell (`tools/editor-shell`) and therefore to both `tools/map-editor` and `tools/terrain-editor`. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source tags: [D-nn] = locked in 07.1.1-CONTEXT.md; [existing] = already in `shell.css`/shell TS, keep; [default] = researcher choice inside Claude's Discretion.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla TS + DOM + hand-written `shell.css`; shadcn/React not applicable, per CLAUDE.md "no UI framework") |
| Preset | not applicable |
| Component library | none (shared shell controls in `tools/editor-shell/controls.ts`) |
| Icon library | none. Unicode glyphs in `textContent` (▲ ▼ ≈ ▬ ◐ ═ ◭ ✕ ▦ ▒ ⚿ ↖ ╱ ✥ ▭ ⌫) [existing] |
| Font | `13px system-ui, sans-serif` [existing] |

Registry safety gate: not applicable (no shadcn, no third-party registries).

Existing tokens to reuse (no new colours): `--bg #14161a`, `--panel #1d2026`, `--panel-2 #262a32`, `--text #d8dde6`, `--accent #4aa3ff`, `--error #ff6b6b`, `--ok #66cc99`, `--warn #ffb347`. Hairlines/borders are `#000`.

**Focal point:** the primary visual anchor is the accent-highlighted active tool button, paired with the sidebar's tool-name heading directly beside it in the left column. Everything else (panels, dividers, inactive buttons) stays neutral so the eye lands on "which tool am I using and what are its options".

## Layout Contract

Current state (for the executor): terrain editor uses `layout: "dock"` (top row holds Raise/Lower + inline flyout; bottom-left toolbar holds the rest; floating flyout above the active bottom button; history top-right; view pad right; infobox bottom-right 300px). Map editor uses `"classic"` (vertical `.shell-rail` at left:8/top:40, `.shell-flyout` at left:64, history top-right, infobar bottom).

Target regions (both editors, from the shell):

| Region | Position | Contract |
|--------|----------|----------|
| Menubar | top, 28px | unchanged |
| Left sidebar `.shell-sidebar` | fixed, left edge, top 28px to bottom (above the classic infobar's 24px in classic), `width: max-content`, min 200px, max 280px [default] | Always visible. Not overlaid: the canvas is positioned to its right (`left: <sidebar width>`, `width: calc(100% - sidebar width)`). Background `--panel`, 1px `#000` right border, no border-radius, no floating shadow. |
| Sidebar header | top of sidebar | Raise/Lower arrow pair (terrain only, see below), then active tool name (heading style) |
| Sidebar body | below header | Active tool's options and readouts, `overflow-y: auto`; replaces `shell.flyout` (`.shell-flyout.floating`, `flyoutAnchor`, `placeFlyout` removed/obsolete) |
| Sidebar empty (no tool active) | header + body | Header heading "No tool selected"; body muted line "Pick a tool to see its options." |
| Bottom toolbar (terrain) | bottom-left of the canvas area, `left = sidebar width + 8px`, `bottom: 8px` | Grouped tool buttons with dividers (below). `max-width: calc(100% - sidebar - 380px)`; wraps by group, never mid-group where avoidable. |
| Tool rail (map editor, classic) | vertical, at the left of the canvas area (`left = sidebar width + 8px`, top 40px) [default: keeps D-03 "no layout switch"; sidebar is the leftmost column] | Same grouped buttons with horizontal dividers |
| History pad | top-right, Undo / Redo / Clear all | unchanged [D-05] |
| View pad, infobox/infobar | right / bottom | unchanged; viewpad `top: 80px` in dock kept |

The terrain top row (`.shell-topbar`) is removed; Raise/Lower move into the sidebar header [D-04, D-06]. Map editor has no Raise/Lower.

Canvas rule: any pointer-to-world maths must use the canvas element's own `getBoundingClientRect()` (not `window` or `#app` origin) since the canvas no longer starts at x=0. Resize and overlay code must be checked [D-06 integration note].

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gaps between tool buttons, panel padding, icon-to-label gap |
| sm | 8px | Sidebar field gap, sidebar horizontal padding, group-divider margin each side |
| md | 16px | Sidebar section separation, dialog padding |
| lg | 24px | Not used in this phase |
| xl | 32px | Value-box height and minimum height of value controls (steppers, selects) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions (all inherited from existing CSS and left as-is unless noted):
- Raise/Lower arrow buttons: 40px wide x 28px tall each; stacked with a 4px gap, the pair totals exactly 60px tall (28 + 4 + 28) x 40px wide [default].
- Tool button: `height: 40px`, `min-width: 56px`, horizontal padding 8px, sized to the full word (not fixed 40x40) [D-01].
- Value box: height 32px (xl). Inside-box arrow buttons are 16px wide x 16px tall, stacked (2 x 16 = 32px), so they fill the box height exactly [D-09].
- 1px borders and 2px inner gaps (existing `.stepper` gap 2px) retained.
- Group divider: 1px line, 24px tall in horizontal toolbars (full width, 1px tall in the vertical map rail) [D-02].

## Typography

Exactly 4 sizes, 2 weights, as already used by the shell.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (field labels, option text, value text, tool-button word) | 13px | 400 | 1.4 |
| Label / hint (shortcut key hint on buttons, tooltip text, unit suffix) | 11px (was 9px key hint; raised for legibility) | 400 | 1.3 |
| Heading (sidebar active-tool name, section summaries) | 13px | 600 | 1.2 |
| Glyph (rail icon, Raise/Lower arrows) | 16px | 400 | 1 |

Notes: the sidebar tool name is Heading (13px/600) rather than a larger size, to stay inside the 4-size budget. Only weights 400 and 600 are used (the `.status.error` and `details.section > summary` 600s already match). Tooltip is 11px (smaller than today's 13px) [D-08].

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg #14161a` | Canvas surround, value-box and select/input fill |
| Secondary (30%) | `--panel #1d2026` / `--panel-2 #262a32` | Sidebar, toolbars, history/view pads (`--panel`); button faces (`--panel-2`) |
| Accent (10%) | `--accent #4aa3ff` | See reserved list |
| Destructive | `#6b2b2b` fill (existing `.btn.danger`), `--error #ff6b6b` text | Clear all only (unchanged) |

Accent reserved for:
1. The active tool button (`aria-pressed="true"`, black text on accent) including the active Raise or Lower arrow.
2. Keyboard focus ring (2px outline, offset 1px) on tool buttons, value boxes and their arrows.
3. The value box border while dragging/scrubbing or focused.
4. Shortcut `kbd` text in the shortcuts dialog (existing).

Not accent: dividers (`#000` on `--panel`), sidebar border, tooltip, hover (hover = `--panel-2` lightened by 8% via `filter: brightness(1.15)` [default]), group labels.

Tooltip colours [D-08, default]: translucent pill `background: rgba(0,0,0,0.72)`, `border: 0`, `border-radius: 999px` for single-line, `8px` when wrapped; text `--text`; padding 4px 8px; `max-width: 240px` (was 280px). Subtle: no border, no shadow.

## Component Contracts

### 1. Tool buttons [D-01, D-02, D-03]
- Content: glyph (16px) above full-word label (13px/400), shortcut key hint (11px, opacity 0.7) in the top-right corner of the button (absolutely positioned) so it never wraps the word. Word is the `label` field already on `ShellTool`.
- Labels, shortened where needed to fit 56-88px: use `label` verbatim unless over 12 characters, then these display labels: "Surface paint" -> "Paint", "Road brush" -> "Road", "Erase road" -> "Erase", "Smooth area" -> "Smooth box", "Lock/unlock road" -> "Lock", "Draw road" -> "Draw road", "Move node" -> "Move node". Add an optional `shortLabel?` or `group` field to `ShellTool`; `aria-label` stays the long label.
- States: default (`--panel-2`), hover (brightness 1.15), active (accent), focus-visible (accent ring), disabled (opacity 0.4, existing).
- Groups: add `group: string` to `ShellTool`; consecutive same-group tools sit together, a divider element (`role="separator"`, `aria-orientation` matching the bar) between groups. No visible group captions (keeps the bar compact).

Terrain bottom toolbar, left to right [D-02]:

| Group | Tools (in order) |
|-------|------------------|
| Sculpt | Smooth, Flatten (Raise/Lower are in the sidebar; Sculpt group in the toolbar starts at Smooth) |
| Select | Grid select, Block, Smooth box |
| Surface | Paint |
| Roads | Road, Erase, Lock, Stamp |

Note: CONTEXT D-02 lists Sculpt as Raise, Lower, Smooth, Flatten and Roads as Road, Lock, Stamp. Erase road is not listed there; this spec places it in Roads (by-job) after Road. Raise and Lower still belong to Sculpt conceptually and keep their `H`/`J` keys.

Map editor groups (by job) [D-02, default]:

| Group | Tools |
|-------|-------|
| Select | Select (V), Move node (M) |
| Draw | Draw road (R), Building (B) |
| Remove | Eraser (E) |

### 2. Raise / Lower pair [D-04]
- Two stacked buttons at the top of the sidebar header, ▲ over ▼, glyph only (16px), no word, no visible key hint. Each 40x28px with a 4px gap: total pair height 60px. `aria-label` "Raise" / "Lower". Both keep `data-tip` with name + key (H / J) + one sentence; long how-to via the long-hover tier.
- Active tool state and options behaviour are identical to today (`setActiveTool("raise"|"lower")`; options render in sidebar body below the header).
- Hidden entirely in the map editor.
- Same states as any tool button (active = accent).

### 3. Left sidebar [D-06, D-07]
- Shared component: `shell.sidebar` (container) with `shell.flyout` kept as an alias pointing at the sidebar body so editors' option builders need minimal change.
- Structure top to bottom: arrow pair (terrain) -> tool name (13px/600) -> 1px divider -> options body.
- Option rows: `.field` stacked, label above control (existing `.field-label`, opacity 0.7), 8px between fields. Selects/steppers are content-sized, left aligned. Sections (`details.section`) keep existing look.
- Buttons inside (e.g. "Lock all", "Re-grade selected", "Smooth whole map") render full-width (`width: 100%`) so the sidebar width is set by the widest control, not by button text, and wrap-free.
- Width: `max-content` clamped 200-280px; the 200px minimum avoids canvas jitter when switching tools.
- Readouts (e.g. selection size, change amount): label/value pair rows, value right-aligned, 13px/400.

### 4. Value box (replaces −/+ stepper) [D-09, D-10]
- One shared control: `createStepper` keeps its signature (`value, spec, tip, unit, onChange`) and returns the same `{el, get, set}`; only DOM/CSS changes, so all callers (sidebar fields and New-popup fields) update at once.
- Anatomy: `.value-box` = inline-flex, height 32px (xl), `--bg` fill, 1px `#000` border, radius 3px, width `ch`-sized to content (`field-sizing: content` as already used on `select`, min 4ch, max 10ch). Contains: text input (right-aligned digits), optional unit span (11px, opacity 0.6), and a vertical pair of arrow buttons ▲ / ▼ (11px glyphs), each 16px wide x 16px tall (together exactly the 32px box height), at the right edge, separated by a 1px `#000` hairline drawn within the 16px (box-sizing border-box).
- Interactions:
  - Click an arrow: one step; hold = repeat (400 ms delay, then every 80 ms, existing). Shift = coarse.
  - Drag-scrub: pointer-down on the value area (not the arrow buttons) then horizontal drag steps the value, 8px per step [default]; Shift while dragging = coarse step; cursor `ew-resize` on hover/drag. A press without movement (under 3px) focuses the input for typing. Use Pointer Events with `setPointerCapture`; during a scrub the box border is accent.
  - Mouse wheel over the box steps it (wheel up = increase) only while the pointer is over the box; `preventDefault` so the page/canvas does not zoom; Shift = coarse. [default: no focus required]
  - Keyboard: ArrowUp/ArrowDown (Shift = coarse), Enter commits, blur commits (existing); `[` `]` stepping preserved. Invalid text reverts on blur (existing).
  - Min/max/decimals/step/coarse come from `StepperSpec`; clamping unchanged. Scrub maths lives in a pure, unit-tested helper in `stepper.ts` (pixels -> integer steps, remainder carried).
- Every part carries `data-tip` (box: `${tip} (drag, scroll or use arrows; Shift = coarse)`; arrows: `${tip} (increase|decrease)`).
- Disabled state: opacity 0.4, no scrub/wheel.
- The 18px −/+ `.step-btn` and 32px min sizes are removed.

### 5. Tooltips [D-08]
- Two tiers via `data-tip` (short) and optional `data-tip-long`: short tier = name + one short sentence + key, shown after **700 ms** (`DELAY_MS`, was 400); long how-to text is appended/swapped in only after a further 1500 ms of continued hover [default]. Existing long strings (e.g. Raise's tip) move to `data-tip-long`; `data-tip` becomes <= ~60 characters.
- Auto-fade: opacity transition 150 ms in, and after **3000 ms** visible the tooltip fades out over 250 ms even while the pointer stays; it does not reappear until the pointer leaves and re-enters the control.
- Style: see Color (translucent pill, 11px). `pointer-events: none` (existing). Hide on pointerdown, keydown, scroll (existing). Tooltips on/off toggle and per-browser memory (Help menu, `prefs`) unchanged [07.1 D-04]. `auditTips` unchanged.

### 6. History pad, view pad, menubar
Unchanged in position and behaviour [D-05]. Only token alignment: adopt the new tooltip, hover and focus rules.

## Interaction and State Contract

| Situation | Behaviour |
|-----------|-----------|
| No tool active (start) | Sidebar shown; heading "No tool selected"; body shows the muted prompt (see Copywriting) |
| Tool selected | Button active (accent); sidebar title = tool label; options rendered in body; cursor focus stays on canvas (no auto-focus of value boxes) |
| Switching tools | Sidebar body re-rendered; sidebar width stable (min-width 200px) so canvas does not shift |
| Value scrub / wheel | Updates live via `onChange`; undo behaviour exactly as today (steppers do not push history themselves) |
| Text entry in value box | Letter hotkeys suspended while focused (existing `isTextEntryFocused`); blur returns hotkeys |
| Window narrower than ~900px | Bottom toolbar wraps to two rows; sidebar stays fixed; canvas shrinks (no horizontal scroll) |
| Dialog open | Sidebar and toolbars stay visible behind the backdrop; value boxes inside dialogs (New popup) use the same control |

Accessibility: tool buttons keep `aria-pressed` and `aria-label`; dividers `role="separator"`; value box input has `aria-label` from the field label; arrows have `aria-label` "Increase"/"Decrease"; focus ring visible on all controls; contrast of `--text` on `--panel` and black on `--accent` unchanged (both above 4.5:1).

## Copywriting Contract

This is an internal tool; copy is labels and tooltips, no marketing copy.

| Element | Copy |
|---------|------|
| Primary CTA | None new. Existing: "Create" (New-area popup), "Open" (Open popup), "Save" (File menu); unchanged |
| Empty state heading | Sidebar: "No tool selected" |
| Empty state body | "Pick a tool to see its options." |
| Error state | No new errors. Existing dialog/status errors unchanged. Out-of-range typed values revert silently to the last valid value (existing); the value-box tooltip names the range, e.g. "Brush size (1 to 64 m)" [default] |
| Destructive confirmation | Clear all: unchanged from today ("Delete every road and building in this area (asks first; Undo brings them back)"). No new destructive actions |

Tooltip copy rules: short tier = "Name: one sentence (Key)", sentence case, <= 60 characters, no trailing full stop; examples: "Raise: lift terrain under the brush (H)", "Lower: dig terrain under the brush (J)", "Smooth: ease bumps under the brush (G)", "Eraser: delete roads and buildings you drag over (E)". Long tier = existing long how-to text.

Tool labels (visible): Raise/Lower are glyph-only; all others are the display label from Component Contract 1.
