<objective>
Build the render layer: a WebGL renderer, the interpolation utility that turns the fixed tick into smooth motion at any refresh rate, and the Three.js half of the debug scene.

Purpose: ROADMAP SC2 requires a physics object to render smoothly at any refresh rate with no judder. RESEARCH.md "Pitfall 4" verified Rapier exposes no interpolated transform - `translation()` and `rotation()` return post-step state only, and `nextTranslation()`/`nextRotation()` are kinematic targets, not predictions. At 144 fps roughly 60 percent of frames run zero physics steps; without interpolation those frames render an identical image, producing a distinctive 60 Hz stutter inside a 144 Hz presentation. That is exactly what SC2 is looking for.

Output: `src/render/renderer.ts`, `src/render/interpolator.ts`, `src/render/debug-scene.ts`, `tests/interpolation.test.ts`.
</objective>

<layering_rules>
src/render/** may import `three` and may READ from `src/physics/` and `src/core/`.
It must NEVER write simulation state - no `world.step()`, no `body.setTranslation`,
no `applyImpulse`, no mutation of a `TransformCache` buffer. The dependency is
one-way: render reads sim.

`renderer.render()` is called exactly once per animation frame and NEVER inside the
fixed-tick loop (plan 01-07 owns that call site). `renderer.info` is read only AFTER
`render()` returns, because `info.autoReset` defaults to true and resets at the START
of `render()`.
</layering_rules>

<placement_decision>

a `TransformCache.apply(meshes, alpha)` method or a free function - and asked the

with `TransformCache` exposing raw buffers. This keeps `src/physics/` free of any
`three` import, consistent with the `src/core/` purity rule. Plan 01-04 already

  <behavior>
    - Endpoint equivalence at 0: with alpha 0 the target position and quaternion equal the `prev` values at that index, component-wise within 1e-12
    - Endpoint equivalence at 1: with alpha 1 they equal the `cur` values within 1e-12
    - Midpoint: with alpha 0.5 and a pure translation, the position is the exact arithmetic midpoint
    - Rotation takes the short arc: interpolating between quaternions 175 degrees apart at alpha 0.5 yields a rotation whose angle from `prev` is about 87.5 degrees, not about 92.5 degrees
    - No allocation per call: calling `applyInterpolated` 10000 times does not create new `THREE.Vector3` or `THREE.Quaternion` instances beyond the module-level scratch objects
    - `applyAllInterpolated` maps index i of the target array onto offset `i * XFORM_STRIDE` in both buffers, verified by giving three targets three distinct transforms and checking none are swapped
    - Out-of-range alpha is clamped or documented: passing 1.5 does not produce a position beyond `cur`
    - Zero-step frame behaviour: with `prev` and `cur` held constant and alpha sweeping 0 to 1, the target position changes monotonically - this is the property that removes judder on frames that ran no physics steps
  </behavior>
  <action>
    Create `src/render/interpolator.ts`.

    `applyInterpolated(target, prev, cur, index, alpha)`: compute `o = index * XFORM_STRIDE` importing `XFORM_STRIDE` from `../physics/transform-cache`. Set `target.position` from `prev[o]`, `prev[o+1]`, `prev[o+2]` then `lerp` toward a module-level scratch `THREE.Vector3` set from the `cur` components. Set `target.quaternion` from `prev[o+3..o+6]` then `slerp` toward a module-level scratch `THREE.Quaternion` set from the `cur` components.

    Use `.set(...)` rather than `.copy(...)` on both. RESEARCH.md is explicit: Rapier's `Vector` and `Rotation` are structurally compatible with the Three types, but relying on structural typing couples the code to `@types/three` internals.

    Use `THREE.Quaternion.prototype.slerp` - never a hand-rolled slerp. RESEARCH.md "Don't Hand-Roll" notes sign-flip and shortest-arc handling is where hand-rolled slerps break, and the symptom is a body visibly spinning the long way round once per revolution.

    Declare the scratch `Vector3` and `Quaternion` at module scope and reuse them, so there is no per-frame allocation.

    Clamp `alpha` into [0, 1] at the top of the function and document why in a comment - `SimClock.alpha` already clamps, but the interpolator must be safe standalone.

    `applyAllInterpolated(targets, cache, alpha)` iterates `targets` and delegates to `applyInterpolated` with the array index. It takes a structural `{ prev, cur }` rather than the `TransformCache` class, so tests can drive it with plain buffers and `src/render/` never needs a `src/physics/` class import beyond the stride constant.

    Write `tests/interpolation.test.ts` covering every behavior-block item. It runs under the `node` environment with no WebGL context - `THREE.Object3D`, `Vector3` and `Quaternion` are pure math classes and instantiate fine in Node. Do NOT construct a `WebGLRenderer` in this test.
