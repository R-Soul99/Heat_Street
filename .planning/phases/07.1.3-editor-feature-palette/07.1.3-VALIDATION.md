# Phase 07.1.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Source: `07.1.3-RESEARCH.md` section "Validation Architecture".

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 5.0.0, `environment: "node"` (no DOM, no jsdom) |
| **Config file** | `vitest.config.ts` (`tools/**` tests are picked up by the default include) |
| **Quick run command** | `npx vitest run tools/terrain-editor tools/editor-shell` plus the task's own test file |
| **Full suite command** | `npm run check` (`tsc --noEmit` + `biome check .` + `vitest run`) |
| **Estimated runtime** | ~2 seconds quick, ~60 seconds full |

Node-only testing means DOM and pointer code in `editor.ts` cannot be unit-tested. It must stay a thin router over pure, tested modules. Three geometry and `InstancedMesh` objects can be built headlessly, and Rapier runs in node.

---

## Sampling Rate

- **After every task commit:** Run the task's own test file plus `npx vitest run tools/terrain-editor tools/editor-shell`
- **After every plan wave:** Run `npm run check`
- **Before `/gsd-verify-work`:** Full suite must be green, then the two short human checks in the briefs
- **Max feedback latency:** 60 seconds
