# Phase 07.1.3 — UI Design Contract

> Visual and interaction contract for the terrain editor's Place tool group: the Place drop-down, the sidebar palette, start-point markers and list, feature ghosts, selection of placed features, and the Drive buttons. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source tags: [D-nn] = locked in 07.1.3-CONTEXT.md; [brief1]/[brief2] = `.planning/plans-ahead/01-start-points.md` / `02-scenery-palette.md`; [07.1.2] = carried unchanged from the approved 07.1.2 UI-SPEC and the shipped shell; [Assumed] = gap filled by the researcher non-interactively, listed again under "Assumptions" for the user to review.
> This spec states only what is NEW. Everything not mentioned keeps its 07.1.1 / 07.1.2 contract: sidebar 240px, 24px tool-name title, subtitle, divider, options body, value box, tooltip tiers, top-bar menu mechanism (`BarGroup` `menu` item), history pad, view pad, infobox, canvas offset, floating chips.
> Scope: terrain editor only. The map editor (`tools/map-editor`) is not touched.

## Layout Contract

### Where Place sits [D-15]

The top bar gains one **Place ▾** `menu` item, inserted in the "menus" group after Road (order: Terrain, Road, Place). Same trigger anatomy as Road: glyph over word, no hotkey of its own [07.1.2].

```
Top bar: ... [ Terrain ▾ ][ Road ▾ ][ Place ▾ ] | Grid Contours | Undo Redo
                                      +-----------------+
                                      | ⚑ Start point 1 |
                                      | ----------------|
                                      | ▣ Building    2 |
                                      | ♣ Tree        3 |
                                      | ✿ Bush        4 |
                                      | ▤ Hedge       5 |
                                      | ╫ Fence       6 |
                                      | ◢ Ramp        7 |
                                      +-----------------+
```

- Menu entries are standard tool buttons (width equals the widest label, glyph, label, key hint at right). A divider separates Start point from the scenery kinds (start points are not scenery) [Assumed].
- Picking an entry closes the menu and arms that kind. The Place trigger then takes the accent state (`aria-pressed="true"`), and Select and Brush both lose accent: Place is a third, exclusive mode alongside Select and Brush [Assumed]. Switching to Select (S) or Brush (B) disarms Place but keeps the last kind remembered for the session.
- The menu is built from data in `tools/terrain-editor/rail-tools.ts` (`PLACE_TOOLS`, `PLACE_MENU`) with `TERRAIN_BAR` gaining the entry, so the existing bar tests and hotkey audit apply [D-15].
- Adding a future kind (e.g. "Route", see Deferred in CONTEXT) is one data entry plus one palette definition; no layout change. The menu is a vertical list, never a fixed-width row.

### Sidebar when a Place tool is armed

Structure per 07.1.2: title (24px/600) -> subtitle (13px, opacity 0.7) -> 1px divider -> options body.

| Armed kind | Title | Subtitle | Options body, top to bottom |
|------------|-------|----------|-----------------------------|
| Start point | "Place" | "Start point" | Hint block; section "Start points" (list, see below) |
| Building | "Place" | "Building" | Hint block; Style swatches; Width, Depth, Height, Rotation boxes; (no scatter) |
| Tree | "Place" | "Tree" | Hint block; Variant swatches; Scale; Random rotation; Scatter section |
| Bush | "Place" | "Bush" | same as Tree |
| Hedge | "Place" | "Hedge" | Hint block; Variant swatches; Height; running-length readout |
| Fence | "Place" | "Fence" | same as Hedge |
| Ramp | "Place" | "Ramp" | Hint block; Height, Angle, Width boxes; direction readout |

- The **Start points** list also appears, collapsed by default, in Select mode when the map has at least one start point, so markers can be managed without arming Place [Assumed]. In Place > Start point it is open.
- Option rows follow 07.1.1: label above control, 8px between rows, full-width controls. Hint block is muted 11px text. Option values are remembered per kind for the session and with the other editor options [07.1.2 D-31].

### Variant swatches [D-15, brief2 stage 6]

- **Column rule (every row full, no ragged last row; applies to any kind, present or future):** for a kind with N variants use 3 columns if N divides by 3, else 2 columns if N divides by 2, else a 1-column list (this covers N = 1 and any prime N such as 5 or 7). 6 variants go 3 x 2, never 4 + 2. Per kind today: Tree (3) = 3 columns; Fence (3) = 3 columns; Bush (2) = 2 columns; Hedge (1) = 1 full-width swatch; Building (5) = 1-column list of 5 full-width rows. Variant counts come from the briefs and are not changed. Swatch width fills the 224px content width with 4px gaps: 72px (3 columns), 110px (2 columns), 224px (1 column). Height is 56px for the grid layouts; the Building list rows are 224px x 40px (tile 40x40 on the left, name to its right at 11px, `--panel-2` fill) so five rows stay compact [Assumed].
- Swatch face: top 40px is a flat preview tile filled with the catalog's primary colour (hex from `scenery-catalog.ts`) with the kind glyph centred in `--text`/dark contrast; bottom 16px strip holds the variant name, 11px, centred, `--panel-2` fill. No rendered thumbnails this phase [Assumed].
- States: rest 1px `#000` border; hover `filter: brightness(1.15)`; selected 2px accent outline offset 1px; focus ring 2px accent offset 1px. `role="radiogroup"` with `role="radio"` children, `aria-checked`, `aria-label` = "{Kind} {variant}", `data-tip` = variant name.
- Variant names are the catalog ids in sentence case: Pine, Oak, Dead; Round, Scrub; Box; Post and rail, Picket, Chain-link; Shed, House, Barn, Shop, Block.

### Start points list (sidebar section) [D-03, brief1 stage 4]

One row per start point, 32px tall, 4px gap between rows, inside `details.section` "Start points":

```
[ ★ ][ Start 1                ][ ⌖ ][ ✕ ]
[ ☆ ][ Start 2                ][ ⌖ ][ ✕ ]
```

- Make default button (★ filled = this is the default, accent glyph, disabled; ☆ outline = click to make default, 32x32). `data-tip` "Make default: use this start in the game". 
- Name field: inline text input, 40 characters max, replaces the whole row width; Enter or blur commits as one undo step, Esc reverts. The selected start point's row has a 2px accent left border [Assumed]. Default row additionally shows "default" as 11px muted text under the name is NOT used (the star carries it; avoids a taller row).
- Go to (⌖): centres the camera target on the point, no undo step. Delete (✕): removes, one undo step, no confirm (undoable).
- Row click selects the start point (selection highlights the marker and the row). Maximum 32 rows; the list scrolls inside the sidebar, never the section itself.
- Below the list, full-width button **Drive from: {name}** [D-06] (see Drive buttons).

### Canvas elements

**Start-point marker** [brief1 stage 4, Claude's discretion on look]: per start point a group of: thin pole 3m tall (radius 0.08m), small rectangular flag 1.2m x 0.7m at the pole top, and a flat arrow on the ground 3m long, 1.2m wide, lying on terrain along `headingRad`, drawn on top of the terrain with depth test off for the arrow so slopes never bury it. Colours: default start `--ok #66cc99` (green = go), other starts `--warn #ffb347`; selected marker gets an accent `#4aa3ff` ring (1.6m radius) on the ground. A text label (the name) is shown as a DOM tag above the flag at 11px, `--panel` fill, 4px padding, only for the selected and the default marker, to avoid clutter [Assumed]. Marker is `pointer-events` via raycast pick radius 2m.

**Ghost preview** (every point kind): a translucent copy of the real mesh (`opacity 0.5`) following the cursor, seated on terrain. Refused spot (on road paint, outside the area, or at a limit): ghost tinted `--error #ff6b6b`, cursor `not-allowed`, reason in the info bar. 

**Line preview** (hedge, fence): placed points as 6px accent dots joined by an accent 2px polyline; a ghost segment from the last point to the cursor; ghost segments crossing road paint tinted red. Running length readout "{n} m, {k} points" in the sidebar and the info bar.

**Building footprint preview**: accent-outlined rectangle on the terrain (2px accent, fill `rgba(74,163,255,0.25)`, same as the Select overlay) while dragging, ghost box at the chosen height. Rotation readout "{deg}°" beside the cursor via the info bar.

**Ramp preview**: ghost ramp (same builder as the game) plus a direction arrow from press point to cursor.

**Scatter preview**: brush circle (reuse the brush ring) in accent at 50% alpha, with ghost instances at 0.5 opacity for the seeded result.

**Selected feature highlight** (Select mode and after placing): accent 2px wire box around the feature's bounds (points: bounding box of the mesh; hedges/fences: along the polyline; buildings: the footprint box). Hover in Select mode: same box at 50% alpha.

### Floating toolbar changes

- The brush-size chip (Radius value box + Square/Circle toggle) is enabled while Scatter is on for Tree or Bush (Radius only; Square/Circle disabled, scatter is circular) and disabled (opacity 0.4) in every other Place state [Assumed].
- No other chips change.

## Component Contracts

### 1. Place menu [D-15]
Seven entries, order and glyphs as in Layout. Keys 1 to 7 (`Digit1` to `Digit7`) arm the entries directly; they are suspended while a text field or dialog has focus (existing `isTextEntryFocused`). Reasoning: all mnemonic letters are taken (S B H J G F P R E L U X C T D Z Y); digits are free and the hotkey audit keys on `e.code` [Assumed]. Entries added to the shortcuts dialog and the audit list in `rail-tools.test.ts`.

### 2. Start point tool [D-05, brief1 D6]
- Press on terrain records the position; dragging draws a preview arrow (accent) from press to cursor and sets the facing; release commits one undo step [D-16]. Drag under 1 m: face along the nearest road, else heading 0.
- Press on an existing marker selects it; dragging a selected marker moves it (one step); dragging with Shift held turns it in place (one step) [Assumed]; Delete removes it (one step).
- Limit 32: placing the 33rd is refused, info bar "A map can have at most 32 start points".
- Position outside the area extent is refused, "Start points must be inside the map area".
- New points are named "Start {n}" using the never-reused id counter; the first one placed becomes the default automatically (first array entry) [D-03].

### 3. Point scenery (Tree, Bush) [brief2 stage 6]
- Click places one instance at the cursor with the sidebar Scale and (when Random rotation is on, default) a random rotation; one undo step. Ghost follows the cursor.
- **Scale**: value box 0.5 to 2, step 0.1, unit `x`. **Random rotation**: two-state toggle button ("On"/"Off"), default On; when Off a Rotation box (0 to 359, unit `°`, step 15) appears below it.
- **Scatter** section (`details.section`, closed by default): toggle "Scatter" (off by default) plus **Density** value box 1 to 20, unit "per 100 m²". When on, press-and-drag paints instances inside the brush circle using the seeded random; the whole drag is one undo step. Brush Radius from the floating chip.

### 4. Line scenery (Hedge, Fence)
- Click adds points; double-click or Enter finishes; Esc cancels the line in progress; Backspace removes the last point. Finishing with fewer than 2 points does nothing (info bar "A line needs at least 2 points"). The limit is 64 points per line; the 65th click is refused with "A line can have at most 64 points". One finished line is one undo step.
- **Height** value box, hedge default 1.5 m, fence default 1.2 m, range 0.3 to 6, step 0.1, unit `m`.
- Readout "{length} m, {k} points" updates while drawing.

### 5. Building [brief2 stage 6 step 3]
- Press, drag to the opposite corner, release: commits the footprint. Mouse wheel while dragging rotates 15° per notch. One undo step.
- Boxes smaller than 1 m on either side are refused ("Building too small, drag a larger footprint"); default footprint when the user only clicks: the catalog style's default size.
- Sidebar: **Width**, **Depth** (metres, defaults from the catalog style, shown and editable before drag-less click placement), **Height** (metres), **Rotation** (° step 15). Dragging overrides Width/Depth for that placement and writes them back to the boxes.
- Seat: box sits on the lowest terrain height under the footprint and extends down by the height difference (brief 2) so no corner floats.
- All sidecar buildings, including style-less ones from converted maps, are drawn in the editor as plain blocks so they can be seen, selected and deleted [D-21]; their sidebar subtitle reads "Building (no style)".

### 6. Ramp [D-14, brief2 stage 7]
- Sidebar **Height** (0.5 to `MAX_CREST_HEIGHT_M`, unit `m`), **Angle** (within `parseRamp` range, unit `°`), **Width** (within `parseRamp` range, unit `m`). Defaults are the `RampSpec` defaults. Press sets position, drag sets direction, release commits one step. Ramp shape numbers are not changed [D-14].
- Ramps are crest objects; they are drawn with the game's crest builder.

### 7. Selecting, moving, deleting placed features [brief2 stage 6 step 4, D-16]
- Select mode: click a feature selects it (wire box). Drag moves it (hedge/fence move whole line; one step). Delete removes it (one step, no confirm). Click on empty ground deselects the feature; plain drag on empty ground still starts the box selection of 07.1.2.
- Box selection + Delete (and the History pad's existing delete paths) removes every feature whose position lies inside the box. Above 20 items a dialog asks first: heading "Delete {n} features?", body "They are removed from this map. Undo brings them back.", buttons "Delete {n} features" (danger fill `#6b2b2b`) and "Keep features" (neutral). Delete and Keep features are the only controls; Esc keeps them; focus starts on Keep features [Assumed].
- Features stay selectable only when no Place tool is armed (avoids fighting the Place gestures).

### 8. Placement refusal on road paint [D-12]
Refusal feedback is the red ghost, the `not-allowed` cursor and the info-bar message. No dialog, no sound. For lines: any sampled point on road paint refuses the whole segment at that click; the user can click elsewhere.

### 9. Drive buttons [D-06, brief1 stage 5]
- **Drive from: {name}** replaces the single Drive item as the primary action: a full-width button at the bottom of the Start points section and the existing top-bar Drive entry, labelled with the selected start point's name, or the default's when none is selected. Hotkey `D` stays and triggers this action [existing global code].
- **Drive here** stays as a secondary menu entry. From the menu it uses the camera target and the info bar says "Driving from the centre of the view"; via a right-click or hotkey press it uses the terrain point under the cursor at that moment, never a stale last-hit position [D-06]. Facing is the camera's ground-projected look direction.
- With no start points, **Drive from** is replaced by a disabled-looking (`aria-disabled`, still hoverable) button reading "Drive from: (none)" and the info bar says "Place a start point first, or use Drive here."
- Both still save first and check drivability, as today.

## Interaction and State Contract

| Situation | Behaviour |
|-----------|-----------|
| Pick a Place entry | Menu closes, Place trigger accent, sidebar swaps to that kind's palette, cursor `crosshair`, ghost appears over terrain |
| Switch to Select (S) or Brush (B) | Place disarms, kind remembered; ghosts and line previews disappear; line in progress is cancelled |
| Esc | Cancels a line in progress or a drag in progress first; else disarms Place and returns to Select; else clears selection [07.1.2] |
| Pointer leaves the canvas | Ghost hidden; no placement possible |
| Undo/Redo | Each placement, scatter drag, move, delete, rename, make-default is exactly one step through the dispatcher undo [D-16]; selected feature highlight clears if the feature disappears |
| Sculpting under a placed item | Items re-seat to the new terrain height; start markers, features and building seats update after the operation [brief1 stage 4, brief2 stage 6 step 6] |
| Alt held | Browser menu activation prevented as in 07.1.2; Alt does nothing in Place |
| Typing in the name field or a value box | Letter and digit hotkeys suspended |
| Limit reached (4,000 point features, 500 lines, 2,000 buildings, 32 starts) | Placement refused with an info-bar message "Limit reached: {n} {kind}s per map. Delete some to place more" |
| Map area has no roads | Road-paint refusal never triggers; placement unrestricted inside the area |
| Narrow window (< ~900px) | Sidebar fixed; swatch column count follows the per-kind rule (3, 2 or 1 columns), never reflows to a ragged row; list scrolls |

Hotkeys added (all `e.code`, must pass the hotkey audit test; none collide with S B H J G F P R E L U X C T D Z Y, Delete, Escape):

| Key | Action | Key | Action |
|-----|--------|-----|--------|
| 1 | Place: Start point | 5 | Place: Hedge |
| 2 | Place: Building | 6 | Place: Fence |
| 3 | Place: Tree | 7 | Place: Ramp |
| 4 | Place: Bush | Enter / Backspace | Finish / undo last point of a line (Place Hedge, Fence only) |

Accessibility: Place trigger and menu entries have `aria-label` (long name) and `aria-pressed`; swatches are `role="radiogroup"`/`radio`; start-point list is `role="list"` with each name input labelled "Name of start point {n}"; all DOM text via `textContent`; every control has `data-tip`; focus rings visible; disabled controls use `aria-disabled="true"` so tooltips still explain why. Marker name tags are visual only; the list carries the same information.

## Assumptions (non-interactive session; review these)

1. Place is a third exclusive mode (accent moves from Select/Brush to the Place trigger); Select and Brush hotkeys disarm it.
2. Palette kinds use digit hotkeys 1 to 7 because every mnemonic letter is taken; no hotkey for the Place trigger itself (same as Road).
3. A divider separates Start point from scenery kinds in the Place menu.
4. Swatches are flat colour tiles with glyph and name strip, not rendered thumbnails. Column count per kind: 3 columns if the variant count divides by 3 (Tree, Fence), else 2 columns if it divides by 2 (Bush), else 1 column (Hedge as one full-width swatch; Building as a 1-column list of 5 rows, 224x40 each, with no sixth style added). A future kind with N variants follows the same rule, so rows are always full.
5. Start-point list rows: star, inline name, Go to, Delete; name tags on the canvas only for the selected and default marker; default marker green, others amber, selected ring accent.
6. The Start points section also shows (collapsed) in Select mode when starts exist.
7. Shift-drag on a selected start marker turns it in place; plain drag moves it.
8. Brush-size chip enables only for Scatter (radius only).
9. Bulk delete confirmation above 20 items uses the dialog copy above (dismiss button "Keep features"), focus on Keep features; features are only selectable when no Place tool is armed.
10. Marker and ghost visuals: 3m pole, flag 1.2 x 0.7m, ground arrow 3m long; ghosts at 0.5 opacity, refused ghosts tinted red.
11. Glyph choices (✚ ⚑ ▣ ♣ ✿ ▤ ╫ ◢ ★ ☆ ⌖) are placeholders; the planner may swap any glyph that renders poorly in `system-ui` without changing the label.
12. Info-bar message wording above is the proposed set; exact limits (32 / 64 / 4,000 / 500 / 2,000) come from the briefs.
