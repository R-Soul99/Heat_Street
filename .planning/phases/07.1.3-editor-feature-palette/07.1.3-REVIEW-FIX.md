## Fixed Issues

### CR-01: Legacy GLB buildings can be moved, rotated or bulk-deleted

**Files modified:** `tools/terrain-editor/features.ts`, `tools/terrain-editor/scenery-guards.ts`, `tools/terrain-editor/editor.ts`, `tools/terrain-editor/features.test.ts`, `tools/terrain-editor/scenery-guards.test.ts`
**Commit:** 0431503
**Status:** fixed: requires human verification (browser)
**Applied fix:** New `isEditableBuilding(b, legacyGlbBuildings)`: false for a style-less building
on a `legacyGlbBuildings` map. `pickFeatureAt`, `pickFeatureByRay`, `removeInMask` and
`deleteBuilding` take the flag and skip those boxes; `moveSceneryItem` and `rotateSceneryItem`
refuse them with "That building comes from the map model and cannot be changed here". The editor
passes `area.legacyGlbBuildings` at every call site and `sceneryExists` treats such a box as not
selectable. Styled, palette-placed buildings on those maps stay fully editable. The boxes are
still drawn in the editor (unchanged).

### WR-01: Building meshes are not refreshed after most sculpt paths re-seat the buildings

**Files modified:** `tools/terrain-editor/tool-dispatch.ts`, `tools/terrain-editor/editor.ts`, `tools/terrain-editor/tool-dispatch.test.ts`
**Commit:** 20cf2f9
**Status:** fixed: requires human verification (browser)
**Applied fix:** `finish` now returns whether the pushed diff re-seated buildings. Brush, erase
and road stroke release, Flatten on a selection and Smooth all set `buildingsChanged` from it.
`stopOpHold` passes the `endOpRepeat()` result to `sceneryChanged`. Tests cover each dispatcher
path. Buildings are still redrawn at the end of a stroke or hold, not on every tick.

### WR-02: Holding Left/Right on a selected item silently changes the Raise/Lower step

**Files modified:** `src/core/terrain-undo.ts`, `tools/terrain-editor/tool-dispatch.ts`, `tools/terrain-editor/features.ts`, `tools/terrain-editor/editor.ts`, `tests/terrain-undo.test.ts`, `tools/terrain-editor/tool-dispatch.test.ts`, `tools/terrain-editor/features.test.ts`
**Commit:** 31189dc
**Status:** fixed: requires human verification (browser)
**Applied fix:**
- Left/Right turn the selected item 15 degrees, Shift+Left/Right 1 degree (`arrowRotateDeg`),
  and key repeat is allowed.
- The arrow keys are consumed whenever a placed item is selected in Select mode, including a
  hedge or fence (which shows "Hedges and fences cannot be turned."), so they never reach the
  sidebar Step value.
- Undo coalescing: `commitScenery` takes an optional merge key. A run with the same key folds
  into the newest undo entry (`UndoStack.amendTop`). A held key always merges; separate presses
  on the same item merge when they are within 700 ms of each other. Any other edit, undo or redo
  ends the run.
- Design choice to confirm: quick separate taps (under 700 ms apart) also become one undo step,
  not only a hold.

### WR-03: Ramp panel steppers push one undo entry per tick

**Files modified:** `tools/terrain-editor/editor.ts`, `tools/terrain-editor/tool-dispatch.test.ts`
**Commit:** 70d82e9
**Status:** fixed: requires human verification (browser)
**Applied fix:** `editSelectedRamp` commits through the same merging `commitScenery`, keyed by
ramp id and value (height, angle or width). A held stepper button (400 ms delay, then 80 ms
ticks) is one undo step per value. The test holds height from 2 m to 50 m (96 ticks) and checks
it is one step and that earlier history survives.

### WR-04: Building selection is an array index and silently retargets after undo or redo

**Files modified:** `tools/terrain-editor/features.ts`, `tools/terrain-editor/editor.ts`, `tools/terrain-editor/features.test.ts`
**Commit:** caa7cbd
**Status:** fixed: requires human verification (browser)
**Applied fix:** The map format has no building id, so the editor now keeps the building object
the selection was made on and re-resolves the index on every buildings change
(`resolveBuildingIndex`): same object at another index is followed, a sculpt re-seat in place
(only height changed) keeps the selection, anything else clears it. Delete and rotate re-resolve
before acting. Undo and redo are also blocked while a move drag is in progress.
Known limit: undoing a move or turn of the selected building clears the selection (the restored
object is a different one), it does not re-select it.

### WR-05: Building footprint road check samples only the centre and four corners

**Files modified:** `tools/terrain-editor/features.ts`, `tools/terrain-editor/scenery-guards.ts`, `tools/terrain-editor/editor.ts`, `tools/terrain-editor/features.test.ts`, `tools/terrain-editor/scenery-guards.test.ts`
**Commit:** 2b1a2ce
**Status:** fixed: requires human verification (browser)
**Applied fix:** One shared `canPlaceFootprint` used by place, move and rotate. It tests the
centre and corners, then the edges and interior on a grid no coarser than one paint pixel
(minimum 0.25 m). Side effects to be aware of: rotate now also checks the centre, and an
existing building that already overlaps road paint can no longer be turned in place (it can be
moved off the road). A 100 m footprint at 0.5 m paint is about 40,000 samples per check during
a drag; not measured in a browser.

### WR-06: Hedge and fence segments are level slabs, so they float on slopes

**Files modified:** `src/core/scenery-geometry.ts`, `src/render/scenery-view.ts`, `src/physics/terrain-scene.ts`, `tests/scenery-geometry.test.ts`, `docs/scenery.md`
**Commit:** 2980a45
**Status:** fixed: requires human verification (browser and a drive)
**Applied fix:** Each segment now runs from the ground at its start to the ground at its end and
is tilted along its length (`LineSegment.pitch`, `slopeLengthM`). The hedge box, fence rails and
the collider share one rotation (`lineBoxQuat`), so neither end floats or is buried and rails
meet their posts. Posts and picket slats stay upright. The collider keeps its 0.3 m sink below
the ground line.
- Pitch was chosen over splitting segments by height, because splitting would make box counts
  depend on terrain. Segment and box counts are unchanged, so triangle estimates, catalog
  numbers, the 40,000 budget tests and instancing are all untouched. `docs/scenery.md` has a
  new "Hedges and fences on slopes" section.
- Remaining limits: a segment is still one straight piece up to 8 m, so over a sharp crest or
  hollow shorter than a segment its middle can sit slightly above or below the ground. The
  editor's click-pick boxes for lines (`featurePickBoxes`) are still level boxes at the average
  height, so picking a line on a steep slope is approximate.
- The game physics change (`terrain-scene.ts` collider rotation) was tested only through the
  pure quaternion and geometry tests and the existing `tests/terrain-scene.test.ts`; no car was
  driven into a fence on a slope.

### WR-07: Ramp checks validate only the foot start point

**Files modified:** `tools/terrain-editor/features.ts`, `tools/terrain-editor/scenery-guards.ts`, `tools/terrain-editor/editor.ts`, `tools/terrain-editor/features.test.ts`, `tools/terrain-editor/scenery-guards.test.ts`
**Commit:** 38df7a9
**Status:** fixed: requires human verification (browser)
**Applied fix:** New `canPlaceRamp(area, crest)` checks the start of the foot and all four
footprint corners. It is used on release when placing, in the drag ghost once a direction
exists, in `moveSceneryItem`, and in `updateRamp` (which now takes the area) for rotation and
the Height / Angle / Width steppers. New refusal text: "That ramp would reach outside the map
area". A ramp that already reaches outside (the saved map has some over 100 m long) can still be
made shorter or narrower on the same heading, but cannot be moved or turned until it fits.
