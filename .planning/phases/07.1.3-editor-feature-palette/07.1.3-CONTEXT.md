**Gathered:** 2026-11-15

<domain>
## Phase Boundary

The terrain editor gains a **Place** tool group with a sidebar palette. Two parts, in this order:

1. **Start points** for test drives: named, with a facing direction, saved with the map. "Drive" starts the car on the chosen one. Full detail: `.planning/plans-ahead/01-start-points.md`.
2. **Scenery palette**: buildings, trees, bushes, hedges, fences and ramps, saved with the map, drawn in the game and solid where they should be. Full detail: `.planning/plans-ahead/02-scenery-palette.md`.

The briefs are the specification. Their stages map to plans roughly one to one; plan them in the briefs' order. Everything in a brief's Decisions section is locked unless marked ASK.

**Out of scope:** breakable props (GET-06), glTF scenery models, off-road stage gates (Phase 10), a garage or map-select screen.

</domain>

<decisions>
## Implementation Decisions

### Start points (brief 01)
- **D-01:** Stored in the terrain sidecar as optional `startPoints`, written only when non-empty; no format version bump.
- **D-02:** Shape `{ id, name, x, z, headingRad }`; no `y` (height always sampled from terrain).
- **D-03:** First entry is the map default; sidebar has "Make default".
- **D-04:** Game spawn priority: `?at=` (+ optional `?heading=` in degrees) > `?start=<id>` > sidecar default > road-graph spawn > grid centre. No throw when a map has no spawn.
- **D-05:** Place by click-and-drag (position, then facing).
- **D-06:** "Drive from: <name>" is the main action; "Drive here" stays as a secondary action and must stop using the stale last-cursor position.

### Scenery (brief 02)
- **D-07:** New optional sidecar array `features`; existing `objects` (crests) and `buildings` untouched apart from an optional building `style`.
- **D-08:** Catalog of kinds and variants lives in code (`src/core/scenery-catalog.ts`); files store variant ids only.
- **D-09:** Procedural low-poly meshes built in code, drawn with `InstancedMesh`; scenery adds at most 12 draw calls and 40,000 triangles.
- **D-10:** Solid: buildings, tree trunks, hedges, fences. Not solid: bushes. Hedges block pursuit line of sight; trunks and fences do not. **Default pending user confirmation (ASK in brief 02 D4).**
- **D-11:** Terrain-native buildings must be drawn in the game (today they have a collider and no mesh).
- **D-12:** Features cannot be placed on road paint.
- **D-13:** The same view module draws features in the editor and the game.
- **D-14:** Ramps are placed as existing crest objects; ramp shapes are not changed.

### Editor UI
- **D-15:** One **Place ▾** drop-down in the top bar; option values in the left sidebar; swatches in even rows. Show the user a layout sketch before building (memory: editor-ui-principles).
- **D-16:** Every placement, move and delete is one undo step through the existing dispatcher undo; no second undo stack.

### User decisions on the research's open questions (2026-11-15)
These override `07.1.3-RESEARCH.md` and the briefs where they differ.

- **D-17:** Palette buildings are drawn as one merged mesh per style, with no per-building camera fade. They stay out of `buildingMeshes`; the car x-ray outline covers visibility. Brief 02's human check "camera still fades a building" becomes "the x-ray outline shows the car behind a building".
- **D-18:** The start point set in the editor is the map's start. The sidecar default start point replaces the map default spawn wherever that spawn is used today (free drive, solo `p2p`, solo `circuit`), with **no mode gate**. This overrides the research's Open Question 2 recommendation ("free drive only"), which existed only to protect medal times (see D-22). `circuit-race` keeps its grid from the course. `?at=` and `?start=` still win in every mode.
- **D-19:** Scenery casts no shadows in this version.
- **D-20:** AI cars ignore scenery for now. Accepted; revisit if pursuers look too stupid in play. Do not add avoidance in this phase.
- **D-21:** The editor draws every sidecar building, including style-less ones from converted maps, as plain blocks so they can be seen and deleted.
- **D-22:** Keeping existing medal times valid is **not** a constraint at this stage of the project (user, 2026-11-15). Do not add complexity to protect them. Unintended handling changes are still bugs: do not edit `src/physics/vehicle.ts` in this phase.

### Claude's Discretion
Exact catalog numbers, colours, marker look, hotkeys (must pass the hotkey audit test), and how plans are split into waves.
