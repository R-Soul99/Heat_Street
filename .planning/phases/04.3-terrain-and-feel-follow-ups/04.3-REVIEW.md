## Summary

No Critical issues found in the files read. The terrain editor PUT endpoint is sound against path traversal.

- The area id must match `/^[a-z0-9-]{1,64}$/`.
- The file kind is limited to `bin` or `json`.
- The resolved path is checked to sit under `public/maps`.
- Bodies are size-capped, validated with the shared codec, and written through temp-file plus rename.
- `resolveTerrainFile` does not rely on separators in the id, because the regex excludes them.

The determinism grep found no violations.

- `Math.random` appears only in `src/audio/surface-loops.ts` and `src/render/surface-fx.ts`, both render/audio only.
- `performance.now` is limited to `src/loop.ts` and `src/debug/`.

The wheel-ray patch is driven by chassis position at the fixed tick, so it is deterministic. Its rebuild logic holds up: `update()` cannot fall through with a stale target, because the `found !== t` branch is always taken once the target is out of bounds.

## Warnings

### WR-01: `safeMessage` leaks partial Windows paths containing spaces

**File:** `tools/terrain-editor/vite-plugin.ts:48`
**Issue:** The Windows branch `[A-Za-z]:[\\/][^\s"']*` stops at the first whitespace. This repository lives at `d:\Projects 2\Heat Street - Copy\...`. An fs error such as an ENOENT or EPERM message would be redacted to `<path> 2\Heat Street - Copy\public\maps\x.terrain.json`. That defeats the stated T-04.2-37 intent. The server is dev-only and localhost, so impact is low, but the sanitiser does not do what its comment claims.
**Fix:** Do not forward raw fs error text for non-validation failures. Only pass messages through when they start with a known validation prefix; otherwise return a fixed string.
```ts
const isValidation = /^(terrain-format:|parseRoadGraph:|terrain-save:)/.test(raw);
return sendError(res, isValidation ? 400 : 500, isValidation ? safeMessage(err) : "write failed");
```
Log the real error server-side with `server.config.logger.error`.

### WR-02: Bin and sidecar PUTs are validated independently and can be saved out of sync

**File:** `tools/terrain-editor/vite-plugin.ts:132-141`
**Issue:** The `.bin` PUT only decodes the binary. The `.json` PUT only parses the sidecar. Nothing cross-checks that the grid dimensions (rows, cols, cell size) in the sidecar match the binary. The two files are written by separate requests with no transaction.
- A client that fails between the two PUTs, or a hand-crafted PUT, leaves the area half-saved.
- Either the loader or `buildTerrainCollider` then receives mismatched dimensions, and `ColliderDesc.heightfield` can be handed a height array of the wrong length. That would throw or corrupt the collider.

**Fix:** On the JSON PUT, read the existing `.bin` and verify dimensions against the new sidecar, or have the loader assert `heights.length === (rows + 1) * (cols + 1)` and fail with a clear error. Ideally save both in one request.

### WR-03: 413 handling destroys the socket before the response is sent

**File:** `tools/terrain-editor/paths.ts:47`
**Issue:** `req.destroy()` is called before the promise rejects. The middleware then calls `res.end` on a destroyed socket, so the client usually sees a connection reset rather than the 413 JSON. It is functionally safe, but the error contract in `vite-plugin.ts:145` is not reliably delivered.
**Fix:** Stop accumulating and call `req.resume()` to drain, or reject first and destroy after the response is flushed (`res.once("finish", () => req.destroy())`).

## Info

### IN-01: Drive logger registers global listeners and a DOM badge with no teardown

**File:** `src/debug/drive-logger.ts:142-196`
**Issue:** `createDriveLogger` appends a badge to `document.body` and adds `keydown`, `keyup` and `blur` listeners on `window`, and nothing removes them. If a map switch re-runs composition without a full page reload, loggers and badges stack up. Each stacked logger would toggle on `L` and download duplicate CSVs.
**Fix:** Return a `dispose()` that removes the listeners and the badge, or guard with a module-level singleton.

### IN-02: `buildRuns` and `buildEdgeBerm` have an undocumented minimum grid size

**File:** `src/core/terrain-edge-berm.ts:49-74`
**Issue:** With `h.length - 1 === 0` there are no runs, so no berm boxes are produced and a degenerate grid silently has no wall. Grid construction requires `cellSizeM > 0` but does not appear to enforce `rows >= 1` and `cols >= 1` (not verified).
**Fix:** Assert `grid.rows >= 1 && grid.cols >= 1` at the top of `buildEdgeBerm`.
