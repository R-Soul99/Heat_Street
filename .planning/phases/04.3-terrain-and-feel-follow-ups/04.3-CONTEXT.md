# Phase 04.3: Terrain and Feel Follow-ups - Context

**Gathered:** 2026-11-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the follow-ups Phase 4.2 left open, before Phase 5's race modes build on them. No new capabilities beyond the roadmap list:

1. The shipped car stops spinning when the throttle is lifted on narrow, fast roads (lift-off oversteer).
2. The 2/60 one-tick wheel-contact losses on the slope gate are gone.
3. Terrain maps have a boundary at the edge, so the car can't simply drive off the world.
4. Roads are wider (+2 m).
5. juliette-ga render CPU is back under its 6.0 ms slice (measured 7.71 ms).
6. The terrain editor refuses to save a road graph that fails validation.
7. The terrain editor gains a square raise/lower tool with a separate smoothing pass.
8. Medal reference times are re-recorded **last**, once the car is retuned and roads are widened.

</domain>

<decisions>
## Implementation Decisions

### Lift-off oversteer fix
- **D-01:** The target feel is "keep it lively". Lifting mid-corner should still make the tail step out clearly and catchably. Only the unwanted spins go: a lift on a straight, or with small steering corrections on a gentle bend or narrow fast road, must not spin the car.
- **D-02:** Fix by **reshaping the curve**, not just lowering the number. Keep the shipped `liftOff` feel value at 5. Change the `liftRaw` term in `src/physics/vehicle.ts` (around lines 699-716) so that:
  - small steer inputs and small real wheel angles or slip contribute little, and big ones contribute a lot (a progressive, non-linear response instead of today's linear one, which saturates at 1 with about 20% steer and a full lift);
  - how loose the rear can get from lift-off alone is capped below a full release to `powerOversteerRearSideFriction`.
  The exact shape (exponent, thresholds, cap) is Claude's discretion, set from measurements.
- **D-03:** Add new feel-dossier routines as **hard tests**: (a) a full lift at speed on a straight with no or minimal steer, and (b) a full lift on a gentle bend with small corrections. Both must not spin, using the shipped feel-preset car rather than only `defaultTuning()` (see D-04).
- **D-04:** The existing `lift-off-60` routine (94 deg overshoot today) is a **guide only**: report it, don't gate it. The human drive decides.
- **D-05:** The sign-off drive is on **juliette-ga** (where the spin happens) and **feel-test** (the baseline).

### Terrain edge boundary
- **D-06:** A **solid physics barrier** runs around the terrain bounds. The car bumps off it like a building: no teleport, and timed runs are never interrupted.
- **D-07:** It is a **visible low wall or berm** that reads clearly from the helicopter cam.
- **D-08:** It is **built automatically at load** for every terrain map. Nothing is authored or saved in the area file or the editor, so all existing terrain maps get it for free.
- **D-09:** The collider is **only as tall as the visible berm**. A big jump can carry the car over it.
- **D-10:** If the car clears the wall, **let it fall**. There is no out-of-bounds respawn safety net; the player restarts with R. This was an explicit user choice, and the respawn option was offered and declined.

### Road width
- **D-11:** Every road gets **+2 m** total width (1 m each side).
- **D-12:** This applies to the **migrated maps juliette-ga and grid-test**, by re-running the converter (`tools/map-compiler/terrain/convert.ts`) with the wider width, and to the **road-brush presets** in `src/core/terrain-road.ts` `ROAD_PRESETS` (street 8 to 10, highway 12 to 14, track 6 to 8, dirt 5 to 7).
- **D-13:** **feel-test is NOT widened.** It stays the unchanged baseline for the dossier, the drive logger and `feel-test.medals.json`.
- **D-14:** demo-hills (hand-painted) keeps its painted roads. Widening it would need a repaint and is not part of this phase.

### Editor save guard
- **D-15:** Saving **blocks** on hard validator failures and shows the reason, reusing the existing message format in `validateRoads()` (`tools/terrain-editor/editor.ts:501`).
- **D-16:** These are explicit exceptions that do not block a save:
  - `UNDIRECTED_REACHABILITY` (disconnected pieces are fine mid-build; today it is already treated as info);
  - `GEOMETRY_SELF_INTERSECTION` on terrain maps, because terrain maps never build ribbon road meshes (see 04.2-VERIFICATION.md override). This means demo-hills, with its 3 accepted failures on edge 0, still saves.
- **D-17:** Where to enforce it (client-side in `save()`, and/or server-side in `tools/terrain-editor/vite-plugin.ts`'s PUT validation) is Claude's discretion. The rule must be the same in both if both enforce it.

### Square raise/lower tool + smoothing pass (folded todo)
- **D-18:** Block size is an **adjustable N x N cells** slider, from 1 x 1 (8 m) up to about 8 x 8 (64 m). Click steps one block; dragging paints blocks.
- **D-19:** The step height is **adjustable, default 1 m**, with a slider of roughly 0.25 to 5 m. A click raises; Shift+click lowers (match existing raise/lower modifier conventions if they differ).
- **D-20:** The **35 deg slope limiter still applies** to square steps, and road-flagged cells stay levelled (WR-02), so the map is always driveable even before smoothing.
- **D-21:** Smoothing is a separate pass with two entry points: **"Smooth area"** (brush or box selection) and a **"Smooth whole map"** button. Each is one undo step through `src/core/terrain-undo.ts`, has adjustable strength and passes, and **never touches road cells**.
- **D-22:** All four visibility aids are in scope:
  - a toggleable **grid overlay** of the cell lines;
  - a **block preview**: an outline of the exact cells the next click changes, plus the current height there;
  - toggleable **height contours** (e.g. every 1 m);
  - a **zoom check** hint when zoomed out too far to see single cells.

### Order of work
- **D-23:** Medal references are re-recorded **last**, after the lift-off retune (D-01..D-05) and the road widening (D-11..D-12), because both change lap times.

### Claude's Discretion
- **juliette-ga render budget** (7.71 ms to under 6.0 ms): the approach is open (draw-call merging, chunk culling, lazy paint textures, etc.). It must be measured with the `?debug` profiler HUD and recorded in `docs/frame-budget.md`.
- **2/60 one-tick contact loss on the slope gate:** diagnosis and fix are open (see 04.2-GATE.md and 04.2-05-SUMMARY.md). The constraints are that collider subdiv 2, max slope 35 and max bank 8 are locked from the 04.2 sign-off, and the `ramp` routine stays on its absolute band.
- **Medal re-record mechanics:** which maps need it follows from what changed. juliette-ga and grid-test need it (wider roads and a retuned car). Re-check feel-test and demo-hills only if the lift-off change moves their times. Use the existing `buildReferenceCourseRecord` debug flow and bump `handlingContentVersion`.
- Berm height, berm look, and the exact inset from the heightfield edge.
- The exact curve shape and cap for the lift-off fix (D-02).

### Folded Todos
- **Add square raise/lower tool with separate smoothing pass** (`.planning/todos/pending/2026-11-03-add-square-raise-lower-tool-with-separate-smoothing-pass.md`). The problem: the soft round brushes are slow and their effect is hard to read. It is folded into D-18..D-22.

</decisions>

## Existing Code Insights

### Reusable Assets
- `src/physics/vehicle.ts` ~L699-716: the current lift-off blend (`lift`, `throttleRef`, `liftRaw`, `liftHold`, `counterSteerFade`). This is where the curve gets reshaped.
- `src/core/feel.ts`: the `liftOff` feel slider maps to `drive.liftOffOversteer` (0..2x base) at L179.
- `src/physics/telemetry/routines.ts` / `run.ts` and `npm run feel-dossier` (`vitest.dossier.config.ts`): the routine harness for the new no-spin tests.
- `src/physics/terrain-scene.ts`: the terrain heightfield collider. The edge barrier colliders go next to it.
- `src/render/terrain-view.ts`: the chunked terrain render. It holds the berm visuals and is the likely home of the juliette-ga render work.
- `src/core/terrain-road.ts` `ROAD_PRESETS`, `MIN_ROAD_WIDTH_M` / `MAX_ROAD_WIDTH_M`: the preset widths.
- `tools/map-compiler/terrain/convert.ts`: the converter that levels bands and paints roads from `edge.widthM`.
- `tools/terrain-editor/editor.ts`: `save()` (L316) and `validateRoads()` (L501), which already splits reachability failures from hard ones.
- `tools/terrain-editor/vite-plugin.ts`: the dev-server PUT endpoint, which already validates with the shared codec.
- `tools/terrain-editor/tool-dispatch.ts`, `src/core/terrain-brush.ts` (`raiseLower`, `smoothBrush`, `flattenBrush` ~L284/309), `src/core/terrain-slope.ts` (slope limiter) and `src/core/terrain-undo.ts` (stroke diffs, 50-deep undo): the base for the square tool and the smoothing pass.

### Established Patterns
- Fixed-timestep physics. Medal times depend on tuning, so any handling change means a medal re-record (D-23).
- Feel changes are measured with `npm run feel-dossier` and then signed off by a human drive, one problem per change.
- Saved browser tuning in localStorage can hide new code defaults. Clear it before the sign-off drives.
- Headless telemetry still uses `defaultTuning()`, not the shipped feel preset (04.2-15 follow-up). The new lift-off routines should run against the shipped preset car.
- Editor status text uses DOM/textContent only (WR-06).

### Integration Points
- The edge barrier hooks into terrain map loading (the same path as the heightfield collider) and the terrain render.
- The save guard hooks into the editor `save()` and, optionally, the vite-plugin PUT.
- Road widening means re-running the converter for juliette-ga and grid-test and regenerating `public/maps/*.terrain.*`, with tests such as `tests/demo-hills.test.ts` and the migration tests updated as needed.

</code_context>

<specifics>
## Specific Ideas

- The lift-off should stay a usable chase-movie trick: lively and catchable, not neutered.
- The edge should read as "the world ends here" from the overhead helicopter view. Jumping over it is a deliberate risk the player takes.
- The square tool is for roughing out shape fast and visibly. Sharp-looking blocks are fine; smoothing comes afterwards.

</specifics>
