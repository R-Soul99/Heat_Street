## Findings (shipped car, flat telemetry scene)

Sweeping `drive.liftOffOversteer` 0 vs 5 on UNMODIFIED vehicle.ts:

| Routine | gain 0: peak slip / overshoot | gain 5: peak slip / overshoot |
|---|---|---|
| lift-straight-90 | 13.5 / 116.9 | 13.5 / 116.9 (identical at all gains) |
| lift-gentle-60 | 2.4 / 194.4 | 2.6 / 194.6 |
| lift-bend-90 | 2.6 / 129.0 | 6.0 / 132.6 |
| lift-bend-75 | 2.4 / 158.9 | 6.7 / 165.2 |
| lift-bend-60-03 | 2.2 / 206.3 | 7.2 / 217.2 |
| lift-off-60 | 3.3 / 92.6 | 29.8 / 94.6 |

1. headingOvershootDeg is independent of the lift gain (gain 0 gives the same numbers). It is steady cornering, not a spin. In lift-gentle-60 the car holds 0.2 steer; yaw 0.6 to 1.0 rad/s, slip stays about 2 deg; heading just keeps turning. The speed lock fade restores steering angle as speed drops, so yaw rises. So the orchestrator's "assert on headingOvershootDeg" advice is unusable for bend routines: no lift curve can lower it.
2. lift-straight-90 wanders (yaw 0.55 under throttle from a 0.08 wiggle, dominant term `power`, then `flick`) with gain 0 as well. That is a power-blend / high-speed steering sensitivity problem, not lift-off.
3. The lift blend adds only about 3-5 deg of slip on straights and bends. Only lift-off-60 (steer 0.8) reaches peak slip 29.8, near the spin line but a deliberate "lively" case.
4. The prototype curve cut shipped lift-off-60 peak slip from 29.8 to 3.4 (below the lively > 8 bound) and also broke the existing tyre-falloff slide test (hold-slide-70), while changing no spin-routine number. So the plan's curve as specified is not safe either.
