# Phase 04.3 Plan 05: High-speed tap-correction oscillation fix (retargeted from the lift-off spin)

The original lift-off reshape was abandoned (the earlier version of this summary recorded why: the spin was not reproducible on the flat harness and the plan's curve would have killed `lift-off-60` and `hold-slide-70`). On 2026-11-03 the user supplied a drive log that shows the real "unwanted spin": a keyboard **tap-correction oscillation at 70-105 mph**. Each short correction tap over-corrects, the swings grow, and the car spins. The user approved fixing all three causes. All new values are exposed as tunables and are **pending the plan 11 sign-off drive**.

## Evidence (logs/tap-correction-spin-2026-11-03.csv, untracked, not committed)

Shipped feel preset (flick 5.1, steerAtSpeed 7, looseness 5.3), keyboard, flat juliette-ga.

- t=1.97, 68 mph: a 3-tick tap took steer to 0.316 = 11.7 deg front wheel; settled in about 0.8 s.
- t=8.40, 104 mph: a 2-tick tap = 6.3 deg; afterwards yaw stayed about 0.16 rad/s for more than 0.7 s with steer 0 (no yaw damping at speed).
- t=9.12, 104 mph: a 5-tick counter-tap reached steer -0.527 = 15.8 deg; yaw -0.65; `rear_side_friction` fell 0.277 -> 0.205 (rear term `power`); slip kept growing after release.
- t=9.70: a 5-tick tap led to yaw +2.8 rad/s, a spin.
- Full lock was about 31 deg at 97 mph (37 deg at 68 mph). Keyboard ramp: +0.105/tick on, only -0.067/tick off, so short taps lingered.
- The flick term never touched rear grip; the user's own tries (flick 0, steerAtSpeed 5, looseness 4) did not fix it. Plan 05's earlier probe also found the 90 mph wander dominated by `power`, then `flick`.

The headless harness now reproduces it: tap routines replayed through the real `LiveInputSource` ramp on `shippedTuning()` gave, before the fix, a single 3-tick tap at 100 mph that never settled (65 deg of heading), and equal alternating taps whose yaw peaks grew 0.55 -> 0.99 -> 1.14 rad/s.

## Fixes (one commit each cause, plus the test-first commit)

1. **Speed-sensitive steering (commit 5fdc27d).** Fixed the curve itself instead of adding a limiter: `highSpeedSteerFraction` base default 0.45 -> 0.09 (the `steerAtSpeed` feel mapping, unchanged, multiplies by x1.48 at the shipped slider 7, so 0.133 effective). The existing `steerLockScale` smoothstep (full lock below 12 m/s, easing to the fraction at top speed) is untouched. Keyboard return-to-centre `steerReturnPerSec` 4 -> 6, and the `?feel` turn-in slider now scales it with the wind-on (`lerp(0.4, 1.6, turnIn/10)`), so it is always at least as fast as the ramp (7.6 vs 6.3 /s at the shipped 7.2). I did not add speed-scaling of the keyboard ramp: lock already shrinks with speed, so a 2-tick tap at 100 mph is now about 1.5 deg of wheel. Gamepad analog input is untouched (it passes straight through and the lower lock scales it proportionally).
2. **Power oversteer gate (commit 97d6db0).** `powerBlend` is multiplied by `max(speedFade, slipOpen)`: `speedFade` falls smoothly from 1 at 25 m/s (56 mph) to 0 at 40 m/s (90 mph); `slipOpen` rises over slip 6 -> 12 deg, so a rear that is really sliding bypasses the fade (deliberate high-speed slides, `hold-slide-70`, stay possible). Below 25 m/s nothing changes.
3. **High-speed yaw damping assist (commit 97d6db0).** A chassis torque impulse in the fixed-step tick only (step 5e, after the flick kick). It removes `yawDampingGain` (5 /s) of the *unwanted* yaw rate per second at full gate, where wanted yaw = forward speed x tan(front wheel angle) / wheelbase. One-sided: it only ever reduces |yaw| (an understeering car on mud is never helped round; this fixed an earlier two-sided draft that broke the skidpad surface ordering test). Gates multiply: speed (0 below 14 m/s, full at 30 m/s), steer (fades out as |steer| goes 0.17 -> 0.5), slip (fades out as slip goes 5 -> 10 deg), off with the handbrake, needs a rear wheel in contact. Pure function of the tick's state, so medal times stay deterministic.

## Deviations from the brief

1. **[Rule 1] Two-sided damping broke `surface-telemetry` skidpad ordering** (mud measured higher lateral g than other surfaces, because a kinematic "demanded yaw" is more than an understeering car achieves, so damping pushed it round). Fixed by making the assist one-sided (never adds rotation) before committing.
2. **`tests/vehicle-recovery.test.ts` anti-trivially-green companion** ("a loose rear 0.12 fails the highSpeedPulse band") started passing because the yaw damping assist now stabilises that car (peak slip 9.3 -> 3.5 deg, passes the band). That test only proves the routine *can* fail, not liveliness. I kept its original assertions unchanged but measure it with `yawDampingGain = 0`, and added a test that with the assist on the same car passes while a very loose rear (0.05) still fails. This is a re-anchor in the same style as the 2026-10-23 and 2026-10-28 ones in that file; flagging it in case you would rather handle it differently.
3. The brief asked for one fix commit per cause where practical. Causes 2 and 3 share a commit (97d6db0): they edit the same tuning interface, panel and tick function, and the tap tests need both to pass.
4. Stage note: the guide update (which the `tuning-guide-sync` test needs) is in the docs commit as requested, so that test is red on commit 97d6db0 and green again on the docs commit.

## What you need to do before driving it

- **`?feel` (recommended path): nothing.** `?feel` replaces any saved big-panel blob with the class base and derives the handling from the feel sliders every load, so the new base values flow in. The new "High-speed stability" slider defaults to 5 for everyone (missing in an old saved feel blob falls back to the default). You do not have to click "Reset to base" unless you want to put your other sliders back to the shipped preset.
- **Without `?feel`** the game loads the saved big-panel blob (`heat-street.tuning.v1`, per class keys for fwd/awd) over the class defaults and `parseSavedTuning` copies saved leaves over new defaults. If you ever saved from the big tuning panel, that blob still holds the old `highSpeedSteerFraction`/`steerReturnPerSec` and hides the new values (new yaw damping and power fade keys are missing in it, so they take the new defaults, which is half a fix). Clear that key, or use the panel's reset, to see the full new behaviour. The project has no tuning version mechanism, so I did not add one.
- Medal times: the new steering lock and assist change high-speed handling, so any times recorded before this plan are on different physics. This is the same re-recording caveat as the other 04.3 feel changes (plan 11 sign-off).
