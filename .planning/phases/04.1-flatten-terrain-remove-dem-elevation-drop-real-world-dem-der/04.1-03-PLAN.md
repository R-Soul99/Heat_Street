  profile. For `t <= 0` return `heightM`; for `t >= 1` return `0`; otherwise return
  `heightM * (1 - (3 * t * t - 2 * t * t * t))` (one minus smoothstep). Doc-comment that this
  profile is C1-continuous at BOTH ends, which is what makes the rim seam invisible and the apex
  launchable rather than a discontinuous lip.

- `export interface CrestGeometryEntry { readonly crestId: string; readonly surface: SurfaceType; readonly positions: Float32Array; readonly indices: Uint32Array }` —
  field-for-field parallel to `ShoulderGeometryEntry`, with `surface` documented as always

- `export function buildCrestGeometry(crests: readonly AuthoredCrest[], heightSampler: (x: number, z: number) => number): readonly CrestGeometryEntry[]`

  Per crest, build a radial dome:
  - Vertex 0 is the apex at `(centerX, heightSampler(centerX, centerZ) + heightM, centerZ)`.
  - For ring `r` in `1..CREST_RINGS` and segment `s` in `0..CREST_SEGMENTS-1`:
    `t = r / CREST_RINGS`, `radius = radiusM * t`,
    `theta = (2 * Math.PI * s) / CREST_SEGMENTS`,
    `x = centerX + radius * Math.cos(theta)`, `z = centerZ + radius * Math.sin(theta)`,
    `y = heightSampler(x, z) + crestProfileHeight(t, heightM)`.
    The outermost ring therefore lands EXACTLY on the sampled terrain height (profile is 0 at
    `t === 1`) — the same rim-seating technique `buildEdgeShoulder` uses for its outer rail, and
    the reason a crest never produces a cliff at its base.
  - Triangles: a fan from the apex to ring 1, then two triangles per quad between consecutive
    rings, each ring closing back to segment 0.
  - Winding must be CCW viewed from +Y, matching every other surface in `road-geometry.ts`. If
    the first index ordering produces clockwise triangles, swap the second and third index of
    every triangle rather than changing vertex generation — the test in Task 2 is the arbiter.
  - Return `positions` as a `Float32Array` of length `3 * (1 + CREST_RINGS * CREST_SEGMENTS)`
    and `indices` as a `Uint32Array`.

  Defensive invariants, thrown with this repo's "name the function and the offending id" style:
  throw if `radiusM <= 0`, if `heightM <= 0`, or if two crests share an `id`. Message must
  contain `buildCrestGeometry:` and the crest's `id`.

  the point-to-point distance rather than `NaN`.

- `export interface RoadDistanceField { distanceToPavedEdgeM(x: number, z: number): number }`

- `export function buildRoadDistanceField(graph: RoadGraph): RoadDistanceField`
  Precompute, once, a flat array of every edge segment as
  `{ ax, az, bx, bz, halfWidthM, minX, maxX, minZ, maxZ }`, where `halfWidthM` is that edge's own
  `widthM / 2` and the bounding box is the segment's XZ box expanded by `halfWidthM`.
  `distanceToPavedEdgeM(x, z)` returns
  `Math.max(0, min over segments of (pointToSegmentDistanceXZ(...) - halfWidthM))` — clamped at
  0 so a query point on the pavement returns 0, never a negative number.
  Performance guard (required — the caller runs this 16,641 times over ~1,800 segments): inside
  the loop, skip any segment whose expanded bounding box is farther from `(x, z)` than the
  running best, using the cheap box-distance
  `Math.hypot(Math.max(0, minX - x, x - maxX), Math.max(0, minZ - z, z - maxZ)) - halfWidthM`.
  Throw `buildRoadDistanceField: graph has no road segments to measure against` if the graph
  yields zero segments, rather than silently returning `Infinity` everywhere.
