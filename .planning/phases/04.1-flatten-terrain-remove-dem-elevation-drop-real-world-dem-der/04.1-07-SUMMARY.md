# Phase 04.1 Plan 07: Authored Crests Wired Into the Compiled .glb and Runtime Physics Summary

**`buildGltfDocument` now bakes a `crests` mesh into the compiled `.glb` and `src/physics/map-scene.ts` now builds one grass-registered trimesh collider per authored crest, both driven by the identical `buildCrestGeometry`/`crestsForArea`/bilinear-sampler call plan 04.1-03's pure geometry module already provides — closing the "launch over the hill" gap between authored geometry and both consumers.**

## Accomplishments

- `tools/map-compiler/author/gltf.ts`: `buildGltfDocument` gains a fifth `crests: readonly CrestGeometryEntry[] = []` parameter; when non-empty it merges every entry through the existing `concatGeometry` helper into a `crests`-named mesh/node at identity transform (matching the `terrain`/`buildings` naming convention `map-view.ts` looks meshes up by), and reports `crestCount`/`crestTriangleCount`/`crestVertexCount` on `GltfBuildStats`. Passing no crests (every existing call site) leaves the document unchanged.
- `tools/map-compiler/author/gltf.test.ts`: new `buildGltfDocument — authored crests (D-04b)` describe block (4 tests) covering the zero-crests default path, real `JULIETTE_GA_CRESTS` wiring (mesh/node presence, identity transform, `crestCount === 3`), stat-sum correctness, and index-rebasing.
- `src/physics/map-scene.ts`: `buildRoadColliders` threads a new `areaId: string` parameter (sourced only from `collision.areaId`, never defaulted) and, inside the existing heightfield guard, builds one trimesh collider per authored crest via `buildCrestGeometry(crestsForArea(areaId), heightSampler)` on the shared `roadBody`, registered as `"grass"` — structurally mirroring the shoulder block immediately above it.
- `tests/map-scene.test.ts`: the road-collider count assertion now adds `crestsForArea(collision.areaId).length` instead of a bare constant; a new `authored crest colliders (D-04b)` describe block (4 tests) proves the collider-count delta against an unknown `areaId`, grass registration, a downward-raycast apex-height match within 0.5m, and the unknown-`areaId` zero-crest/no-throw case.

**3. [Rule 1 - Bug] Crest raycast tests' ray origin ignored the real (still-DEM-era) heightfield ground height**
- **Found during:** Task 2, first test run — both new raycast-based tests failed with `hit` being `null`.
- **Issue:** The plan's literal action text specifies a ray origin of `crest.heightM + 5` metres, implicitly assuming a near-zero terrain baseline (the flat-terrain future state this whole phase is building toward). The currently-committed `public/maps/juliette-ga.collision.json` on disk still carries the OLD DEM-era elevation (measured via a throwaway diagnostic test: ~140-147m at the three crest centres), because the flat-terrain recompile that zeroes this out is plan 04.1-08/09's job — not wired in yet. A ray starting at `y = 14` (`9 + 5` for the tallest crest) when the real ground is ~147m never reaches anywhere near a collider.
- **Fix:** Both tests now call `sampleHeightfieldBilinear(heightfield, crest.centerX, crest.centerZ)` first and use `groundY + crest.heightM + 5` as the ray origin height, and the apex-height comparison uses `groundY + crest.heightM` as the expected value instead of the plan's literal (baseline-assuming) `crest.heightM`. This is the SAME sampler the crest collider code itself uses, so the test's expectation formula matches the implementation's own formula regardless of what the currently-compiled ground height actually is — it will keep passing unchanged once 04.1-08/09 recompiles the area with flat elevation.
- **Files modified:** `tests/map-scene.test.ts`
- **Verification:** Diagnostic test (created, run, then deleted — never committed) confirmed the real sampled heights; after the fix, all 4 new crest-collider tests pass, and confirmed load-bearing by temporarily stubbing the crest-collider block to an empty array — 2 of the 4 tests then fail as expected (collider-count delta and apex-height match), then reverted and re-verified green.
- **Committed in:** `bd81350` (Task 2 commit)
