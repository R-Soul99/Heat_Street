<objective>
Replace the DEM-sampled off-road heightfield with a deterministic, seeded, capped procedural
relief generator whose amplitude fades to exactly zero at every road's paved edge (D-02, D-02a,
D-02b, D-03).

reintroducing a road-to-terrain height mismatch. The grid SHAPE (`HeightfieldGrid`, the verified
`heights[row + col * (rows + 1)]` storage order, the sink field) is unchanged, so
`author/collision.ts`, `author/gltf.ts`, `src/core/heightfield-sample.ts` and
`src/physics/map-scene.ts` all keep working untouched — only the per-cell value computation
changes.

Output: `buildOffRoadRelief(graph, bounds, resolution?)` and a rewritten unit suite.

- `export const RELIEF_AMPLITUDE_M = 2;` — D-02a's locked cap, chosen by the developer over a
  +/-5m option as "noticeably subtler". Raising it steepens every shoulder ramp and works
  against this phase's whole purpose; lowering it toward 0 makes off-road terrain read as the
  featureless plane D-02 explicitly rejected.
- `export const RELIEF_FALLOFF_DISTANCE_M = 130;` — the distance from a road's PAVED EDGE over
  which relief ramps from 0 up to full amplitude. **Record the deviation from
  04.1-RESEARCH.md's Assumption A3 explicitly and with its reason**: A3 proposed a falloff
  distance no larger than the shoulder width (a few metres), which is unrepresentable — this
  grid's own spacing is ~43m, so a sub-cell falloff is invisible after the grid is baked and
  bilinearly resampled, and the terrain adjacent to a road would then carry near-full amplitude
  anyway. 130m is ~3 grid cells, so the nearest grid node to any road (at most ~30m away)
  carries only `RELIEF_AMPLITUDE_M * smoothstep(30/130)` = ~0.27m. D-02b's literal guarantee
  ("exactly 0 at the paved edge") holds a fortiori, and the residual height inside plan
  04.1-02's 6m shoulder is ~0.27m + `HEIGHTFIELD_SINK_M`, i.e. under 4 degrees of grade.
  State the hard invariant: `RELIEF_FALLOFF_DISTANCE_M` must stay at least 3x the grid spacing
  (`max(scaleX, scaleZ) / resolution`), enforced by this plan's test.
- `export const RELIEF_SEED = 20260919;` — fixed seed so a recompile is byte-identical; note
  that `Math.random` is forbidden here for exactly that reason.
- `export const RELIEF_FEATURE_SIZE_M = 220;` and `export const RELIEF_COARSE_FEATURE_SIZE_M = 500;`
  — the two noise octave wavelengths. Both must stay well above the ~43m grid spacing or the
  noise aliases into per-cell jitter rather than reading as rolling ground.

Change `HEIGHTFIELD_SINK_M` from `4.5` to `0.1`, and REWRITE its doc comment (keeping the old
revision history as history, per this file's own convention) to record that the constant's JOB
has changed, not just its value: it no longer bridges a real smoothed-road-vs-raw-DEM elevation
disagreement (there is no DEM), it is now purely a physics-contact separation margin so the road
ribbon at y=0 and the terrain grid are never exactly coincident static colliders (RESEARCH.md
Pitfall 4 — coincident zero-gap colliders cause contact-solver jitter and z-fighting). Note that
0 is deliberately NOT used, and that 0.1m is `[ASSUMED]` pending plan 04.1-10's session.

New functions:

- `function hashLattice2D(ix: number, iz: number, seed: number): number` — a deterministic
  integer hash returning `[0, 1)`. Use integer mixing (`Math.imul`, xor, unsigned shift), NOT
  `Math.sin`-based hashing, so the value is bit-stable across engines and the recompile stays
  byte-identical. Doc-comment that requirement.
- `function valueNoise2D(x: number, z: number, featureSizeM: number, seed: number): number` —
  classic lattice value noise: floor to lattice coords at `featureSizeM` spacing, hash the four
  corners, smoothstep the fractional coordinates, bilinearly blend, and map the result from
  `[0, 1)` to `[-1, 1]`.
- `export function reliefAt(x: number, z: number, distanceToPavedEdgeM: number): number` —
  `noise = 0.65 * valueNoise2D(x, z, RELIEF_COARSE_FEATURE_SIZE_M, RELIEF_SEED) + 0.35 * valueNoise2D(x, z, RELIEF_FEATURE_SIZE_M, RELIEF_SEED + 1)`
  (the weights sum to 1, so the `[-1, 1]` range is preserved);
  `t = Math.min(1, Math.max(0, distanceToPavedEdgeM / RELIEF_FALLOFF_DISTANCE_M))`;
  `falloff = t * t * (3 - 2 * t)` (smoothstep — D-02b leaves the curve to Claude's discretion;
  smoothstep is chosen because it is C1 at both ends, so there is no visible crease where the
  relief reaches full amplitude);
  return `noise * RELIEF_AMPLITUDE_M * falloff`.
  Doc-comment the hard guarantees this function provides: the return value is exactly `0` when
  `distanceToPavedEdgeM <= 0` (D-02b), and `Math.abs(return) <= RELIEF_AMPLITUDE_M` always
  (D-02a).
- `export function buildOffRoadRelief(graph: RoadGraph, bounds: RoadGraphBounds, resolution: number = HEIGHTFIELD_RESOLUTION): HeightfieldGrid` —
  keep the EXACT `(resolution + 1) x (resolution + 1)` row/col loop and the identical
  `heights[row + col * samplesPerAxis]` storage assignment from `buildHeightfield` (the verified
  index math must not change). Build the distance field ONCE before the loop
  (`const roadDistance = buildRoadDistanceField(graph)`), then per cell assign
  `reliefAt(x, z, roadDistance.distanceToPavedEdgeM(x, z)) - HEIGHTFIELD_SINK_M`.
  Return the same `HeightfieldGrid` object shape with `sinkM: HEIGHTFIELD_SINK_M`.

Do NOT edit `tools/map-compiler/cli.ts`, `author/collision.ts`, `author/gltf.ts` or
`src/physics/map-scene.ts` from this plan. `cli.ts` is plan 04.1-08's; the other three consume
`HeightfieldGrid` by shape and need no change at all.
