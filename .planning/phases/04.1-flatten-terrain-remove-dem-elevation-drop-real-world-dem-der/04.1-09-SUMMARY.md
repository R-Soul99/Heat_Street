## Decisions Made

- Reproducibility check used SHA-256 hashing of all three artifacts across two consecutive compiles (stronger than the plan's own byte-length requirement for the `.glb`) — all three are bit-for-bit identical.
- The corruption regression-check edited both a node's `y` and its referencing edges' endpoint points together (not the node alone), because editing the node alone trips `parseRoadGraph`'s own pre-existing strict endpoint-Y-to-node-Y equality check at parse time, which throws before any test body runs (reported as a failed suite with "no tests", not per-test failures). The self-consistent edit keeps the artifact schema-valid while still exercising every new flatness assertion, and produced the intended signal: 4 tests failed (`has exactly one distinct node y value...`, `has exactly 0m of node elevation relief...`, `has exactly zero gradient on every edge...`, `has y exactly 0 on every edge point...`), comfortably over the plan's "at least 3" bar.
- Task 3's measurement script was written to the session scratchpad directory and executed via dynamic `import()` of absolute file paths (using `pathToFileURL`) for the local project TypeScript modules and for `@gltf-transform/core`'s installed entry point in the main repo's `node_modules` (this worktree's own `node_modules` only contains Vite's cache — the real `node_modules` lives in the main repo checkout the worktree is nested inside). This kept the report generator entirely out of version control as the plan requires, while still reusing the exact same sampling logic as `tests/compiled-map.test.ts`.
