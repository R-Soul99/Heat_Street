# Phase 04.1 Plan 01: Flatten Terrain — Flat Road Elevation Summary

Replaced the DEM-sampling/smoothing/densifying road-elevation compiler stage
(`applyElevation`) with a constant-zero flat-elevation pass (`applyFlatElevation`)
per D-01/D-03, so every compiled road node and edge point gets `y = 0` by
construction instead of by bridging a real DEM's noise.

## What Was Built

**Task 1 — `tools/map-compiler/graph/elevation.ts` rewrite:**
- Added `FLAT_Y = 0` (documented as D-03's literal baseline, not a placeholder).
- Added `applyFlatElevation(graph)`, following the file's existing pure-transform
  convention: `graph.nodes.map(...)` and `graph.edges.map(...)` each returning
  new spread-constructed objects, never mutating `graph` or anything reachable
  from it.
- Added a private `polylineLength2D` helper (exact once every point shares one
  `y`), replacing the old `polylineLength3D`.
- Added `FlatElevationReport` (`nodeCount`, `edgeCount`, `pointCount`,
  `maxAbsNodeY`, `maxAbsPointY`, `totalEdgeLengthM`) as the flatness regression
  signal.
- Preserved the existing defensive-throw convention: an edge referencing a
  node id absent from the graph's own `nodes[]` throws
  `applyFlatElevation: edge id=${edge.id} references node id(s) not present in the graph's own nodes[]`.
- Deleted all DEM-era machinery that has no job once `y` is constant by
  construction: the interior moving-average smoothing pass and its
  distance-weighted averaging helper, the long-segment point-densification
  pass, the per-edge steepest-gradient scan and its warning threshold, the
  real-3D polyline-length helper, `ElevationReport`'s gradient-report fields,
  and the lat/lon `ElevationSampler`/`Projector` type imports.
- Rewrote the file header comment to explain the new flat-baseline behavior,
  cite D-01/D-03, describe (without naming, to satisfy the plan's own
  zero-literal-match acceptance criteria) what was deleted and why it's dead
  rather than merely unused, and restate the pure-data-transform layering
  discipline sentence.

**Task 2 — `tools/map-compiler/graph/elevation.test.ts` rewrite:**
- Replaced the DEM-sampler-based fixtures (`makeSawtoothSampler`,
  `makeNoisyJunctionSampler`, `makeRampSampler`, `makeBumpSampler`, the
  `Projector`) with fixtures that feed deliberately non-zero ("junk") `y`
  values directly into node/edge-point constructors — a no-op pass fails these.
- 6 tests cover: every node's `y` is exactly `0`; every edge point's `y` is
  exactly `0`; `lengthM` is the exact 2D length for a 3-4-5 right-triangle
  edge (within `1e-9`); input immutability (`graph`/`nodes`/`edges`/`points`
  all unchanged, compared via `structuredClone` snapshot and reference
  identity); the `FlatElevationReport` contents (`maxAbsNodeY`/`maxAbsPointY`
  both `0`, counts match the fixture, `totalEdgeLengthM` equals the summed
  edge lengths); and the missing-node-id throw (message contains both
  `applyFlatElevation` and the offending `edge id=`).
- Verified the suite genuinely exercises behavior: temporarily stubbed
  `applyFlatElevation` to return its unmodified input, ran the suite (all 6
  tests failed), then reverted the stub (all 6 pass again).
