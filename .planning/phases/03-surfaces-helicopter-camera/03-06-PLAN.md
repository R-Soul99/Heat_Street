<objective>
Turn SC1's claim — "driving from tarmac onto gravel, grass, mud, sand or dirt produces
a distinct and measurable grip change (skidpad lateral-G differs per surface)" — into a
command that runs in seconds and fails loudly when it stops being true.

Purpose: 03-VALIDATION.md names `tests/surface-telemetry.test.ts` as the direct
automated proof of SC1 and the only Wave-0 gate for the phase's central requirement.
This plan also settles two things Phase 2 and 03-RESEARCH.md left open rather than
carrying them into a playtest: whether the ground collider's own friction coefficient
participates in the tire model at all (Assumption A1 / Open Question 1), and whether
the `rearSideFriction` straight-line instability fixed in plan 02-10 reopens once real
lower-grip surfaces exist (`.planning/STATE.md`'s explicit Phase 3 carry-forward).

Output: an extended `src/physics/telemetry/run.ts`, a new
`src/physics/telemetry/surface-routines.ts`, and `tests/surface-telemetry.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telemetry world ↔ live game world | A telemetry run must never touch the world that produces a medal time (threat T-02-18, already mitigated in `run.ts`) |
| WASM allocation ↔ JS GC | Each `new RAPIER.World()` allocates in WASM linear memory JS GC does not reclaim; a six-surface sweep creates six worlds per call |
| `SurfaceProfiles` parameter → Rapier setters | The sweep is the one place a caller can feed arbitrary profiles straight into the solver |
