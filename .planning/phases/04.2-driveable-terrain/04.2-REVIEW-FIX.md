## Fixed Issues

### CR-01: Terrain save is not a consistent snapshot

**Files modified:** `src/core/terrain-format.ts`, `tools/terrain-editor/editor.ts`, `tests/terrain-format.test.ts`
**Commit:** ffd2eb5
**Applied fix:**
- `encodeTerrainBinary` quantises every height into a `Uint16Array` and range-checks each one (it throws instead of silently wrapping). It also copies the paint data. Both happen synchronously, before the deflate await.
- The editor allows only one save at a time.
- The editor serialises the sidecar at the same moment as the binary.
- An edit counter, bumped by `setDirty(true)`, decides whether the dirty flag can be cleared after the PUTs.

**Regression test:** the test edits the heights and paint while the encode is pending. It fails before the fix and passes after.

### CR-02: "New..." creates areas that can never be saved

**Files modified:** `tools/terrain-editor/new-area.ts`, `tools/terrain-editor/new-area.test.ts`, `tools/terrain-editor/index.html`
**Commit:** d9656da
**Applied fix:**
- `createEmptyTerrainArea` rejects grids over `MAX_TERRAIN_VERTICES` and paint maps over `MAX_PAINT_PIXELS` when the area is created. The error tells the user to use a larger cell size.
- The cell-size input's `min` is raised from 0.5 to 1.

**Regression tests:**
- 1000 m at 0.5 m cells is rejected, and so is 2000 m at 1 m cells.
- A 1998 m area at 1 m cells is created and encodes successfully.

### WR-01: Road stroke's slope limiter can move earlier roads' levelled vertices

**Files modified:** `src/core/terrain-road.ts`, `tests/terrain-road.test.ts`
**Commit:** 0ba1be5
**Applied fix:**
- Added an exported `roadVertexMask(grid, paint, graph, win)`, which combines the road paint with the levelled radius from the graph.
- The stroke's `limitSlope` mask now covers the whole limiter window. Before, it covered only the road paint.

**Regression test:** a road on 8 m cells, then a second road across a cliff. Before the fix, the first road's graph y drifted by 5.996 m. After the fix the drift is 0.

**Status:** fixed: requires human verification (limiter logic).

### WR-02: Sculpt brushes run the slope limiter with no road mask

**Files modified:** `src/core/terrain-brush.ts`, `tools/terrain-editor/tool-dispatch.ts`, `tools/terrain-editor/tool-dispatch.test.ts`
**Commit:** ba632a9
**Applied fix:**

- The dispatcher supplies `roadVertexMask` for raise/lower, smooth, flatten and stamp.

This closes the verifier-uncertain plan 07 truth 4.

**Regression test:** a road in a cutting, with raise dabs beside it. Before the fix, 56 road vertices moved. After the fix, none move and the graph y still matches the terrain.

**Status:** fixed: requires human verification (limiter logic).

### WR-03: Windowed limiter "fixes" pre-existing over-cap slopes and steps at the window border

**Files modified:** `src/core/terrain-slope.ts`, `src/core/terrain-brush.ts`, `tests/terrain-slope.test.ts`, `tests/terrain-brush.test.ts`
**Commit:** a021c9a
**Applied fix:** both parts of the review's suggestion.
1. `limitSlope` treats the one-vertex ring just outside the window as fixed sources. The sweeps read the ring but never write it.
   - When the ring makes one direction impossible to satisfy, the down/up choice now prefers the result with fewer remaining violations, then the cheaper one.
2. `runHeightOp` freezes two kinds of vertex as fixed sources: those the op does not change, and those already in an over-cap pair before the op. The tolerance is 0.02 m, to absorb save quantisation.

**Regression tests:**
- A 4 m dab on a 45° slope: before the fix it changed 37 vertices outside the radius, after the fix none.
- A 20 m block inside a window now ramps down to its unchanged neighbours instead of keeping a cliff at the border.

The gate is unaffected because it does not run the limiter.

**Status:** fixed: requires human verification (limiter logic).

### WR-04: Catmull-Rom physics upsample changes levelled road surfaces

**Files modified:** `src/core/terrain-grid.ts`, `tests/terrain-sampler.test.ts`
**Commit:** f7aa20a
**Applied fix (the minimal option):** `upsampleTerrainGrid` interpolates linearly wherever the pair sits in a straight run of three samples (second difference ≤ 1e-4 m). That covers levelled road bands, flat or graded. Curved terrain such as crests and hills keeps the Catmull-Rom shape.

**Regression test:**
- The flat band (0, 0, 0, 2) now gives a midpoint of 0. Before the fix it was -0.125.
- The graded band (0, 1, 2, 10) gives 1.5. Before the fix it was 1.0625.
- A crest keeps its cubic value.

**Gate before and after (enforced):**
- PASS both times.
- All subdiv-2 metrics move by less than 1%. The largest change is bank 25 m/s, dir -1, suspensionJitterM: 0.001619 → 0.00163.
- Every subdiv-2 contactLossTicks value stays at 0.

The obvious fix, clamping every value to [min, max], was tried first and rejected. It flattened the crests and failed the gate (subdiv 2 hill 25 dir +1 and climb 25 dir +1: contactLossTicks 1 > 0).

**Status:** fixed: requires human verification. Driving on terrain feel-test, juliette-ga and demo-hills should feel the same.

### WR-07: Save is not atomic across bin/json; concurrent PUTs share one temp file

**Files modified:** `tools/terrain-editor/vite-plugin.ts`, `tools/terrain-editor/editor.ts`, `tests/terrain-plugin.test.ts`
**Commit:** b4bc624
**Applied fix:**
- `writeAtomic` is exported. It names each temp file `<file>.<pid>.<randomUUID>.tmp` and queues writes to the same file within the process.
  - A unique temp name alone was not enough: on Windows, concurrent renames onto the same target still failed with EPERM.
- The editor encodes both halves before it writes either one, and PUTs the sidecar first. The CR-01 guard already ensures only one save runs at a time.

**Regression test:** 8 concurrent writes to one file. All succeed, the published body is intact and no temp files are left. Before the fix: ENOENT.

### WR-08: Sidecar parser does not range-check crest, ramp or building numbers

**Files modified:** `src/core/terrain-format.ts`, `tests/terrain-format.test.ts`
**Commit:** 2e7ae98
**Applied fix:** the parser now enforces:

| Field | Accepted range |
|---|---|
| ramp `angleDeg` | 0 < value < 90 |
| ramp `widthM` | > 0 |
| ramp `footRadiusM` | >= 0 |
| ramp length | finite and <= `MAX_AREA_SIZE_M` (catches very shallow angles) |
| `heightM` | 0 < value <= 200 |
| `radiusM`, domes | (0, `MAX_AREA_SIZE_M`] |
| `radiusM`, ramps | [0, `MAX_AREA_SIZE_M`] (unused for ramps) |
| building `halfExtents` | each axis > 0 |

Crest ids must also be unique. All four committed terrain sidecars still parse.

**Regression test:** each bad value is rejected with an error that names the field.
