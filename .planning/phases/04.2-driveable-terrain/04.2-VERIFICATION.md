# Phase 04.2: Driveable Terrain Verification Report

**Phase Goal:** A hand-sculpted, hand-painted hilly area that a car can drive over smoothly, built with a small 3D sculpt page. Terrain is the single source of truth: a height grid plus a finer surface paint map, with no separate road mesh on the ground. A road brush paints surface, levels heights and records the road graph. The phase absorbs and closes Phase 4.1. The prototype gate runs on feel-test first.

## Verdict in one paragraph

The core goal is met in the code. The binary heightfield and paint map load and drive. Per-wheel surface comes from the paint map. The 3D sculpt page has every D-10 tool, 50-step undo and Drive here. The road brush emits v1 graphs with junctions that the validator, A* pathfinding and the save/load round trip all accept (spot check below). Three maps are migrated with documented differences, Phase 4.1 is closed, and the automated gate still passes at HEAD with `GATE_ENFORCE=1`.

Three plan must_haves fail at HEAD:
- **Plans 06 and 11 interact (one root cause):** migrating feel-test to terrain made the in-game `?gate` course unreachable, and dropped the car shadow and ground probe on feel-test.
- **Plan 14:** the user's demo-hills graph fails the validator (ribbon self-intersection).

All three are small. Each is a good candidate for a fix or an override (suggested below). The code review blockers CR-01 and CR-02 do not defeat any must_have, so they are warnings.

## Gaps Summary

There are two root causes.

**A. The feel-test migration (plan 11) orphaned the plan 06 game wiring.** The `?gate` course, the car shadow and the ground probe are all behind `!isTerrain` checks that are now always false. The fix is small: re-gate them on terrain feel-test, or delete them and record that the route was retired after sign-off. If the user regards the in-game gate as served (the headless gate still guards the numbers), accept it with an override:

```yaml
overrides:
  - must_have: "With ?map=feel-test&gate&debug the user can drive the gate course inside the normal feel-test session"
    reason: "Gate was driven and signed off before migration; headless gate (GATE_ENFORCE=1) still passes at HEAD; in-game route retired with feel-test's move to terrain"
    accepted_by: "<user>"
    accepted_at: "<ISO timestamp>"
```

The shadow/probe loss is visible to the player on feel-test and should be fixed rather than overridden.

**B. The demo map's graph fails the validator** (3 ribbon self-intersections on one tight fold), because the editor saves graphs with hard failures. Terrain maps build no ribbons at runtime, and the graph parses, routes and pathfinds. So this is a reasonable override candidate if the user does not want to repaint the bend. The editor save guard is already a recorded follow-up.
