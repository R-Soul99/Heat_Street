  <behavior>
    - Round trip: encode then decode a 7x5-cell grid with heights in -3.27..+12.5 m and a 30x22 paint map gives heights equal to round(h / 0.01) * 0.01 (abs diff <= 0.005) and paint bytes identical, cellSizeM/origin/scale/mpp identical, colliderSubdiv identical.
    - A grid of all-zero heights decodes to exactly 0 (Object.is(h, 0) for every vertex).
    - Golden bytes: encoding a fixed 1x1-cell grid (heights [0, 0.01, -0.01, 1.0]) with a 2x2 paint map and paintEncoding 0 (raw) produces a byte array whose first 4 bytes are ASCII "HSTR", bytes 4-5 are formatVersion 1 (LE), and whose full content equals a golden Uint8Array literal committed in the test.
    - paintEncoding 1 (deflate-raw via CompressionStream) round-trips and produces fewer bytes than raw for a uniform 1000x1000 paint map.
    - Decoding rejects with an Error whose message contains "unknown format version 99" when the header version is 99.
    - Decoding a version below current invokes the injected migration for that version (test passes a fake migrations table mapping 0 -> function upgrading to 1).
    - Decoding rejects truncated input (every prefix length 0..headerBytes and one byte short of full) with a named error, and rejects a header whose (rows+1)*(cols+1) > 4,000,000 or paint pixel count > 2^27 BEFORE allocating.
    - Decoding rejects a deflated paint section that inflates to more bytes than paintWidth*paintHeight (inflation stops at the cap).
    - Decoding rejects a surface-enum header listing a name not in SURFACE_TYPES; a header listing the same names in a different order is decoded by remapping indices to current SURFACE_TYPES order.
  </behavior>
  <action>
Create `src/core/terrain-format.ts` (pure core, `.ts` specifiers, DataView little-endian, no Float32Array views over unaligned offsets — pad each section to a 4-byte multiple).
Header layout v1 (document in code and in the schema doc in Task 2): magic `HSTR` (4 bytes), formatVersion u16, headerBytes u16, rows u32, cols u32, cellSizeM f32, originX f64, originZ f64, heightOffsetSteps i32, heightScaleM f32 (default 0.01, Pitfall 3), colliderSubdiv u8, paintEncoding u8 (0 raw, 1 deflate-raw), reserved u16, paintWidth u32, paintHeight u32, paintMetresPerPixel f32, paintOriginX f64, paintOriginZ f64, surfaceCount u8 then for each surface a u8 length + ASCII name, padding to 4 bytes; then Uint16 heights[(rows+1)*(cols+1)] in the existing `row + col * (rows + 1)` order, padded to 4; then the paint section (raw bytes, or u32 compressedLength + deflate-raw bytes).
Height quantisation: dequantised height = (q + heightOffsetSteps) * heightScaleM computed in float64, written into a fresh Float32Array; encoder picks heightOffsetSteps = floor(minHeight / scale) and throws a RangeError naming the area span if (maxSteps − minSteps) > 65535. This makes any multiple of the scale (including exactly 0) exact (feel-test flatness, D-07).
Export `TERRAIN_MAGIC = "HSTR"`, `TERRAIN_FORMAT_VERSION = 1`, `MAX_TERRAIN_VERTICES = 4_000_000`, `interface TerrainBinary { grid: TerrainGrid; paint: PaintMap; colliderSubdiv: 1 | 2 }`, `encodeTerrainBinary(binary: TerrainBinary, opts?: { paintEncoding?: 0 | 1; heightScaleM?: number }): Promise<Uint8Array>` (default paintEncoding 1), `decodeTerrainBinary(bytes: ArrayBuffer | Uint8Array, sourceLabel: string, migrations?: Readonly<Record<number, (bytes: Uint8Array) => Uint8Array>>): Promise<TerrainBinary>`. Errors always name `sourceLabel` and the offending field. Deflate/inflate use the global `CompressionStream`/`DecompressionStream("deflate-raw")` (available in browsers and Node 24); inflate reads chunks and aborts once the expected length is exceeded. Never retain references into the input buffer — copy into fresh typed arrays (T-04-35 precedent).
  </action>
