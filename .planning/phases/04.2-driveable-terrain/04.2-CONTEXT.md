# Phase 04.2: Driveable Terrain - Context

**Gathered:** 2026-11-01
**Status:** Ready for planning

<domain>
## Phase Boundary

A hand-sculpted, hand-painted hilly area that a car can drive over smoothly, built with a new small 3D sculpt page. Terrain becomes the single source of truth: a height grid plus a finer surface paint map, with no separate road mesh on the ground. A road brush paints surface, levels heights and records the road graph in one stroke. Absorbs and closes Phase 4.1 (flat terrain), whose core idea is reversed.

Full design: `.planning/gsd-brief-driveable-terrain.md` (supersedes "Architecture" items 1-3 of Revision 2 in `claude/map-authoring-plan.md`).

**Hard checkpoint:** a prototype gate on `feel-test` runs first. If it fails, stop before touching the real pipeline.

**Out of scope (stays deferred):** bridges, overpasses, tunnels (elevated ribbon meshes, later phase); the full 3D Map Tools milestone (snap-together/curved road pieces, mesh-ramp gizmo, objects); Newton Poppleford import.

</domain>

<decisions>
## Implementation Decisions

### Prototype gate and terrain limits
- **D-01:** The gate is judged on numbers first, then a human drive. An automated drive test (same family as `feel-dossier` / drive logger) must meet thresholds on a hill, a banked bend and a road climbing a slope: chassis vertical jitter, wheel-contact loss, speed dips at seams, and flat-ground results unchanged. Only then does the user drive it and sign off. Exact threshold values are Claude's discretion (to be set from measured flat-ground baselines).
- **D-02:** Height grid cell size defaults to **3m**, overridable per area (2m for small maps, coarser for big ones); stored in the area file. The surface paint map is finer (0.25-0.5m per pixel).
- **D-03:** One **global** max slope, about **35 degrees**, enforced while sculpting; brushes cannot exceed it. Cliffs and walls are objects, not terrain. The exact value is tuned during the prototype gate.
- **D-04:** Performance target is **60fps against the existing `docs/frame-budget.md`** (16.6ms total, physics <=4ms, render submit <=6ms). Maximum area size is about **2 x 2km** (~440k vertices at 3m). Larger areas (e.g. Newton-size 3.5 x 1.7km, ~660k vertices) are measured and reported, not promised.

### Existing maps
- **D-05:** **Migrate feel-test, grid-test and juliette-ga** to the new terrain format in this phase (the user chose full migration over keeping the ribbon path for them).
- **D-06:** Migration is an **automatic converter** from the compiled map: rasterise the road graph into the paint map, level heights along roads, and keep the graph (ids, edges) as-is so routes and checkpoints still reference the same edges. Repeatable and testable.
- **D-07:** **feel-test keeps identical geometry** (same road layout, jumps, stations; flat heights) so handling logs and `feel-dossier` numbers stay comparable. Medals for juliette-ga and grid-test are **re-recorded from a fresh designer reference run** using the existing re-record support; differences documented.
- **D-08:** `my-map`, `newton-poppleford` and `skidders-and-popp` are **not migrated**. They keep opening via the legacy ribbon loader from the map menu, with no medals or guarantees. The ribbon/collision code is therefore **not deleted** (it is also needed later for bridges).

### Sculpt page
- **D-09:** A **new 3D page** (Three.js, orbit camera, top-down toggle) lives next to `tools/map-editor`, reusing its Vite plugin/save plumbing. The 2D editor stays working for legacy maps and is retired later.
- **D-10:** v1 tools: raise/lower, smooth, flatten, surface paint, road brush, undo/redo, save/load, **drive here**, **plus heightfield stamps (wedge/mound)** for earth ramps and hills. Mesh ramps with a transform gizmo are **not** in this phase.
- **D-11:** Undo is **stroke-based, 50 steps deep**, storing only changed cells, cleared on reload. Area files are **versioned binary** with a format version in a small header: 16-bit heights, paint map, JSON sidecar for graph/objects, so the loader can migrate old files.
- **D-12:** **Drive here** opens the game at the cursor position from the saved file, with no manual compile step. The phase delivers the three migrated maps plus **one small hand-sculpted hilly demo map** to prove the tool.

### Road brush and graph output
- **D-13:** A stroke that crosses or touches an existing road **auto-splits into a junction node**, splitting both edges and blending heights so both roads meet at the same level. A stroke ending in open ground is a dead end.
- **D-14:** The profile comes from **road-class presets plus a width slider** (default width, lanes, surface, speed limit per class). **Banking is automatic from curve radius** with a max-bank setting, off by default on streets.
- **D-15:** An **erase brush removes surface paint and splits/deletes the graph edge**; the levelled terrain stays. Re-painting over an old road replaces it, so no road is ever drawn twice. Undo covers mistakes. Selecting and editing centrelines as splines is out of scope.
- **D-16:** Strokes emit the **existing road-graph v1 schema** (`docs/schemas/road-graph.v1.md`) with **stable edge ids** across re-saves; node `y` comes from terrain height. Validator, parser and ngraph pathfinding/minimap/route code stay unchanged.

### Claude's Discretion
- Threshold values for the prototype gate, set from measured baselines (D-01).
- Final max-slope value near 35 degrees (D-03).
- Physics collider choice for the terrain (Rapier heightfield vs chunked trimesh), chunk size, smoothing and interpolated-normal approach so the raycast car does not jitter, and how surface type is looked up per wheel from the paint map. Not discussed; the research phase decides, guided by the brief and CLAUDE.md (`FIX_INTERNAL_EDGES` for any trimesh, chunked colliders).
- Banking formula and max-bank default (D-14).
- Road-class preset values (D-14).

### Folded Todos
None. Reviewed but not folded (see Deferred).

<code_context>
## Existing Code Insights

### Reusable Assets
- `src/core/heightfield-sample.ts`: bilinear sampler shared by compiler and runtime via a structural `SampleableHeightfield` interface; reuse for terrain height lookup.
- `src/physics/map-scene.ts`: builds the Rapier scene (trimesh road colliders, off-road `ColliderDesc.heightfield`, shoulders, crests); the legacy path that stays for non-migrated maps.
- `src/core/ground-surface.ts`: per-area ground surface lookup (`groundSurfaceForArea`, flat test area flag); starting point for paint-map surface lookup.
- `src/core/crest-geometry.ts` and the authored `ramp` field: existing crest/ramp object model; the brief says existing authored crests use the same object model as new objects.
- `src/core/road-graph.ts` (`parseRoadGraph`) and `tools/map-compiler/graph/*`: graph parser/validator and ngraph usage that must keep working.
- `tools/map-editor/` (`editor.ts`, `model.ts`, `vite-plugin.ts`): 2D editor and its save plumbing.
- `tools/map-compiler/cli.ts`, `tools/map-compiler/synthetic/*` (proving-ground, grid layout, route authoring): generators for feel-test/grid-test and route authoring scripts used by the migration converter.
- `src/debug/map-menu.ts`, `src/core/map-select.ts` (`KNOWN_MAP_IDS`, `MAP_LABELS`): map selection for new terrain maps.
- `src/core/frame-budget.ts` + `docs/frame-budget.md`: mirrored budget the new terrain must be measured against.
- `src/debug/drive-logger.ts`, `npm run feel-dossier`, `src/debug/test-stations.ts`: measurement tools for the prototype gate.

### Established Patterns
- Pure `src/core/` modules (no three/rapier/fs) with tests; rendering in `src/render/`, physics in `src/physics/`.
- Heightfield storage convention: `heights[row + col * (rows + 1)]`, row = Z, col = X, literal metres.
- Compiled areas ship as `public/maps/<id>.{glb,map.json,collision.json,routes.json,medals.json}`, loaded by URL at runtime.
- Build defects fail loudly at compile time; runtime geometry queries degrade gracefully.
- Medal thresholds are fixed percentage bands off a recorded designer reference run, re-recordable.

### Integration Points
- Terrain loader sits beside the legacy map loader; selection by area format.
- Per-wheel surface lookup (`wheelGroundObject`) must resolve from the paint map for terrain maps instead of per-collider surface.
- Graph feeds minimap, checkpoint/route placement, AI pathfinding (Phase 5/7), so edge ids must stay stable.
- Medal files and routes reference graph edges, so the converter must preserve ids.

</code_context>

<specifics>
## Specific Ideas

- Populous-style terrain sculpting: neighbours follow on a falloff, slope limit prevents spikes.
- "Hills you can drive up and down, not scenery." Mostly hand-built maps (invented towns, race tracks); real areas are a bonus.
- Smoothing and interpolated normals are required so the car does not jitter on hand-sculpted ground.
- Prototype course on `feel-test`: a hill, a banked bend and a road climbing a slope.
- Feel-test is the measured baseline for all handling logs; its geometry must not change.

</specifics>

<deferred>
## Deferred Ideas

- Bridges, overpasses, tunnels as elevated ribbon meshes, and how bridge ends meet the ground (ramps up to deck vs abutment carve) - later phase.
- Full 3D Map Tools milestone: snap-together and curved road pieces, parametric mesh ramps with transform gizmo, objects with "on ground"/"fixed" height modes, spline-editable road centrelines.
- Newton Poppleford import (last and optional); migration of `my-map`, `newton-poppleford`, `skidders-and-popp` to terrain.
- Retiring the 2D map editor and eventually the legacy ribbon loader for non-bridge roads.
- Restoring original terrain when a road is erased (per-stroke before-heights).
- Unlimited persisted undo history.
- Number of hand-built maps and race types beyond the one demo map: decide when planning Phase 5+ content.

- "Author a shorter, tighter course on the Juliette map" - course authoring on a map being migrated here; revisit after juliette-ga migration and medal re-record.
