## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01:** Gate is judged on numbers first, then a human drive. Automated drive test (same family as `feel-dossier` / drive logger) must meet thresholds on a hill, a banked bend and a road climbing a slope: chassis vertical jitter, wheel-contact loss, speed dips at seams, flat-ground results unchanged. Only then the user drives and signs off. Exact thresholds are Claude's discretion (set from measured flat-ground baselines).
- **D-02:** Height grid cell size defaults to **3m**, overridable per area (2m small maps, coarser big ones); stored in the area file. Surface paint map is finer (0.25-0.5m per pixel).
- **D-03:** One **global** max slope, about **35 degrees**, enforced while sculpting; brushes cannot exceed it. Cliffs/walls are objects, not terrain. Exact value tuned during the prototype gate.
- **D-04:** 60fps against `docs/frame-budget.md` (16.6ms total, physics <=4ms, render submit <=6ms). Max area ~2 x 2km (~440k vertices at 3m). Larger (Newton 3.5 x 1.7km, ~660k vertices) measured and reported, not promised.
- **D-05:** Migrate **feel-test, grid-test, juliette-ga** to the new terrain format.
- **D-06:** Migration is an **automatic converter** from the compiled map: rasterise road graph into paint map, level heights along roads, keep graph (ids, edges) as-is so routes/checkpoints still reference the same edges. Repeatable and testable.
- **D-07:** **feel-test keeps identical geometry** (same road layout, jumps, stations; flat heights) so handling logs and `feel-dossier` numbers stay comparable. Medals for juliette-ga and grid-test re-recorded from a fresh designer reference run using existing re-record support; differences documented.
- **D-08:** `my-map`, `newton-poppleford`, `skidders-and-popp` NOT migrated; they open via the legacy ribbon loader from the map menu, no medals/guarantees. Ribbon/collision code is NOT deleted.
- **D-09:** New 3D page (Three.js, orbit camera, top-down toggle) next to `tools/map-editor`, reusing its Vite plugin/save plumbing. 2D editor stays working for legacy maps.
- **D-10:** v1 tools: raise/lower, smooth, flatten, surface paint, road brush, undo/redo, save/load, **drive here**, plus heightfield stamps (wedge/mound). Mesh ramps with gizmo NOT in this phase.
- **D-11:** Undo is stroke-based, 50 steps, stores only changed cells, cleared on reload. Area files are **versioned binary** with a small header carrying format version: 16-bit heights, paint map, JSON sidecar for graph/objects, loader can migrate old files.
- **D-12:** **Drive here** opens the game at the cursor position from the saved file, no manual compile step. Deliverable: three migrated maps plus **one small hand-sculpted hilly demo map**.
- **D-13:** Stroke crossing/touching an existing road auto-splits into a junction node, splitting both edges and blending heights so both meet at the same level. Stroke ending in open ground is a dead end.
- **D-14:** Profile from road-class presets plus width slider (default width, lanes, surface, speed limit per class). Banking automatic from curve radius with a max-bank setting, off by default on streets.
- **D-15:** Erase brush removes surface paint and splits/deletes the graph edge; levelled terrain stays. Re-painting over an old road replaces it. Undo covers mistakes. Spline editing of centrelines out of scope.
- **D-16:** Strokes emit the **existing road-graph v1 schema** (`docs/schemas/road-graph.v1.md`) with **stable edge ids** across re-saves; node `y` from terrain height. Validator, parser, ngraph pathfinding/minimap/route code unchanged.

## Summary

The existing runtime already contains most of the primitives needed. `src/physics/map-scene.ts` builds an off-road `ColliderDesc.heightfield` (one collider, `heights[row + col*(rows+1)]`, literal metres, translation at grid centre, `scale.y = 1`) and `src/core/heightfield-sample.ts` is a shared bilinear sampler. The new terrain makes that heightfield the ONLY ground, so the 5.09 m road/terrain disagreement that killed hills in 04.1 cannot occur: roads are painted into the paint map and levelled into the same heights the collider uses.

Three findings change the plan versus the naive reading of CONTEXT:

1. **Per-wheel surface lookup cannot use `SurfaceMap` (collider handle to surface).** `src/physics/vehicle.ts:485-486` calls `surfaces.map.lookup(ground?.handle)`; a single terrain collider has one handle. The lookup must become position based: read `vc.wheelContactPoint(i, scratch)` (allocation-free with `target`) and sample the paint map. Add an optional `positionLookup` to `SurfaceMap`/`SurfaceContext` (or a sibling), used only when the wheel's ground collider is the terrain collider. The legacy path stays untouched.
2. **Rapier 0.20.0 `ColliderDesc.heightfield(...)` takes a `HeightFieldFlags` argument and `HeightFieldFlags.FIX_INTERNAL_EDGES = 1` exists** [VERIFIED: node_modules/@dimforge/rapier3d/geometry/shape.d.ts]. The project currently builds its heightfield WITHOUT it. Use it for the terrain (the chassis collider contacts the ground; the wheels themselves are rays and are unaffected by the flag). CLAUDE.md's trimesh rule is thereby satisfied equivalently.
3. **The physics surface is piecewise-linear triangles, not bilinear.** `sampleHeightfieldBilinear` returns a bilinear blend, which differs from the two-triangle surface Rapier collides with whenever a quad is warped (every sloped/banked cell). Anything that must sit ON the physics surface (spawn height, checkpoint pose, graph node `y`, objects "on ground", minimap) needs a triangle-consistent sampler. Write one in `src/core/` and confirm the diagonal direction empirically against a Rapier raycast in a Wave 0 test.

**Primary recommendation:** One Rapier heightfield collider (with `FIX_INTERNAL_EDGES`) built from a lightly smoothed copy of the authored heights, rendered as chunked `THREE.Mesh` with the same triangulation and analytic (central-difference) vertex normals, a Uint8 surface-index paint map sampled by wheel contact point, and a Wave 0 headless-Rapier prototype gate on `feel-test` that measures jitter before any pipeline work. No new npm dependencies are needed.

Heightfield storage convention stays `heights[row + col*(rows+1)]`, row = Z, col = X [CITED: src/core/heightfield-sample.ts]. Reuse it everywhere so the existing `SampleableHeightfield` interface still applies.

### Collider choice (decision): single Rapier heightfield, not chunked trimesh
- A regular grid is exactly what `ColliderDesc.heightfield` is for. Memory is the heights array only (445k floats = 1.8 MB at 2x2km/3m); a trimesh would store ~890k triangles plus a BVH, and `FIX_INTERNAL_EDGES` on trimesh adds build cost [ASSUMED: trimesh build cost, not measured].
- The project already uses this path in `map-scene.ts`, so construction/axis conventions are proven.
- Chunking is not needed for physics at 2x2km; Rapier's heightfield uses its own spatial structure internally [ASSUMED]. Measure physics ms in the gate; only if the 4ms budget is threatened, split into per-chunk heightfield colliders (each chunk shares its boundary row/col so there is no seam).
- Pass `HeightFieldFlags.FIX_INTERNAL_EDGES` [VERIFIED: shape.d.ts]. Note: raycast wheels use ray hits, so jitter from wheels comes from triangle normals/heights, not from this flag; the flag protects the chassis collider and any loose bodies.
- Heights given to Rapier must be the dequantised stored values (not the editor's float working copy) so physics, render and sampler agree exactly.

### Smoothness (the jitter problem), prescriptive
The car is a raycast vehicle: each wheel casts a ray and gets a hit point plus the hit triangle's normal. On a 3m grid, adjacent triangles differ in slope, so wheel normals step as a wheel crosses edges.
1. **Author-time smoothing**: after every brush stroke run a 3x3 weighted relax limited to touched cells + 1-cell border (keeps undo diffs small). The road brush levels a band wider than the paint width (half-width + falloff) so a road never lies on a cell edge that straddles a level road and a steep shoulder.
2. **Slope limit** (D-03): enforce max neighbour delta `tan(maxSlope) * cell` (axis neighbours) and `* sqrt(2)` for diagonals using a two-pass (forward then backward raster sweep) relaxation, O(n) for the affected window, run on the changed-cell bounding box expanded by `ceil(maxDelta / allowedDelta)` cells. Road levelling has priority: the road band is a constraint that the limiter adjusts AROUND (the embankment falloff must be at least `deltaH / tan(slope)` metres wide, else the limiter will bend the road; detect and report).
3. **Collider resolution knob**: if gate numbers show wheel-normal chatter, build the physics heightfield from a 2x bicubic (Catmull-Rom) upsample of the authored grid (1.5m triangles), with the render mesh using the identical upsampled grid. Keep this behind an `colliderSubdiv` area option (default 1) so the cost is only paid if the gate needs it. This is the main mitigation if smoothing is insufficient.
4. **Do not rely on interpolated normals for physics**: Rapier gives per-triangle normals. "Interpolated normals" apply to rendering (and the camera/car-shadow ground normal if added). For physics the equivalent is point 1-3 (smaller, smoother triangles).
5. Whether Rapier's raycast vehicle applies suspension force along the hit normal or along the wheel ray is not confirmed here [ASSUMED]; read `ray_cast_vehicle_controller` behaviour empirically in the Wave 0 test by logging `wheelSuspensionForce(i)` crossing a seam. Do not design around either belief before measuring.

### Pattern: triangle-consistent sampler
**What:** `sampleTerrainHeight(grid, x, z)` splits each quad by the same diagonal Rapier uses, barycentric interpolate. Also `terrainNormalAt` (flat triangle normal for physics-equivalence; central-difference for render).
**When:** spawn/respawn placement, checkpoint `y`, graph node `y`, "on ground" objects, crest rim sampling (crest-geometry currently calls the bilinear sampler: `map-scene.ts:261-269`), minimap shading.
**Verify:** Wave 0 test builds a tiny Rapier world with a random 4x4 heightfield and compares `world.castRay` height to the sampler at 200 random points, tolerance 1e-3 m. This also reveals which diagonal Rapier uses (do not hard-code from memory).

### Per-wheel surface lookup
- Keep the `SurfaceMap` collider-handle path for legacy maps and object colliders (building, crest domes).
- Add `SurfaceMap.registerTerrain(handle, paintSampler)` or a new `SurfaceContext.paint?: { colliderHandle: number; surfaceAt(x:number,z:number): SurfaceType }`. In `vehicle.ts` at the grip loop: if `ground?.handle === paint.colliderHandle`, call `vc.wheelContactPoint(i, scratchVec)` and `paint.surfaceAt(p.x, p.z)`; else existing lookup. Zero per-tick allocation (reuse the scratch vector, mirrors `transform-cache.ts` discipline).
- `surfaceAt` is nearest-pixel on a `Uint8Array` of `SURFACE_TYPES` indices. The closed six-value enum in `src/core/surface-types.ts` (`tarmac | gravel | dirt_road | grass | sand | mud`) fits in 3 bits; use a full byte for simplicity and leave room for future values. Index MUST be derived from `SURFACE_TYPES` order; store the enum order in the file header to survive reordering.
- Audio/FX consumers (`surface-audio.ts`, `surface-fx.ts`) take the per-wheel surface result from the vehicle (`wheelSurfaces[i]`); confirm they do not depend on `roadMeshes`/`roadSurfaces` arrays from `map-view.ts` for terrain maps (fx currently accepts parallel mesh/surface arrays, `map-view.ts` header). Check in plan: the terrain view may expose an empty `roadMeshes` list.

### Render
- Chunks of 64x64 cells (192m at 3m): a 2km map is ~11x11 = 121 chunks, each 65x65 = 4,225 vertices, ~8k triangles. Frustum culling per chunk is free in three. Total 2x2km terrain is ~890k triangles if all visible; the helicopter camera sees a fraction. Current live target is `Triangles < 45,000` and `Draw calls < 16` (`docs/frame-budget.md`); the terrain will push both and the budget doc + `src/core/frame-budget.ts` mirror must be revised together (test `tests/frame-budget.test.ts` enforces they match). Plan a task for this, with a real measurement, as prior phases did.
- Optional LOD: lower-density index buffers for far chunks (every 2nd/4th vertex) built once; skip LOD unless the gate shows triangle cost. Do not add geometry-clipmap complexity.
- Paint map texture: per-chunk `THREE.DataTexture` (RGBA8, linear filter, colours from a palette per surface) gives soft edges cheaply with `MeshStandardMaterial.map`; no custom shader (CLAUDE.md prefers stock materials; WebGL renderer). Physics reads the Uint8 index map, never the colour texture.
- Size reality check: 2km at 0.5 m/px is 4000x4000 = 16M pixels = 16 MB index + 64 MB if every chunk is colour RGBA8. At 0.25 m/px it is 4x worse. Therefore: default paint resolution 0.5 m/px, cap per-area, build chunk textures lazily (only chunks near the camera), and measure VRAM. This is a flagged risk (see Pitfalls) because D-02 permits 0.25.
- Geometry shares triangulation with the collider; compute vertex normals via central differences on the height grid (not `computeVertexNormals` per chunk, which creates seams at chunk borders).
- Add a skirt-free chunk border by sampling the neighbour's heights for border normals (avoid visible seams).

### Binary format (D-11)
Header (little-endian): magic `HSTR`, formatVersion u16, headerBytes u16, rows u32, cols u32, cellSizeM f32, originX f32, originZ f32, heightOffsetM f32, heightScaleM f32 (e.g. 0.01 => 655 m range), paintWidth u32, paintHeight u32, paintMetresPerPixel f32, surfaceEnum (count u8 + names, so reordering survives), then `Uint16 heights[(rows+1)*(cols+1)]` in the existing storage order, then `Uint8 paint[paintW*paintH]`. JSON sidecar `<id>.terrain.json`: `{ formatVersion, areaId, graph (road-graph v1 verbatim), objects: [crests/stations...], nextEdgeId, buildings }`. Decoder dispatches on `formatVersion` through `migrate(v)` functions. Round-trip and golden-bytes tests required. Avoid `Float32Array` over unaligned offsets: pad sections to 4-byte multiples.

### Road brush to graph (D-13..D-16)
- Stroke input: sampled cursor points on terrain; resample at ~cell/2 spacing, smooth (Chaikin 1-2 iterations), simplify (RDP, tolerance ~0.25 m) to polyline points `[x, y, z]` with `y` from the levelled terrain via the triangle sampler.
- Levelling: for each paint-map-resolution stamp along the centreline set heights in cells within `halfWidth + shoulder`, blending to the existing terrain by smoothstep falloff; centreline height profile is itself a smoothed low-pass of the sampled terrain heights along the stroke (limit longitudinal grade to the slope cap; this prevents the road following every bump).
- Banking: `bank = clamp(atan(v^2 / (g*R)) * k, 0, maxBank)` using a design speed per road class and local radius `R` from three-point curvature on the smoothed polyline; add crossfall offset `lateral * tan(bank)` to the levelled height. Default `maxBank` 8 degrees (ASSUMED starting value, tune in the gate), `0` for residential/street presets. Smooth bank along the stroke so it ramps in/out (no step).
- Graph: stroke becomes one edge (or several split edges) with `lengthM` recomputed from points; surface from the preset; `roadClass`, `lanes`, `widthM`, `oneway`, `speedLimitKph`, `bridge:false`, `tunnel:false`, `layer:0`, `osmWayId` dummy/0 (check parser/validator requirements in `src/core/road-graph.ts` and `tools/map-compiler/validate/*`; emit what they require).
- Junctions (D-13): for each new polyline segment test distance to existing edge polylines (`<= max(halfWidths)`); on hit insert a node at the nearest point, split the existing edge into two (new ids from `nextEdgeId`; keep the original id for the first half so routes referencing it still start valid; document that a split edge's second half gets a new id and route/medal files referencing a split edge need a check), blend heights to the shared node height, set `junction:true`. Node ids stay dense `0..n-1` (schema); avoid renumbering existing nodes (append new ones, compact only via an explicit converter step that remaps routes).
- Erase (D-15): clear paint in the radius; for graph edges whose polyline falls within the radius, split at the radius boundary and delete the interior segment; dead-end nodes left behind with degree 0 are removed only if no route references them.
- Stable ids: persist `nextEdgeId` and `nextNodeId` counters in the sidecar; never reuse ids.

### Converter (D-06/D-07)
Inputs per area: `<id>.map.json` (graph), `<id>.collision.json` (heightfield, buildings), `<id>.routes.json`, medals, stations, crests (`src/core/crest-geometry.ts` `FEEL_TEST_CRESTS` etc.). Steps: (1) allocate terrain grid over `bounds` at the area's cellSize (feel-test: preserve the existing flat height value exactly); (2) rasterise each edge polyline with `widthM` into the paint map using that edge's `surface`, later edges do not overwrite earlier except by class priority, junction polygons likewise (road-geometry gives the junction footprints, `src/core/road-geometry.ts`); (3) level cells under each road to the edge point heights (juliette-ga: check whether graph `y` is 0 post 04.1, flat, in which case levelling is a no-op); (4) copy graph verbatim (ids, edges) into the sidecar; (5) carry buildings and crest/ramp objects; (6) fixture-based test: every edge midpoint, after conversion, reads its edge's surface from the paint map and a terrain height equal to the edge `y` within tolerance; every route checkpoint resolves. Feel-test must keep identical geometry: assert wheel-ground height is identical (flat), same graph hash.

Caution for feel-test: its jumps are the authored crest domes (`FEEL_TEST_CRESTS`, built as trimesh over the heightfield with rim sampled from `sampleHeightfieldBilinear`, `map-scene.ts:261-280`). Keep crests as objects with the same trimesh builder over the new grid; this is why "identical geometry" is feasible. Also feel-test ground is tarmac everywhere (`isFlatTestArea`, `groundSurfaceForArea`); the converter must fill the paint map with tarmac (not grass) for flat test areas, or handling logs diverge.

### Sculpt tool architecture
- Separate Vite entry like `tools/map-editor/index.html`; no framework; WebGL canvas + side panel per UI-SPEC.
- Terrain mesh for editing reuses `terrain-view.ts` chunks with dirty-chunk rebuild (only chunks overlapped by the brush bbox).
- Brush ops are pure functions in core returning a diff `{ indices, before, after }`; undo stack stores diffs (D-11). Pointer-up commits one stroke.
- Mouse picking: `THREE.Raycaster` against chunk meshes is O(triangles) per hit test; instead do a grid march (ray vs heightfield DDA) in core: cheaper and testable. Use it for the brush cursor.
- Save plumbing: copy `vite-plugin.ts` pattern: dev-only (`apply: "serve"`), id regex `^[a-z0-9-]+$`, fixed output dir `public/maps/`, size caps on bodies (terrain.bin max e.g. 64 MB), `GET/PUT /__terrain/<id>/<bin|json>`. Register the plugin next to `mapEditorApi()` in `vite.config.ts`.
- Drive here: save first, then `window.open('/?map=<id>&at=x,z&debug')`. Add the id to `KNOWN_MAP_IDS`/`MAP_LABELS` (allowlist stays the security gate). For hand-made ids created in the editor, the allowlist cannot know them at build time: the dev plugin can expose `GET /__terrain/maps` and `resolveMapId` accepts ids from that list ONLY in dev builds (`import.meta.env.DEV`), still regex-validated. Alternative to keep scope small: v1 reserves the fixed id `playground`/`demo-hills` in the allowlist. Recommend the latter.
- `at=x,z` parameter must be parsed with numeric validation (finite, within bounds); place the car at terrain height + clearance with heading along nearest road edge.

### Anti-Patterns to Avoid
- Keeping bilinear for physics-adjacent placement (see triangle sampler).
- Per-chunk `computeVertexNormals` (visible seams) and per-chunk separate colliders without shared border rows.
- One giant paint texture (>4096 px side, mobile limit irrelevant but VRAM large).
- Reusing `ColliderHandle -> SurfaceType` for the terrain.
- Mutating `dt` anywhere; sculpt page's "drive here" must still use the game's fixed-step loop.
- Renumbering graph node/edge ids on save.
- Running the slope limiter globally on every stroke (O(map)); window it.

## Common Pitfalls

### Pitfall 1: Paint-map surface at the wheel is the wrong pixel
Wheel contact point vs wheel centre vs chassis; the contact point from the ray hit is correct. Use `wheelContactPoint`, handle `null` (airborne) by keeping the previous surface (as legacy does via `undefined`).

### Pitfall 2: Coarse grid cannot hold a banked road
At 3m cells a 7m road spans 2-3 cells; crossfall of 8 degrees is ~0.4m across a cell, ok, but road edge dropoff to a steep shoulder can exceed the slope cap. Level a band of `halfWidth + max(2 cells)` and ramp out gently; assert in tests that no wheel-width sample across a road deviates from the planned crossfall by more than a threshold.

### Pitfall 3: Quantisation steps
16-bit heights at 0.01 m scale are fine; at coarse scale (0.1) steps cause visible terracing. Pick 0.01 default; header carries scale.

### Pitfall 4: Slope limiter vs road constraint fights
Process: stroke applies, limiter runs, may lift the road. Make road cells fixed (masked) during limiter pass, then verify post-condition and surface an editor warning.

### Pitfall 5: Chunk seams (render and physics)
Shared border rows and cross-chunk normal sampling; test by comparing duplicated border vertices.

### Pitfall 6: Rapier heightfield rows/cols off-by-one
`nrows`/`ncols` are CELL counts; the heights array has `(nrows+1)*(ncols+1)` entries; `scale` is the total extent not the per-cell size [CITED: map-scene.ts and heightfield.ts comments]. Wrong cellSize (3m vs total) silently stretches the world. Test with a raycast.

### Pitfall 7: Vite/vitest asset path for binaries
`assetsInlineLimit: 0` is already set; load area binaries by URL from `public/` with `fetch(...).arrayBuffer()`. Do not `import` them.

### Pitfall 8: Saved tuning in localStorage hides new defaults
(User memory note.) Any gate tuning change to defaults must be tested with cleared localStorage, otherwise gate numbers vary between machines. Run automated gate in node (no localStorage).

### Pitfall 9: Flat-ground regression via frictions
Heightfield `.setFriction(ROAD_FRICTION)` is applied in the legacy path; replicate exactly in the terrain collider or flat feel-dossier numbers shift.

### Pitfall 10: Medal references recorded on the old ground
AI pace note (`.planning/debug/ai-pace-and-handbrake-feel.md`): re-recorded designer reference runs must be done with the same inputs/driver; document differences.

### Pitfall 11: Terrain triangle budget
See Render. 45k triangle target in the doc is for the old scene; update with measurement, not guess.

### Per-wheel surface from paint map (allocation-free)
```typescript
// Pattern: reuse a scratch vector; ground handle check decides which path
const ground = vc.wheelGroundObject(i);
let surface: SurfaceType;
if (paint !== undefined && ground?.handle === paint.colliderHandle) {
  const p = vc.wheelContactPoint(i, scratch);
  surface = p === null ? lastSurface[i] : paint.surfaceAt(p.x, p.z);
} else {
  surface = surfaces.map.lookup(ground?.handle);
}
```

## Security Domain

Dev-only tool plus a static-asset loader; no auth or network service shipped. ASVS applicability:

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2/V3 Auth/Session | no | dev plugin is `apply: "serve"` only, localhost |
| V4 Access Control | yes (dev) | plugin restricted to dev server; fixed output directory |
| V5 Input Validation | yes | area-id regex `^[a-z0-9-]+$`; allowlisted map ids in `resolveMapId`; numeric validation of `at=x,z`; binary decoder bounds-checks header counts against byte length before allocating (reject rows/cols giving > e.g. 4M vertices); sidecar parsed field-by-field like `parseRoadGraph`/`parseMapCollision` (no spread, no `__proto__`) |
| V6 Cryptography | no | — |

| Threat | STRIDE | Mitigation |
|--------|--------|-----------|
| Path traversal in save endpoint | Tampering | regex id + `path.join` into fixed dir + verify resolved path prefix |
| Malicious/corrupt area file causing huge allocation | DoS | header size caps, byte-length equality check |
| Prototype pollution via sidecar JSON | Tampering | field-by-field reconstruction |
| Request body flood on PUT | DoS | body size cap in `readBody` (existing helper has none; add) |
