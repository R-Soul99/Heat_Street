<objective>
Open the `tools/` tier so a Node-only map compiler can exist at all, and land the two contracts
every later plan in this phase writes against: the `RoadGraph` shape (shared by the compiler and
the browser runtime) and the OSM-to-game surface mapping.

Purpose: every later plan either produces or consumes a `RoadGraph`. Defining it once, in
`src/core/`, is what makes SC3's "collision geometry, nav graph and route placement all derive
from the same road graph" literal rather than aspirational. The three mechanical gates in Task 1
(`tsconfig` include, the Google grep scope, exact-pinned deps) are prerequisites for any of the
new code being type-checked or policed at all.

Output: a runnable `npm run compile-map` entry point, a confirmed area config, a hostile-blob
`RoadGraph` parser, and the surface mapping table with a doc-parity test.

MVP-slice increment: after this plan, a developer can run the map-compiler command by name and
get a real, named answer about the target area — the compiler exists as a thing you invoke,
not a directory of modules.
</objective>

<plan_decisions>
Decisions this plan locks, with reasoning, so later plans do not relitigate them:

- **D-P1 — `RoadGraph` types and its parser live in `src/core/road-graph.ts`, not in `tools/`.**
  Both tiers need the shape; `src/core/` is the project's existing pure tier (no engine, no DOM,
  no wall clock, mechanically policed by `tests/layering.test.ts`), and `tools/` importing `src/`
  is fine while the reverse is not. This deviates from 04-RESEARCH.md's "Recommended Project
  Structure", which implied a compiler-local type — deliberate, for single-source-of-truth.
- **D-P2 — the parser is hand-rolled, not `zod`.** 04-RESEARCH.md's Security Domain recommends
  zod for V5 load-time validation. The project already has three hand-rolled hostile-blob parsers
  (`parseSavedTuning`, `parseSavedSurfaceProfiles`, `parseSavedCameraTuning`) and zero runtime
  validation dependencies. Matching that precedent costs nothing and adds no supply-chain surface.
- **D-P3 — `parseRoadGraph` THROWS, it does not default.** The `parseSaved*` family returns
  `null`/defaults because tuning has a safe default. A map does not: a half-parsed map is the
  exact "invisible until a medal time is inexplicable" failure mode the schema's design decision
  4 exists to prevent.
- **D-P4 — new packages land as devDependencies with exact pins.** `ngraph.graph`, `ngraph.path`
  and `geotiff` are used only by the offline compiler in this phase. Exact pins (no `^`/`~`) per
  ADR 0001's Consequences section.
- **D-P5 — `osmtogeojson` is NOT installed.** 04-RESEARCH.md's Standard Stack lists it for
  Overpass-JSON-to-GeoJSON conversion, but GeoJSON discards OSM node identity, and shared node
  ids are exactly what junction detection needs (plan 04-04). Converting to GeoJSON would
  destroy the topology this compiler exists to recover. This also retires 04-RESEARCH.md's Open
  Question 4 (whether to pin its `3.0.0-beta.5` "latest" tag) — there is nothing to pin.
</plan_decisions>
