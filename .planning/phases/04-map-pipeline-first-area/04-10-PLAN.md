<objective>
Close the two remaining gaps between "the roads are drivable" and "the area is shippable": solid
ground everywhere off the road network, and the attribution SC4 requires actually visible in the
running game.

Purpose: 04-RESEARCH.md's Open Question 3 asked whether the space between roads needs to be solid
at all. It does — a road-only collision surface means the car falls out of the world the first
time a player clips a corner, which is not a hypothetical for a game whose core value is "big
slides". SC4 has two halves and only the negative half (no Google data) has been enforced so far;
the positive half (the credit appears) needs something on screen.

Output: DEM-derived off-road ground in both artifacts, a credit line in the HUD, and a frame
budget that describes the real scene.

MVP-slice increment: the player can leave the road without the world ending, and the game shows
whose data it is built from.
</objective>

<plan_decisions>
- **D-P28 — 04-RESEARCH.md's Open Question 3 is adopted as recommended, on the planner's
  authority.** A DEM-derived heightfield covering the full bounding box, uniformly `grass`,
  sitting beneath the road ribbons, is the answer. Reasoning taken directly from the research: the
  DEM is already fetched, it prevents the fall-through-the-world failure mode, and per-`landuse`
  surface variety can be added later without revisiting this architecture. This was not put to the
  user because it touches neither licensing nor the locked schema, and the alternative (a road-only
  world with a void between) is not defensible against SC1's "drive every road" with a car that
  slides.
- **D-P29 — the heightfield grid is 128x128 and sits 0.35 m below the smoothed road surface.** The
  road ribbons are built from SMOOTHED elevation while the heightfield samples the raw DEM, so the
  two can disagree by several tens of centimetres; sinking the ground guarantees the road ribbon
  always wins the contact and a wheel never catches on terrain poking through the tarmac. 128x128
  over a ~2.9 km box is about 23 m spacing — coarse, deliberately: this is a safety net and a
  backdrop, not a driving surface. Phase 8's off-road evasion is where refining it earns its cost.
- **D-P30 — the attribution appears as an always-on HUD line, not behind a menu.** There is no
  menu or credits screen in the project yet (Phase 5 owns screens). ADR 0001 records that OSMF
  guidelines permit attribution "on the credits page, in the menu, or in another suitable
  location", and an always-visible corner line is unambiguously compliant. A future credits screen
  can consume the same `attribution` block.
</plan_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `heights` array in the sidecar -> Rapier heightfield | A large numeric array from a static file becomes physics geometry |
| `attribution` block -> DOM | Text from a static file is rendered into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-35 | Tampering | heightfield array length or contents | mitigate | `parseMapCollision` asserts the array length equals `(rows + 1) * (cols + 1)` naming both values, copies element-wise into a fresh `Float32Array`, and rejects non-finite values and anything outside -500 to 9000 m — a malformed grid fails at load rather than producing NaN terrain |
| T-04-33 | Tampering | attribution text rendered into the DOM | mitigate | `textContent` only, asserted by grep; the string comes from this project's own build output, and even so no markup path exists |
| T-04-36 | Tampering | attribution silently hardcoded and drifting from the data | mitigate | A test reads `src/hud/map-credit.ts` through `?raw` and asserts it contains no literal `OpenStreetMap`, so the credit can only ever come from the loaded artifact — the same mechanical-guard idiom `tests/no-google-pipeline.test.ts` established |
| T-04-19 | Denial of Service | heightfield grid size | mitigate | Fixed at 128x128 (16641 floats, about 65 KB as binary, a few hundred KB as JSON) regardless of area extent; the resolution constant is exported and commented rather than derived from the bbox |
| T-04-37 | Repudiation | licence obligation silently regressing | mitigate | The credit is constructed unconditionally in `src/main.ts`, outside any `DEBUG_ENABLED` gate, and asserted as such — it cannot become a dev-only feature the way a debug-gated element could |
