<objective>
Make the compiled area solid. Every road edge and junction becomes its own Rapier trimesh collider
carrying its own surface type; every building becomes a box; the car spawns on the road.

Purpose: this is where Phase 3's per-wheel surface grip meets real data. `src/physics/surface.ts`'s
`SurfaceMap` is a `ColliderHandle -> SurfaceType` table with one surface per collider — that
shipped design is what dictates one collider per edge rather than one merged road mesh, and it is
also what makes SC2's "dirt and tarmac already drive differently with no hand-tagging" happen for
free the moment the colliders are registered correctly.

Output: the compiler's collision sidecar plus the physics scene that consumes it, both tested
headlessly before any browser is involved.

MVP-slice increment: the compiled area becomes a physical place. After this plan an automated test
drops a car onto Juliette's Main Street and it lands on tarmac.
</objective>

<interfaces>
Phase 3's shipped contracts this scene must satisfy exactly (read `src/physics/surface-scene.ts`
in full — it is the structural analog):

```typescript
export interface SurfaceMap {
  register(colliderHandle: number, surface: SurfaceType): void;
  lookup(colliderHandle: number | undefined): SurfaceType;
}
export interface SurfaceContext { readonly map: SurfaceMap; readonly profiles: SurfaceProfiles; }
```

`SurfaceScene`'s shape, which `MapScene` must mirror so `src/main.ts` and `startLoop` need no
structural change: `bodies: readonly RAPIER.RigidBody[]` (chassis only), `vehicle: Vehicle`,
`surfaces: SurfaceContext`, `preTick(tick)`, `applyInput(frame)`, `setTuning(t)`,
`setSurfaceProfiles(p)`, `dispose()`.

Collider construction pattern, from `surface-scene.ts`'s `buildSurfaceZone`:
`world.createRigidBody(RAPIER.RigidBodyDesc.fixed().setTranslation(...))` then
`world.createCollider(desc, body)` then `surfaceMap.register(collider.handle, surface)`.

**Mandatory**: road colliders use
`RAPIER.ColliderDesc.trimesh(vertices, indices, RAPIER.TriMeshFlags.FIX_INTERNAL_EDGES)`.
The flag's value is 144 and omitting it produces invisible bumps at every internal triangle seam —
04-RESEARCH.md Pitfall 5, and precisely the SC1 failure this phase exists to avoid.

`buildRoadGeometry(graph)` from `src/core/road-geometry.ts` (plan 04-03) supplies the vertex and
index buffers, already in world-space local ENU metres.
</interfaces>

<plan_decisions>
- **D-P22 — non-road collision data ships in a sidecar `<areaId>.collision.json`, not in the
  `.map.json`.** `docs/schemas/road-graph.v1.md` is normative and closed at v1; adding a
  `buildings` key would be a schema change requiring a v2 document. Road collision still derives
  from the road graph itself via `buildRoadGeometry`, so SC3's "collision geometry derives from the
  same road graph" is unaffected — the sidecar carries only what the road graph does not describe.
- **D-P23 — one collider per edge and one per junction, never merged.** Dictated by
  `SurfaceMap`'s collider-level granularity (04-RESEARCH.md Pattern 2, verified against shipped
  code) and independently by Rapier broadphase guidance in `.planning/research/STACK.md`. Merging
  would make correct per-wheel friction structurally impossible.
- **D-P24 — the map is fetched and parsed by the composition root, not by the physics tier.**
  `createMapScene` takes an already-parsed `RoadGraph` and `MapCollision`. `src/physics/` must not
  touch the DOM or any network API (`tests/layering.test.ts` polices this), and keeping the fetch
  in `src/main.ts` also keeps the scene factory synchronous and directly testable in Node.
</plan_decisions>
