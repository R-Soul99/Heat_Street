<objective>
Give the compiled area real terrain: sample USGS 3DEP for every node, smooth every edge's
centreline, and clamp both ends of that smoothing to the node heights so junctions stay
continuous by construction.

Purpose: D-09 asked for real rolling elevation and crests because the Core Value names jumps
explicitly. SC1's second, independent failure mode is elevation noise — a 1 m DEM sampled raw at
every polyline vertex produces a visibly and physically bumpy road even with perfect topology.
Schema design decision 1 already locked the answer: `y` is authored here, smoothed, once, and
never sampled at runtime.

Output: the same compiled artifact, now with a real Y coordinate on every node and every
centreline point.

MVP-slice increment: the target area stops being flat. Opening the compiled map now shows the
~33 m of Piedmont relief the research pass measured across the box.
</objective>

<plan_decisions>
- **D-P14 — the requested raster is capped at 512 px per axis.** The native 3DEP product is 1 m,
  and `demSource` stays `usgs-3dep-1m` because that is the source dataset. A 512-px request over
  the ~2.9 km box is roughly 5.7 m per pixel, which is far finer than the smoothing window that
  follows and keeps the cached raster around a megabyte — small enough to commit, which is what
  makes rebuilds offline and reproducible. A full-resolution request would be a ~36 MB raster
  whose extra detail the smoothing pass immediately discards.
- **D-P15 — node heights are authoritative and shared.** Each graph node is sampled once; every
  edge touching it takes that exact value at its corresponding endpoint. Junction continuity is
  then true by construction rather than by agreement between two independent smoothing passes.
- **D-P16 — the cached `.tif` is committed.** Same reasoning as the Overpass snapshot (plan
  04-02): SC3's reproducible rebuild cannot depend on a remote service answering.
</plan_decisions>

  <action>
Create `tools/map-compiler/graph/elevation.ts` exporting
`applyElevation(graph, sampler, projector): { graph: RoadGraph; report: ElevationReport }`.

Order of operations matters and is the whole point of the plan:
1. Sample once per NODE at that node's lat/lon (via `projector.unproject`), writing the result to
   the node's `y`. This value is authoritative and is never smoothed (D-P15).
2. For each edge, sample the raw DEM at every interior centreline point.
3. Smooth the interior sequence with a windowed moving average (window 5, shrinking symmetrically
   near the ends), then overwrite the first and last entries with the `from`/`to` nodes'
   authoritative `y`. The clamp is applied AFTER smoothing, not before, so no smoothing window can
   pull a junction off its node height.
4. Recompute `lengthM` as the 3D polyline length now that Y is real — the flat-Y value from plan
   04-04 understates the length of a hilly edge, and `lengthM` feeds pathfinding cost in Phase 5
   and AI target speed in Phase 7.

Export the smoothing window as a named constant tagged `[ASSUMED]` — it is a reasoned default
whose right value is a feel judgement, and plan 04-10's session is where it gets confirmed or
retuned. State in a comment that raising it flattens real crests (working against D-09's jumps)
while lowering it reintroduces DEM noise as judder (working against SC1), so the two failure modes
bracket it from both sides.

Report: per-edge maximum gradient, the list of edges above the 0.35 threshold, min/max node
elevation across the graph, and the total relief. The relief figure is a direct check against
D-09's "real rolling elevation, not flat ground" — if it comes back near zero, the DEM is wrong.

Test with synthetic samplers rather than a real raster: a sawtooth (noise rejection), a monotonic
ramp (relief preservation), and a plane with a bump (gradient reporting). Use a synthetic 4-way
junction graph for the shared-node-height case. Assert the endpoint clamp with exact float
equality, not a tolerance — an approximate match here means a junction step, which is SC1's named
failure mode.
