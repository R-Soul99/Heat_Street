<objective>
Drive every road in Juliette, GA, end to end, and fix what the drive finds — then record the
phase's decisions so they stay decided.

Purpose: SC1's wording is "Player can drive every road in the area end to end without hitting
invisible seams, floating road edges, bumpy junctions, or getting wedged at intersections." The
topology half is proven by the plan 04-03 watertightness test and the plan 04-06 validator; the
perceptual half is not automatable and never will be. Phase 2's plan 02-10 and Phase 3's plan
03-12 both established this shape: a human session, findings recorded verbatim, constants retuned
with before/after, and the tuned values committed.

Output: a signed-off area, a set of retuned constants with recorded reasoning, and an ADR.

MVP-slice increment: the phase's deliverable becomes something the developer has actually played
and accepted, rather than something the tests say is fine.
</objective>

**As a** Heat Street player, **I want to** drive a real small-town road network end to end —
tarmac main street, gravel county roads, real hills — **so that** every route I learn is a real
place rather than a test fixture.

  <what-built>
The complete Phase 4 deliverable: `npm run dev` boots on the compiled Juliette, GA area. Real OSM
topology with junction fans, real USGS 3DEP elevation smoothed and clamped at every node, per-edge
colliders carrying OSM-derived surfaces, building masses along Main Street, DEM-derived off-road

The tuning surface above lists every assumed constant this session can turn. All of them live
in the compiler, so turning one means editing the constant and re-running
`npm run compile-map -- --area juliette-ga` — there is no live panel for map constants, and
building one is not worth it for a one-time authoring pass.
  </what-built>
  <how-to-verify>
Run `npm run dev` with `?debug`. Work through these in order and report findings per step; a
finding is a location plus what felt wrong, not a diagnosis.

1. **Drive every road end to end.** Use the compiler's printed edge count as the checklist size.
   Report any invisible seam, step, floating road edge, bump that is not real terrain, or place
   the car snags or gets wedged. This is SC1's literal wording and is the session's main job.
2. **Every junction.** Cross each one at speed and at a crawl. Report any step, catch, or place
   the fan geometry visibly disagrees with the roads meeting it.
3. **Surface transitions.** Drive from tarmac onto each gravel/unpaved road the compiler reported.
   Confirm grip, dust and audio all change and that the change lands where the visual boundary is.
   Report any road that feels like the wrong surface for what it looks like — that is the silent
   untagged-fallback risk 04-RESEARCH.md flagged, and it is the one defect the build cannot catch.
4. **Junction aprons.** At a tarmac/gravel junction, report whether the apron reading as paved
   feels right or wrong. This is the `[ASSUMED]` highest-road-class rule from plan 04-03.
5. **Road widths.** Report whether Main Street and the county roads feel the right width for the
   car at speed — too narrow reads as a corridor, too wide as a runway.
6. **Crests and jumps.** Find the hilliest road (the compiler printed the steepest edges). Report
   whether crests read as real rolling terrain per D-09, whether anything is catchable as a jump,
   and whether any road feels rippled or noisy rather than smooth.
7. **Leaving the road.** Deliberately slide off onto the grass in several places, including on a
   slope and at the map edge. Confirm you land on solid ground, that it reports grass, and that
   nothing pokes through the road where you rejoin it.
8. **Buildings and camera.** Drive Main Street. Report whether the town reads as a town, whether
   buildings are in plausible places, and whether the occlusion fade behaves now that real density
   exists. Also re-check the steepen mitigation on the `O` toggle — `docs/adr/0003` records it was
   never fairly judged because the `FrontSide` building materials broke the fan-ray probe, and
   plan 04-09 changed those materials to `DoubleSide`. Report whether the probe now reads non-zero
   density, and if steepen is now judgeable, whether it reads better or worse than fade.
9. **Profiler.** Press Backquote. Report frame ms, physics ms, draw calls, triangles and body
   count while driving through the densest part of town.
10. **Overall.** Does this read as a real place worth learning routes in? That is the phase's
    actual bar.
  </how-to-verify>

Write `docs/adr/0004-first-area-and-compiler-decisions.md` in the house ADR style, recording the
decisions this phase locked so a future agent does not reopen them:
- Juliette, GA (Monroe County) is v1's area, with its bounding box and why it was chosen against
  D-01 through D-09, and the user's explicit confirmation.
- Geomesh's road and building Overpass query logic and its building height-inference table were
  PORTED; its elevation pipeline was NOT, because its default Terrarium 30 m source is not one of
  ADR 0001's two approved DEM sources. USGS 3DEP is fetched directly instead per ADR 0001's US
  selection rule.
- The compiler is an offline Node CLI under `tools/`, outside `src/`, with `tsconfig` and the
  Google-data grep gate both widened to cover it.
- Collision granularity is one collider per road edge and per junction, dictated by
  `src/physics/surface.ts`'s collider-level `SurfaceMap`; render granularity is one mesh per
  surface, dictated by `createSurfaceFx`'s parallel-array contract.
- `src/core/road-geometry.ts` is shared between the compiler and the runtime so collision and
  visual geometry cannot drift (plan 04-03 D-P9).
- Non-road collision data ships in a `<areaId>.collision.json` sidecar rather than as a
  `road-graph.v1` schema change (plan 04-08 D-P22).
- Off-road ground is a DEM-derived uniform-grass heightfield sunk beneath the roads (plan 04-10
  D-P28), resolving 04-RESEARCH.md's Open Question 3.
- `osmtogeojson` was not adopted because GeoJSON conversion discards the OSM node identity that
  junction detection requires (plan 04-01 D-P5), which also retires Open Question 4.
Include an Open Questions section carrying forward anything the session left unresolved, and an
Enforcement table naming the tests that keep each decision true, following ADR 0001's own format.

Register the new ADR in `tests/docs-present.test.ts`'s `REQUIRED` array with the 1500-character
floor the other ADRs use.
