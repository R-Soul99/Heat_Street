and its building masses, built from the same road graph the collision geometry comes from.

```typescript

  edges: { edgeId: number; surface: SurfaceType; positions: Float32Array; indices: Uint32Array }[];
```

`@gltf-transform/core` authoring shape:

```typescript
const doc = new Document();
const buffer = doc.createBuffer();
const position = doc.createAccessor().setType("VEC3").setArray(float32Positions).setBuffer(buffer);
const index = doc.createAccessor().setType("SCALAR").setArray(uint32Indices).setBuffer(buffer);
const prim = doc.createPrimitive().setAttribute("POSITION", position).setIndices(index).setMaterial(mat);
const mesh = doc.createMesh("roads-tarmac").addPrimitive(prim);
doc.createScene().addChild(doc.createNode("roads-tarmac").setMesh(mesh));
await new NodeIO().write("out.glb", doc);   // or writeBinary(doc) -> Uint8Array
```

The runtime consumer (plan 04-09) finds meshes by NAME, so the names below are a contract:
`roads-tarmac`, `roads-gravel`, `roads-dirt_road`, `roads-grass`, `roads-sand`, `roads-mud`
(only those actually present), and `buildings`.

Building height inference, ported from Geomesh's `/api/buildings/structures` handler: OSM `height`
tag in metres when parseable; else `building:levels` (or `levels`) multiplied by a per-level
height; else a per-type default — Geomesh's own table has `commercial: 12.0` and
`residential: 6.8` among others. Read `server.ts` for the full table rather than inventing one.

<plan_decisions>
- **D-P19 — road primitives are split by surface type, not merged into one.** 04-RESEARCH.md
  Pattern 2 recommends one merged render mesh for draw-call budget. Splitting by surface costs at
  most six draw calls (well inside `src/core/frame-budget.ts`'s 70-draw target, measured at 57 in
  Phase 3) and buys two things the merge cannot: per-surface materials for free, and the parallel
  `(meshes[], surfaces[])` arrays `createSurfaceFx` already requires for skid-decal projection.
  Merging would force reworking a shipped Phase 3 API.
- **D-P20 — buildings are extruded oriented bounding boxes, not triangulated footprints.** Open
  Question 2 resolved to "minimal placeholder building boxes" as the ceiling. An OBB (convex hull
  plus rotating calipers for the minimum-area rectangle) reads far better than an axis-aligned box
  for a street that does not run north-south, costs about sixty lines, and needs no polygon
  triangulation dependency.
- **D-P21 — no mesh compression in v1.** `@gltf-transform/cli`, `@gltf-transform/extensions` and
  meshopt are NOT installed. A ~3 km road network of flat ribbons is a small mesh; compression
  would add two more packages and a decoder dependency at runtime for no measured benefit.
  Revisit only if the `.glb` exceeds a few megabytes.
</plan_decisions>
