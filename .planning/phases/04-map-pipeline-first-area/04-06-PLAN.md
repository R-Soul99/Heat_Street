<objective>
Make SC5 real: a validator that proves every road in the compiled area is reachable and pathable,
and that refuses to write an artifact when it is not — reporting the specific node and edge ids
rather than a bare failure.

Purpose: SC5 is the only success criterion in this phase that is purely about failure behaviour.
"Reports failures loudly rather than silently" is the requirement; a validator that returns a
boolean is not it. Building it on `ngraph.path`/`ngraph.graph` does double duty: it is the correct
library choice per the existing stack decision, and it proves the emitted graph feeds the exact
pathfinding substrate Phase 5's navigation and Phase 7's AI will consume, with zero adaptation.
It is also what turns D-08 — genuine loops and alternate routes rather than a mostly-linear
layout — into something checked by routability between real node pairs rather than eyeballed:
plan 04-04 asserts a cycle exists, and this validator proves the whole network is mutually
reachable through those cycles under the oneway constraints.

Output: a validator module, wired as a build gate, with the negative cases proven by test rather
than asserted by comment.

MVP-slice increment: the compiler now refuses to ship a broken map. A developer who breaks the
topology finds out at build time, by id, instead of by driving into a void.
</objective>

<interfaces>
`ngraph.graph@20.1.2` and `ngraph.path@1.6.1` were installed by plan 04-01 and have no prior use
anywhere in this repo — there is no call-site convention to copy. The shape:

```typescript
import createGraph from "ngraph.graph";
import { aStar } from "ngraph.path";

const g = createGraph();
g.addLink(fromNodeId, toNodeId, { weight });        // directed link
const pathFinder = aStar(g, { distance: (a, b, link) => link.data.weight });
const path = pathFinder.find(startId, endId);        // [] when unreachable
```

If either package ships no TypeScript declarations, add a minimal local `.d.ts` under
`tools/map-compiler/types/` declaring only the members used above, rather than installing an
`@types/*` package — that keeps the supply-chain surface at what plan 04-01's audit already
covered.

Inputs: `RoadGraph` from `src/core/road-graph.ts`, and `buildRoadGeometry` from
`src/core/road-geometry.ts` (plan 04-03) for the geometry-sanity half.
</interfaces>

<plan_decisions>
- **D-P17 — reachability is checked twice, undirected and directed.** Undirected connectivity
  catches an island component (a road you cannot get to at all). Directed pathability, honouring
  `oneway`, catches the subtler case: a road you can drive into but never out of, which is a
  gameplay trap rather than a topology error and which an undirected check cannot see.
- **D-P18 — the validator is a build gate, not a report.** It runs before the artifact is written.
  A failing map does not get written at all, so a broken artifact can never be committed by
  accident and then silently loaded at runtime.
</plan_decisions>

  <action>
Create `tools/map-compiler/validate/validator.ts` exporting
`validateGraph(graph, geometry): ValidationFailure[]` and
`formatValidationFailures(failures): string`.

Structure it as a list of independent named check functions, each returning its own failures, with
`validateGraph` concatenating all of them — so a new check is an addition, not an edit to a
monolith, and so every check runs on every build regardless of what else failed.

Checks to implement:
1. **Referential integrity** — every `edge.from`/`edge.to` resolves to an existing node; every node
   is referenced by at least one edge.
2. **Undirected reachability** — build an ngraph with both directions for every edge, run a
   traversal from node 0, and report every unvisited node and every edge touching one.
3. **Directed pathability** — build an ngraph honouring `oneway` (one link for a one-way edge, two
   for a two-way edge, weighted by `lengthM`), then use `ngraph.path`'s `aStar` to confirm a path
   exists both TO and FROM a representative node for every other node. Doing this pairwise for
   every node is quadratic; instead run a forward traversal from node 0 and a backward traversal
   on the reversed graph from node 0, and report any node missing from either — that is linear and
   catches exactly the drive-in-never-out case. Additionally run a real `aStar.find` between one
   far-apart node pair and assert it returns a non-empty path, which is what actually exercises
   `ngraph.path` and proves the emitted graph is consumable by the Phase 5 pathfinder with no
   adaptation.
4. **Geometry sanity** — degenerate/duplicate consecutive points; `lengthM` versus computed 3D
   polyline length within 1%; maximum gradient at or below 0.5; and ribbon self-intersection
   detected as any quad whose XZ projection has a negative signed area given consistent winding
   (that is exactly the fold-back case a clamped miter is supposed to prevent, so this check is
   what proves plan 04-03's clamp is doing its job on real data).

Every failure carries a category, the offending `nodeId` or `edgeId`, and a message containing the
concrete numbers involved — mirroring `tests/road-graph-schema.test.ts`'s "iterate every edge,
check the specific invariant, report the specific id" discipline, which 04-PATTERNS.md names as
the in-repo model for this file.

Module header in the project's standard shape, closing with a "Layering:" sentence noting it is
build-time only and that `tests/layering.test.ts` does not scan `tools/**`.

Test every `<behavior>` bullet with small hand-authored graphs. The oneway-trap case is the one
worth building carefully: construct a graph where nodes A-B-C form a loop and D hangs off C
reachable only via a `oneway` edge pointing C to D, then assert the undirected check passes and
the directed check fails naming D.
