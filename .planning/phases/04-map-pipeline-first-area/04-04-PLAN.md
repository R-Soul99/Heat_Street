<objective>
Turn the committed OSM snapshot into a real, schema-conforming road graph for Juliette, GA, and
write it out with one command.

Purpose: this is SC3's first artifact and SC2's payoff. Everything downstream — elevation,
geometry, validation, collision, navigation in Phase 5, pursuit in Phase 8 — consumes this file.
Elevation is deliberately NOT in this plan: every `y` is 0 here, and plan 04-05 replaces it. That
split keeps topology bugs and elevation bugs from masking each other, which is exactly the mistake
04-RESEARCH.md's Anti-Patterns section warns about for SC1's two independent failure modes.

Output: `public/maps/juliette-ga.map.json`, conforming to `docs/schemas/road-graph.v1.md`, with
real nodes, real edges, real surfaces and real provenance.

MVP-slice increment: after this plan, the target area exists as data in the repo — you can open
the compiled map, count the roads, see which are gravel, and see the loops D-08 required.
</objective>

<plan_decisions>
- **D-P11 — `y` is 0 for every node and point in this plan.** Plan 04-05 owns elevation. A flat
  compiled map is a legitimate intermediate: it is drivable and schema-valid, and it isolates
  topology defects from elevation defects.
- **D-P12 — components not connected to the largest one are pruned, loudly.** A bbox cut always
  leaves orphan stubs where a county road exits the box. The compiler drops them and prints each
  dropped edge id, way id and length, rather than emitting a graph the plan 04-06 validator will
  reject. The validator then asserts full connectivity on what remains — belt and braces.
- **D-P13 — `highway=service` ways are excluded unless they carry an explicit `surface` tag.**
  04-RESEARCH.md found 30 of 56 ways in this box are `service`, plausibly driveways, whose absent
  surface tag falls back to tarmac — a documented silent-accuracy risk. Keeping the explicitly
  tagged ones preserves genuine unpaved refuge/forest tracks while dropping driveway spurs. The
  exclusion is config-driven (`excludeHighwayClasses`) and the dropped count is printed.
</plan_decisions>

Create `tools/map-compiler/graph/project.ts` exporting `makeProjector(origin: { lat: number; lon: number })`
returning `{ project(lat, lon): { x: number; z: number }, unproject(x, z): { lat, lon } }`.

Use the standard local-tangent metres-per-degree series evaluated at the origin latitude phi0 in
radians:
metresPerDegreeLat = 111132.92 − 559.82·cos(2·phi0) + 1.175·cos(4·phi0) − 0.0023·cos(6·phi0);
metresPerDegreeLon = 111412.84·cos(phi0) − 93.5·cos(3·phi0) + 0.118·cos(5·phi0).
Then `x = (lon − lon0) · metresPerDegreeLon` and `z = (lat0 − lat) · metresPerDegreeLat` — note the
inverted subtraction on Z, which is what makes Z point SOUTH per the schema's coordinate
convention. Getting that sign wrong mirrors the whole map north-to-south and is close to
undetectable by eye; state it in a comment and assert it in a test. Tag the series
`[CITED: standard WGS84 local metres-per-degree series]`; note in a comment that over a ~3 km box
the error is well under a metre, far below road width, so no full geodetic projection is needed.

Create `tools/map-compiler/graph/build-graph.ts` exporting
`buildGraph(roadsEnvelope, config): { graph: RoadGraph; report: BuildReport }`. This task
implements the topology half; Task 2 adds attribute resolution.

Topology algorithm, in order:
1. Filter way elements: keep those with a `highway` tag; drop those whose class is in
   `config.excludeHighwayClasses` AND which carry no explicit `surface` tag (D-P13), counting drops.
2. Count OSM node-id occurrences across the surviving ways. A node becomes a graph node if it is
   any way's first or last node, or if it occurs in two or more distinct ways. `junction` is true
   when the resulting graph node has degree 3 or more — compute degree after edges are built, not
   from the raw occurrence count, because a way that loops back on itself contributes twice.
3. Choose the origin as the bbox centre from `config.bbox`, build the projector, and project every
   retained OSM node's lat/lon to `{x, z}` with `y = 0` (D-P11).
4. Split each way at every graph node it passes through, emitting one edge per span with `points`
   as the full projected polyline for that span, inclusive of both endpoints.
5. Assign dense node ids and edge ids in a deterministic order — sort by OSM node id and OSM way
   id respectively before assigning — so recompiling the same snapshot produces a byte-identical
   artifact. Non-determinism here would silently break SC3's "reproducible rebuild".
6. Compute `lengthM` per edge as summed XZ distance, and `bounds` as the min/max over every node
   coordinate.
7. Compute connected components ignoring `oneway` (undirected, per the schema's design decision 3),
   keep the largest, and prune the rest — reporting each pruned edge by id, `osmWayId` and length.

If a way element has no `nodes` array (it should, given plan 04-02's `out body geom qt`), fall back
to identifying nodes by their lat/lon rounded to 7 decimal places, and set a flag in the report so
the CLI can print a warning. A silent fallback here would produce a graph with no shared junctions
at all — every way an island — which is a spectacular failure worth naming loudly.

`BuildReport` carries: retained/dropped way counts by reason, node and edge counts, junction count,
pruned-component details, the node-identity mode used, and a placeholder for the surface coverage
Task 2 fills in.

Test with `fixtures/overpass.juliette-sample.json` plus small hand-authored element arrays for the
sharp topology cases (a way looping on itself, a way passing through a shared node, an orphan
component). Assert the deterministic-id property by running `buildGraph` twice and comparing
`JSON.stringify` output for exact equality.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OSM tag values -> compiled artifact | Community-edited free-text values become numeric and enum fields consumed by the physics runtime |
| compiler output -> `public/` | The artifact is served to the browser as a static asset |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-14 | Tampering | edge attribute resolution | mitigate | Every numeric OSM tag is range-checked before use (`widthM` clamped 2-30 then floored/ceilinged 3.5-20, `lanes` must parse to a positive integer, `maxspeed` falls back on an unparseable value) — an absurd or hostile tag value becomes a documented default, never a NaN width that produces degenerate collision geometry |
| T-04-02 | Tampering | unmapped `surface=*` | mitigate | `mapSurface` throws and `buildGraph` aborts naming the value and `osmWayId` — the schema's design decision 4 made executable |
| T-04-15 | Tampering | compiler emits an artifact the runtime rejects | mitigate | `buildGraph` self-checks by running its own output through `parseRoadGraph` before returning, so compiler and runtime can never disagree about what conforms |
| T-04-16 | Denial of Service | `public/maps/*.json` size served to the browser | accept | A ~3 km area at 2-space-indented JSON is on the order of hundreds of kilobytes; readability and diffability are worth more than the bytes at this scale, and the artifact is cached by the browser like any static asset |
| T-04-04 | Tampering | new `tools/` source files | mitigate | Covered by plan 04-01's widened `tests/no-google-pipeline.test.ts` scope; no Google-derived byte enters this pipeline — the only inputs are the committed Overpass snapshot and the area config |
</threat_model>
