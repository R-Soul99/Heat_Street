<objective>
Core changes that let a map hold any number of road race routes authored by hand (D-12, D-13): relax `parseCourseData`, add an optional start position and a serializer, add the editor's `RouteDraft` shape with node/edge derivation, make `nearestRoadNode` safe on an empty graph, and let validation and medal references cope with authored routes.

Purpose: the editor (plans 10-07, 10-12) and the game (plan 10-11) need these before road routes can be authored and raced.
Output: changed course.ts, navigation.ts, medal-reference.ts; new route-draft.ts; updated tests.

Decisions recorded (planner, user asleep):
- D-12 file layout: road routes stay in `routes.json` (+ `medals.json`), stages in `stages.json`, behind one editor tool (research recommendation; the UI hides the split). The brief's "do not relax parseCourseData" trap is superseded by D-01 revised / D-12.
- New authored limits (assumption A4): up to 20 courses per file; p2p 2..40 checkpoints (the last is the finish), circuit 3..40, circuit laps 1..20 (UI-SPEC Laps 1 to 20). Existing files (p2p 5-8, circuit 4-6, laps 3) remain inside the new ranges.
- `CourseStart` gains optional `x`/`z` (both or neither). When present the game spawns there with `headingRad` read as YAW (plan 10-11). Older files without x/z are unchanged.
- `validateCourseRoutes(routes, graph, { authored: true })` keeps only the "no directed path" check; the 30 m edge tolerance, sensor size and gravel/dirt checks are skipped for authored routes. The DEFECT_COORDINATES check runs only when `routes.areaId === "juliette-ga"` (A5; the list is Juliette-local).
- Checkpoint ids stay unique across the whole file (existing parser rule); the editor generates `<routeId>-cp-<n>` and `<routeId>-finish`.
</objective>
