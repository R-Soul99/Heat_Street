<objective>
The stage coordinator (brief stage 3): a fourth `RaceCoordinator` that drives a stage run from the fixed tick, feeds medal timing (each gate a sector), refreshes gate view, minimap, arrow and HUD, and handles restart/respawn.

Purpose: the only gameplay-layer piece of stage mode; `main.ts` (plan 10-08) only composes it.
Output: `src/gameplay/stage-coordinator.ts` and its fake-based test.

Decisions recorded (planner, user asleep):
- Timing: `createMedalTiming({ referenceTimeSec: 0, medals: false })` is built by main and injected (time-only; starts on first movement >= 0.5 m/s like P2P, answering brief 5.4: solo modes have no countdown). The stage medal, when the stage has medals for this vehicle class, is classified at completion with `classifyStageMedal` (plan 10-01) instead of medal-timing thresholds (research open question 1 resolved without touching medal-timing).
- Per-gate split delta vs personal best is computed here from the PB record's `splitsSec` because medal-timing drops comparisons when `medals: false`.
- HUD and gate view are typed as small structural ports declared in this file (`StageHudPort`, `StageGatePort`) so this plan runs in parallel with plan 10-05, which implements them on `RaceHud` and `StageView` with exactly these signatures.
</objective>
