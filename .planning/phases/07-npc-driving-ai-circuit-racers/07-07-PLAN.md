DECISION (course-data representation, CONTEXT "Claude's Discretion" + PATTERNS finding): Circuit Race is a RUNTIME VARIANT of the existing `mode: "circuit"` course (`?mode=circuit-race`, built in 07-02), NOT a third entry in juliette-ga.routes.json. Rationale: parseCourseData hard-requires exactly one p2p + one circuit course (course.ts lines 222-233); parseMedalReference cross-checks every route course against a medal reference, and a third course would need medal thresholds that D-05 says Circuit Race must not have; validateCourseRoutes would re-validate duplicate checkpoints. The variant needs only its own persistence key, derived as raceVariantCourseId("juliette-three-lap-loop") = "juliette-three-lap-loop.race" (it matches COURSE_ID_PATTERN /^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$/). Solo course ids, references and saved bests are therefore untouched.

From src/core/medal-persistence.ts: MEDAL_PROGRESS_KEY "heat-street.medals.v1"; KIND "heat-street.medal-progress"; VERSION 1; MedalProgressRecord { courseId, bestTimeSec, medal }; isValidRecord (field-by-field); copyRecord (named fields only, prototype-pollution safe); parseMedalProgress(raw, known) (bad JSON / wrong kind / wrong version -> emptyMedalProgress()); mergeMedalResult; loadMedalProgress(storage, known); saveMedalResult(storage, courseId, result, known). copyValidCourses DROPS records whose id is not in knownCourseIds, so any save that loads with a list lacking the race id would DELETE the race record.

From src/core/race-placement.ts (07-06): computeStandings(inputs: { racerIndex, finishEffectiveSec: number | null, progressM }[]) -> { racerIndex, position, finished }[]
