# Phase 07.1 Plan 22: Map editor dock layout Summary

The map editor now uses the terrain editor's dock layout (GD-LAYOUT): info box bottom-right, view pad top-right with Grid / Tiles / Legend toggle buttons that show a pressed state, and the five tools as a visible button row bottom-left with the floating flyout above the active tool.

## What changed

- `tools/map-editor/editor.ts`
  - `buildShell` passes `layout: "dock"`; no tool has `dock: "top"` (Select's flyout is a column panel).
  - New shared `toggleGrid`, `toggleTiles`, `toggleLegend`, `legendShown`; the View menu items (kept) and the new `view.extra` buttons call the same functions, which also call `shell.refreshMenus()` so the menu tick and pad button stay in step. `legendShown` reads `#legend` from the DOM because the pad asks for pressed state while the shell is still being built (before `legendEl` is assigned).
  - Removed the unused `hintEl` helper (the pre-existing biome warning is gone).
  - `drawHud` scale bar starts 16 px right of the bottom tool row (it was hidden underneath it once the canvas reached the window bottom).
- `tools/map-editor/index.html`: `#to-terrain-btn` at left 8 / top 36; `#legend` at right 8 / top 248 (under the view pad).
- `tools/editor-shell/shell.css`: `.shell-topbar:empty { display: none; }`. The terrain editor always has top tools, so its bar is never empty and is unaffected.

## Overlap check (Task 2), measured in headless Chrome via CDP

Loaded http://localhost:5173/tools/map-editor/index.html (user's dev server, not restarted), closed the start screen, turned the legend on, clicked each tool and read `getBoundingClientRect` (left, top, right, bottom). Pairwise intersection test reported none for every tool at both sizes.

1920x1080: same left/top-anchored rects; history 1723,36 - 1912,71; view pad 1770,80 - 1912,236; legend 1828,248 - 1912,364; tool row 8,1024 - 232,1072; info 1612,914 - 1912,1072; flyouts end at y 1022. No intersections.

Reasoning for content-dependent sizes: the floating flyout is capped at `max-height: calc(100% - 160px)` and anchored 58 px above the window bottom, so its top is never above y 102 at 720 px, below the Open in terrain editor button (ends at 71). The info box grows upward with long status text; there are 190 px between the legend bottom (364) and the shortest measured info top (554).

No CSS changes were needed in Task 2 beyond the positions set in Task 1, so Task 2 has no separate commit.

## Deviations from Plan

1. **[Rule 1 - Bug] Scale bar hidden under the tool row.** In the dock layout the canvas runs to the window bottom, so the bottom-left scale bar sat under the tool row. `drawHud` now starts it right of the tool row. Commit a66e283.
2. **Legend placement differs from the plan's example** (left 8 / bottom ~56). That spot is where the floating flyout opens above the bottom-left tool row, so the legend went to the right column under the view pad instead. The plan's example was a suggestion; the "nothing overlaps" truth is what it serves.
3. **Open in terrain editor** went top-left rather than near the history pad: the top-left is empty in the dock layout once the empty top bar is hidden.
