## Deviations from Plan
- Stepper pure maths went in Task 1 and the `createStepper` DOM in Task 2 (same file, two commits), as the plan split implied.
- One of my own tests was wrong (prefs getBool "garbage" case collided with the in-memory copy set earlier); fixed the test to use a fresh prefs instance. No pre-existing test changed.
- Shell Help handling: a Help menu named exactly "Help" gets a separator plus the toggle appended; otherwise a new Help menu is added. Menus are copied, the caller's array is not mutated.
- `installTooltips(root)` takes `root` for contract compatibility but delegates on `document.body` so dialogs get tips (per plan); `root` is unused.

## Notes for consumers
- `installTooltips` registers body/window listeners once per call; `createShell` should be called once per page.
- Stepper commit semantics: `onChange` fires only on a real value change; typed values keep full precision, stepped/set values show `decimals`.
- ArrowUp/ArrowDown inside the stepper input stopPropagation, and `resolveShortcut` also skips Arrow bindings when a value control is focused.
