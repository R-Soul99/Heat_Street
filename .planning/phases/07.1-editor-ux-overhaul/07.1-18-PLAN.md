<objective>
Road problems panel, pure half (UAT test 9, major). Plan 07.1-21 wires these into the dispatcher and panel.

Locked user decision GD-ROAD (07.1-UAT.md "Decisions for gap closure", 2026-11-13): "one-way trap and cut-off NEVER block saving (warn only). Each row names the road and end, with fix buttons (Make two-way, Connect ends, Close loop). Only real corruption (e.g. broken references) may block."

Planner diagnosis of the screenshot (screenshots/roadProbs.png, new-area-2, one open looped path, 3 "one-way trap" + 3 "cut off" rows):
- validator.ts checkDirectedPathability does a directed BFS from graph.nodes[0]. A piece that is cut off entirely is ALSO unreachable in the directed sense, so every cut-off node is reported twice more as DIRECTED_PATHABILITY. Terrain-editor roads are always two-way (applyRoadStroke hardcodes oneway: false), so those "one-way trap" rows were duplicates of "cut off", and they blocked saving because NON_BLOCKING_ON_TERRAIN deliberately excluded DIRECTED_PATHABILITY.
- DIRECTED/UNDIRECTED node failures have kind "node", which is why rows said "Junction N".

Scope boundaries: GEOMETRY_GRADIENT stays blocking (the steep-road discussion is explicitly out of scope); REFERENTIAL_INTEGRITY, GEOMETRY_DEGENERATE_POINT, GEOMETRY_LENGTH_MISMATCH stay blocking (corruption). The stale-unlocked-road guard (staleRoadBlockMessage) is unchanged. tools/map-compiler/validate/validator.ts is NOT changed (the compiler and map editor rely on it).

Output: updated save guard + pure road-problems module with fix planners, fully unit tested.

    - RoadFix { kind: FixKind; label: string; tip: string; edgeId: number; nodeId?: number }

    Planners (pure, no mutation of input):
    - planConnectEnds(graph, edgeId): edge in a cut-off piece -> { from: {x, z, nodeId}, to: {x, z, nodeId?, edgeId?}, distanceM } pairing the piece's open ends (all piece nodes if it has none) with the nearest root-piece node or nearest point on a root-piece edge polyline; null when the edge is in the root piece, the root piece has no edges/nodes to join, or distanceM > CONNECT_MAX_M
    - planCloseLoop(graph, edgeId): piece containing edgeId (root or cut-off) has exactly two distinct open-end nodes and their XZ gap <= CLOSE_LOOP_MAX_M -> { a, b, from {x,z}, to {x,z}, gapM }; else null
    - twoWayCandidates(graph, nodeId): ids of oneway edges incident to the node; if none, every oneway edge in the node's undirected piece; [] when there are none
    - makeTwoWay(graph, edgeIds): sets oneway=false on those edges; null when nothing changes; after makeTwoWay(twoWayCandidates(...)) on the trap fixture validateGraph has no DIRECTED_PATHABILITY failures
    - mergeEndNodes(graph, keepId, dropId): rewires every edge endpoint at dropId to keepId (moving that edge's end point to keepId's x,y,z and recomputing lengthM), removes node dropId, null if either id is missing or they are the same or the result would create a zero-length edge; used for tiny Close-loop gaps.
