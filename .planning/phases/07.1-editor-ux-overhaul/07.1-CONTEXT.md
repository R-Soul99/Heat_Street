# Phase 07.1: Editor UX Overhaul - Context

**Gathered:** 2026-11-11, from the user's own request while importing the poppmap road image.

## Problem (user's words, condensed)

- The map editor's right sidebar scrolls and wastes screen space. The terrain editor has the same problem.
- Importing an image laid the traced roads over the existing map instead of starting fresh.
- Creating a blank map is hard and gives no explanation when something fails.
- Real width shows silly precision (0.9345318244236143).
- The terrain editor's raise/lower doesn't work for the user, and they dislike the Alt modifier on it.

## Locked decisions

- **D-01 Layout (approved "perfect"):** thin top bar with dropdown menus (File/Area, Import, View, Help) → full-screen canvas → floating LEFT tool rail with an options flyout for the active tool → zoom +/−, fit and pan pad bottom-right → Undo/Redo/Clear top-right → info bar along the BOTTOM. No scrolling sidebar.
- **D-02 Shared shell:** both editors (`tools/map-editor`, `tools/terrain-editor`) use one shared shell module. Don't build two separate layouts.
- **D-03 Info bar:** area, world size, tile size, cursor x/y, element counts, unsaved-changes marker, last status/error. Every failure shows a readable reason there; nothing fails silently.
- **D-04 Tooltips:** on every control, explaining what it does and how to use it. A toggle switches them on and off (remember the setting per browser).
- **D-05 Numbers:** large up/down steppers; arrow keys step the value (Shift = coarse). Dropdowns are sized to their content. Derived values display to 3 dp (1 m at km scale), with full precision kept internally.
- **D-06 New popup (user-specified):** a **New** button opens a popup with Width and Height fields and a **Create** button that creates and opens a blank canvas of that size. The same popup has an **Import image** button with its OWN Width field; height is derived from the image aspect ratio, as it is now (the user likes this). Import creates a FRESH map and never overlays the current one. Validation errors (bad id, already exists, size limits) show in the popup.
- **D-07 Map editor tools:** Select = drag a box, then tickboxes Roads / Buildings / Objects to delete or disable what's inside, per type or all at once. Draw road = click centre-line points, double-click or Enter to finish; options are width (m) and surface type, kept simple. Eraser = click or drag to delete. Undo, Redo, Clear all (with a confirm).
- **D-08 Terrain editor tools:** separate **Raise** and **Lower** buttons with NO modifier. Diagnose why the current raise/lower doesn't work for the user. **Grid select** = drag a rectangle of cells, then ▲/▼ buttons raise or lower the selection by a step set on a collapsible slider; **Ctrl+drag vertically** pushes or pulls the selection by hand. Brush options go in the tool flyout.
- **D-09 Keyboard:** a shortcut for every tool, and `[` `]` and the arrow keys adjust the active value.
- **D-10 No quick fix first:** the user chose to do the whole overhaul rather than patch the import overlap separately.

## Out of scope

- Placeable objects (trees, hedges, fences) need a map-format and runtime change, so they go in a separate later phase. The Select tool's "Objects" tickbox can exist but stay disabled until then.
