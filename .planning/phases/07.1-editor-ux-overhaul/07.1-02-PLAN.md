<objective>
Make editor-created maps register themselves (settled decision 2: "New worlds register themselves automatically so they can be compiled and driven"). Introduce one manifest plus two generated, statically-importing registry modules, so the compiler's explicit-registry security rule (cli.ts T-04-08: never build an import path from argv) and the runtime `?map=` allowlist both stay intact.

Purpose: today a new world needs two lines hand-added to `tools/map-compiler/cli.ts`, and `src/core/map-select.ts` is a hard-coded list, so new maps cannot be compiled or driven (RESEARCH.md section 1, point 4). `popp` already exists on disk and is unregistered.
Output: registry module + tests, the manifest seeded with existing unregistered authored maps, both generated modules, and cli.ts / map-select.ts consuming them. The dev-server endpoints that call `registerAuthoredMap` are wired in plan 07.1-05.
</objective>
