# Phase 07.1 Plan 04: New Popup and Fresh-Map Image Import Summary

One New popup (File > New... and a top-bar New button) creates a blank map or a fresh map sized from an image, with all validation errors shown inside the popup; image import can no longer land on a map that already has roads.

## Commits
- 818793b feat(07.1-04): pure new-map validation and import planning, precise new-world server errors (tests written and seen failing first; 14 new tests)
- Second commit (see `git log`): editor.ts New popup and fresh-map import flow

## What changed
- new-map.ts (pure): suggestMapId, validateNewMapInput, validateNewWorldBody, planImportWorld (height derived from aspect, min/max width hints rounded to 3 dp).
- vite-plugin.ts: POST /__editor/new-world now returns the precise message (400 for bad JSON/name/size, 409 "already exists", other errors' own message). "bad id or size" is gone.
- editor.ts: popup with Name, Width, Height, "Import image..." section (own Width, linked Metres per pixel, live 3 dp readout, warnings or plan error). Actions: Cancel, Create blank map, Create from image. Errors return inline; unsaved changes are only discarded after validation passes and the user confirms.
- Image trace flyout is now the trace stage: with no image it shows only a hint; with one it shows scale readout, threshold (slider), road width, highway, surface, advanced tracing, Preview, Import roads, Discard image. Offset X/Y, the Real width/m-per-px fields in the flyout, and importing onto the current map are removed (as the plan states).
- Import roads is refused with the specified message if the map has any roads.

## Deviations from Plan
- "Create blank map" is the dialog's primary button always (the shell dialog API cannot change the primary action dynamically); "Create from image" is a normal button.
- On a successful image flow I did not call fit() after loadArea because loadArea already fits.
- Import state `impKm/impMpp/impMode` moved out of module level into the popup (they only exist there now); the flyout holds a locked `impMPerPx`.
- After Import roads succeeds, the pending image is cleared (the flyout returns to its hint), which also prevents a second import.
