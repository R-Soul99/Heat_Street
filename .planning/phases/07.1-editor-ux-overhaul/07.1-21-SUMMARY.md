# Phase 07.1 Plan 21: Road fix buttons, quiet save, visible ?area errors Summary

Road problems rows now offer one undoable button per fix (Make two-way, Connect ends, Close loop alongside Remove duplicate points / Smooth / Re-grade), connectivity warnings never stop or nag a save, and a failed `?area=` handoff opens a dialog with the reason and a Back to map editor button.

## What was built

**Task 1.** `applyRoadFix(kind, edgeId, nodeId?)` is now an explicit switch over every `FixKind`:
- `regrade`, `remove-duplicate-points`, `smooth-heights`: same behaviour and status text as before.
- `make-two-way`: `twoWayCandidates(graph, nodeId ?? edge.from)` then `makeTwoWay`, recorded via the new shared `commitGraphChange` helper (one undo entry). Status "Made N road(s) two-way: Road a, Road b."
- `connect-ends`: `planConnectEnds` then `fixStroke` (an `applyRoadStroke([from, to], presetFor(edge), { widthM, replace: false })`), committed via `commitLockDiff` as one undo entry. Status "Connected Road N to the road network (M m)."
- `close-loop`: `planCloseLoop`; gap under `2 * cellSizeM` uses `mergeEndNodes` through `commitGraphChange`, otherwise `fixStroke`. Status "Closed the loop on Road N."
- A null plan pushes nothing and explains, e.g. "Road 0: nothing within 250 m to connect to; draw a road to it by hand."

Five new tests: the trap flips and validates clean; connect-ends removes UNDIRECTED_REACHABILITY, advances nextEdgeId, paints, and one undo restores graph, heights, paint and nextEdgeId exactly; wide-gap close-loop leaves no degree-1 ends and undoes exactly; tiny-gap close-loop merges the nodes without touching paint and undoes exactly; a planner miss leaves `canUndo()` false.

**Task 2.** The panel renders one `createButton` per `row.fixes` entry, calling `dispatcher.applyRoadFix(f.kind, f.edgeId, f.nodeId)` through the existing result handling. Hints show only when there are no fixes. The header now reads `Road problems: N (B block saving)`. Each row has a muted "warning" badge or a red "blocks saving" badge (CSS in index.html). `validateRoads()` logs one info line: "N road warning(s): cut-off pieces or one-way traps. Saving still works; see View > Road problems." `save()` still refuses only on blocking failures and stale unlocked roads, so it no longer opens the panel when there are only warnings. The legacy `fixKind`/`fixLabel` row fields are gone, and the tests now read `fixes`.

**Task 3.** With `?area=<id>`, startup retries the area list at 0.5 s, 1 s and 2 s. It opens a "Could not open <id>" dialog when the list cannot be reached, the id is not listed, or the load fails. The dialog explains the reason ("There is no saved terrain map called <id> (expected public/maps/<id>.terrain.json)" or the load error), says the drawing is safe in the map editor, and gives the next step. Its actions are "Back to map editor" (goes to /tools/map-editor/index.html) and "Stay here". The message is also set as an error status and logged. The id is shown only when it matches `/^[a-z0-9-]{1,64}$/`; otherwise it reads "(invalid name)". All text goes in through textContent. Startup without `?area` works as before.

## Deviations from Plan

1. **[Process] TDD order.** Task 1 is `tdd="true"`, but I wrote the implementation and tests in the same step and committed them as one `feat` commit. There is no separate failing-test (RED) commit. All new tests exercise the new switch cases, and the planner-miss test checks the exact new status text.
2. **[Rule 2 - Correctness] Planner-internal fix field renamed.** The acceptance grep requires `fixKind` to appear only as the `FixKind` type name. So the per-category single fix inside `buildRoadProblems` moved to a private `RowCore.fix: { kind, label }` instead of keeping `fixKind`/`fixLabel` fields.
3. **[Rule 1] loadArea return type.** `loadArea` now returns `Promise<string | null>` (error text or null) so the startup dialog can show the real load error. Existing callers ignore the value.
4. **[Housekeeping] index.html line endings.** The working copy of `tools/terrain-editor/index.html` had CRLF endings. Git stored it as LF on commit, and I converted the working file to LF to match.
