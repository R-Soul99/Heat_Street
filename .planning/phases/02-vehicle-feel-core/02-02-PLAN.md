Export `interface PadSnapshot { steer: number; throttle: number; brake: number; handbrake:

`readGamepad` returns `null` when `typeof navigator === "undefined"`, when
`navigator.getGamepads` is absent, or when no non-null connected pad is present. Otherwise
it maps the FIRST connected pad using the standard mapping: `steer = axes[0]`,
`throttle = buttons[7].value` (right trigger), `brake = buttons[6].value` (left trigger),

any non-finite value yields 0.

the remaining range so the output still reaches +/-1 at full deflection (no step
discontinuity at the deadzone edge). Apply a 0.06 deadzone to each trigger. Clamp `steer`
to [-1, 1] and both triggers to [0, 1].

Put a comment at the mapping site recording that 02-RESEARCH.md Assumption A1 marks the
standard-mapping indices as `[ASSUMED]` / LOW confidence, verified only by the SC2 human
playtest in plan 02-10, and that a wrong index is a one-line fix.

`readGamepad` must be a plain exported function so plan 02-02 task 2 can inject a
substitute in tests. Do not poll on a timer and do not read a wall clock — the fixed tick

Create `src/input/live-input.ts` with the `src/input/` layering header.

Export `class LiveInputSource implements InputSource` (a class, per `input-tape.ts:49`'s
`implements InputSource` precedent and CLAUDE.md's plain-TS-classes mandate).

Constructor takes an optional deps object: `{ keys?: () => KeyState, readPad?: () =>
PadSnapshot | null, steerRampPerSec?: number, steerReturnPerSec?: number,
throttleRatePerSec?: number, brakeRatePerSec?: number }`. Defaults are built LAZILY INSIDE
the constructor (`createKeyboard().read` and `readGamepad`) exactly as
`startLoop` builds `createBrowserScheduler()` — so importing this module in Node never
touches `document` or `navigator`. Rate defaults: `steerRampPerSec` 2.5,
`steerReturnPerSec` 4.0, `throttleRatePerSec` 3.0, `brakeRatePerSec` 5.0. Comment the
2.5 value with the measured timing: linear rate 2.5/s reaches full lock in 0.400 s;
rate 1.6/s takes 0.633 s; rate 4.0/s takes 0.250 s. Comment that the linear form is
deliberate — an exponential lerp (the three.js example's `MathUtils.lerp(cur, tgt, 0.25)`)
never actually reaches full lock, so "hold left" asymptotes just short of the steering
limit, which is measurable in lap times.

`sampleForTick(tick: number): InputFrame`:
  - return `NEUTRAL` when `tick < 0` (copy `RecordingInput`'s guard).
  - if `tick > this.lastTick`, advance the ramp `Math.min(tick - this.lastTick,
    MAX_CATCHUP)` times and set `this.lastTick = tick`, where `MAX_CATCHUP` is 8 with a
    comment naming `src/loop.ts`'s `MAX_STEPS_PER_FRAME` clamp as the reason a larger
    catch-up cannot occur in practice.
  - if `tick <= this.lastTick`, do NOT advance — return the cached frame object. The frame
    is cached by reference so a repeated sample returns the identical object, matching
    `RecordingInput`'s contract that `sampleForTick(n)` twice yields the same frame.

`private advance()`: read the pad first. If `readPad()` returns non-null, assign
`steer`/`throttle`/`brake` straight through (already deadzoned and clamped by
`gamepad.ts`) with NO ramp — an analog stick is already analog — and return. Otherwise read
keyboard state and approach each axis linearly by `rate * DT` per call:
  - steer target = `(right ? 1 : 0) - (left ? 1 : 0)`; use `steerReturnPerSec` when the
    target is 0 or has the opposite sign to the current value, `steerRampPerSec` otherwise.
    Comment that the faster return/reversal rate is what makes counter-steer responsive
    without making the ramp itself twitchy — SC1 depends on catching a slide.
  - throttle target = `up ? 1 : 0` at `throttleRatePerSec`; brake target = `down ? 1 : 0`
    at `brakeRatePerSec`.
  - handbrake is taken raw from the key/pad state on every advance — binary, never ramped (D-02).

`DT` is imported from `../core/sim-clock` and no literal `1/60` or `0.0167` appears
anywhere in the file.

Before returning the frame, clamp `steer` to [-1, 1] and `throttle`/`brake` to [0, 1], and
substitute 0 for any non-finite value. This is threat T-02-05: a driver or browser bug
producing a `NaN` axis would otherwise reach `setWheelSteering` and corrupt the world.

Create `tests/live-input.test.ts` importing only `src/input/live-input.ts`,

  - "idempotent": call `sampleForTick(7)` twice; assert the second result is reference-equal
    to the first AND that the injected `keys` reader call count did not increase — copy the

  - "ramp is independent of call pattern": drive the source through the `consumeAtFps`

    second of sim time and assert the emitted steer value at every shared tick index is

  - "gamepad axes bypass the ramp": with `readPad` returning `{steer: 0.8, ...}`, assert

  - "gamepad deadzone": `readPad` returning `steer: 0.05` yields 0 (verify the deadzone is

  - "clamps hostile axis values": `readPad` returning `steer: NaN, throttle: 5, brake: -2`
