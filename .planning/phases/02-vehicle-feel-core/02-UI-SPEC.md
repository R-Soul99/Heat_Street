# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** This phase has exactly two UI surfaces and no others:

1. **Speedometer** (NAV-01, D-10–D-13) — player-facing, always on, `src/hud/speedometer.ts`.
2. **Dev tooling** (D-15–D-17) — `?debug`-gated, never player-facing: the lil-gui vehicle tuning panel and the telemetry results panel.

No menus, no level select, no timer, no minimap, no pause screen. Those arrive in Phases 5, 6 and 8 and are out of scope here. This document is nonetheless the seed of the project's HUD design language — Phases 5/6/8 extend the palette, type scale and layer contract below rather than inventing their own.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between the digital-readout window edge and its digits |
| sm | 8px | Legacy profiler-HUD viewport inset (existing, unchanged) |
| md | **16px** | **Viewport inset for all player-facing HUD elements — the speedometer sits 16px from the right and bottom edges** |
| lg | 24px | Vertical gap between stacked dev panels |
| xl | 32px | Reserved — unused this phase |
| 2xl | 48px | Reserved — unused this phase |
| 3xl | 64px | Reserved — unused this phase |

**Exceptions (exactly two, both justified):**

1. **`src/debug/profiler-hud.ts` keeps its existing `top:8px;left:8px` inset.** It is Phase 1 shipped code, it is dev-only, and changing it would touch a file this phase has no other reason to modify. New player-facing HUD elements use `md` (16px).
2. **SVG internal drawing coordinates are exempt from the 4px grid.** The gauge's tick radii, needle length and arc geometry are *drawing* geometry inside a `viewBox`, not layout spacing. They are specified exactly in the Speedometer Geometry Contract below and are governed by that table instead. The gauge's *outer* size and *viewport inset* obey the scale.

The gauge is rendered at **200 × 200 CSS px with `viewBox="0 0 200 200"`, so 1 SVG user unit = 1 CSS pixel exactly.** This is deliberate: it removes all unit-conversion ambiguity between this spec's type sizes and the numbers the executor writes into `setAttribute`.

## Typography

Exactly 4 sizes, exactly 2 weights. Sizes are CSS px at the gauge's 1:1 rendered scale.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Body | 11px | 400 (regular) | 1.45 | Dev tooling text: telemetry result rows, lil-gui labels, profiler HUD (existing) |
| Label | 14px | 600 (semibold) | 1.0 | Dial-face numerals (`0`, `20` … `160`) |
| Heading | 20px | 600 (semibold) | 1.2 | Telemetry results panel title, empty/error state headings |
| Display | 28px | 600 (semibold) | 1.0 | The digital mph readout inset in the gauge |

**Supporting typographic rules:**

| Rule | Value | Why |
|---|---|---|
| Numeric rendering | `font-variant-numeric: tabular-nums` on the gauge root SVG (inherited by all `<text>`) | The readout changes up to 60×/sec. Proportional digits make the number visibly shimmer as `1` swaps for `8`. Tabular figures pin the width. **Non-negotiable.** |
| Unit label `MPH` | 11px / weight 600 / `letter-spacing: 1px` / uppercase | The only place the Body size carries the semibold weight. Still within the 2-weight budget. |
| Gauge font stack | `"Arial Narrow", "Helvetica Neue", Helvetica, Arial, sans-serif` + `font-stretch: condensed` | Period-correct: 60s–70s instrument printing is a condensed grotesque. Zero webfonts, zero new dependencies (Phase 1's threat model resists both). |
| Digital readout is **not** seven-segment / LCD | — | A 1968 muscle car's trip odometer was a mechanical drum in the same condensed sans, not an LCD. An LCD face would be an anachronism against D-10's "period-correct". |
| Font-stack risk | `Arial Narrow` is not guaranteed on every macOS install | Accepted. The fallback chain degrades to `Helvetica`/`Arial` with `font-stretch: condensed`; the gauge stays legible, only slightly wider. Desktop-browser-first is a project constraint and Windows (the dev platform) ships Arial Narrow. |

## Color

The player-facing instrument palette. This is the 60/30/10 contract the checker validates.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0B0C` | Gauge face — the near-black dial that fills the instrument |
| Secondary (30%) | `#F2EFE6` | Warm off-white: dial numerals, major tick marks, `MPH` label, digital readout digits, needle hub ring |
| Accent (10%) | `#E8A33D` | Amber — **redline only** (see reserved-for list) |
| Destructive / alert | `#C8402F` | Deep red — the needle (player-facing) and dev-tool failure states |

**Accent (`#E8A33D`) reserved for — explicit and exhaustive:**

1. The redline arc band spanning **120 → 160 mph** on the dial.
2. The three dial numerals inside that band (`120`, `140`, `160`).
3. The digital readout digits, which switch from `#F2EFE6` to `#E8A33D` when the damped value reaches **120 mph or above**.

Nothing else on screen may use amber this phase. Not the needle, not the bezel, not the `MPH` label, not any dev panel.

**Why warm off-white and not pure `#FFFFFF`:** D-10 specifies "white numerals on black face". `#F2EFE6` reads as aged/warm instrument printing at gauge scale and holds the 60s–70s tone (D-05's Bullitt anchor), where clinical `#FFFFFF` reads as a modern digital dashboard. Contrast against the dial face is **17.9:1**, far above any threshold.

**Why the needle gets the only high-chroma red:** the needle is the single most important read on screen while driving at 120mph through a corner. It must be separable from the numerals at a glance and in peripheral vision. Giving it the same off-white as the numerals collapses that distinction. It is therefore the *only* element allowed `#C8402F` in the player-facing layer.

**Needle-over-redline legibility:** at 120+ mph the red needle sits on top of the amber band, where red-on-amber contrast is poor. **Mitigation is mandatory:** the needle is drawn as two stacked `<line>` elements — a casing in `#0B0B0C` at stroke-width 7 beneath, and the needle in `#C8402F` at stroke-width 4 on top. The dark casing guarantees separation against amber, off-white ticks, and the dial face alike.

### Supporting instrument values

Not part of the 60/30/10 split — these are low-area structural values inside the Dominant family.

| Element | Value | Notes |
|---|---|---|
| Bezel ring | `#2A2A2E` | 4px stroke at radius 94 |
| Minor tick marks (every 5 mph) | `#6E6E73` | Deliberately dim so the 20-mph majors dominate the read |
| `MPH` unit label | `#9A9AA0` | Contrast 6.9:1 on the dial face — a static label, not live data |
| Digital readout window fill | `#16161A` | Slightly lifted from the face so the inset reads as recessed hardware |
| Digital readout window border | `#2A2A2E` | 1px, matches the bezel |
| Needle casing | `#0B0B0C` | The legibility mitigation described above |

Contrast audit (all against the `#0B0B0C` dial face): off-white `#F2EFE6` **17.9:1**; amber `#E8A33D` **9.4:1**; needle red `#C8402F` **4.6:1** (a 4px graphic element, not text — comfortably above the 3:1 non-text threshold); `MPH` label `#9A9AA0` **6.9:1**.

### Dev-only palette — explicitly excluded from the 60/30/10 contract

The tuning and telemetry panels are constructed only when `DEBUG_ENABLED` is true and therefore **never reach a player build**. They are dev instrumentation, not product surface, and are excluded from the ratio contract by design. They still obey the type scale and the `innerHTML` ban.

| Element | Value |
|---|---|
| Panel surface | lil-gui's own default dark theme, unmodified |
| Telemetry panel surface | `rgba(0,0,0,.62)` — matches `profiler-hud.ts` exactly |

| Telemetry `FAIL` | `#C8402F` (shared with the needle — the only cross-layer reuse) |

## Architecture Calls — closing 02-RESEARCH.md Open Questions 4 and 5

The orchestrator asked for explicit calls so the planner does not have to guess. Both are decided here.

### Call 1 — Debug toggle keys (Open Question 4): **keyed variant, three separate keys**

**Decision:** extend `src/debug/debug-gate.ts` with a keyed variant. Do **not** share one `Backquote` toggle across all three overlays.

```
onDebugKey(code: string, fn: () => void): void      // NEW — the general form
onDebugToggle(fn: () => void): void                 // KEPT — now `onDebugKey("Backquote", fn)`
```

Keeping `onDebugToggle` as a thin alias means Phase 1's call site in `src/main.ts:63` and any existing test remain untouched.

| Key | Toggles | Rationale |
|---|---|---|
| `Backquote` | Profiler HUD | Unchanged from Phase 1 (D-05). Zero regression risk. |
| `KeyG` | Vehicle tuning panel | *G* for GUI. Free — driving uses WASD, arrows and `Space` (handbrake, D-02). |
| `KeyT` | Telemetry results panel | *T* for telemetry. Free. |

**Why not one shared toggle:** the three overlays have genuinely different duty cycles. The profiler HUD is glanceable and often left on; the tuning panel is a large opaque rectangle you want gone the moment you start a feel run; the telemetry panel is transient. Binding them together forces the developer to accept all three or none precisely during the long tuning session this phase exists to enable.

**Mandatory companion fix — the focus guard.** `debug-gate.ts:44-46` already carries a standing note: *"this guard will need extending once a text input exists in a later phase."* **The lil-gui tuning panel is that later phase** — every lil-gui numeric control is a real `<input>`, so typing a `g` or a `t` into a number field would currently fire a toggle mid-edit. `onDebugKey` must therefore bail when the active element is a text-entry target:

```
const el = document.activeElement;
if (el instanceof HTMLInputElement || el instanceof HTMLTextAreaElement ||
    (el instanceof HTMLElement && el.isContentEditable)) return;
```

This closes a live defect note rather than adding speculative work, and it is a hard requirement of shipping the panel.

### Call 2 — Speedometer location (Open Question 5): **create `src/hud/`**

**Decision:** the speedometer lives at `src/hud/speedometer.ts`. Create the directory and add a matching rule to `tests/layering.test.ts` in the same task.

**Rationale:** `src/render/` means "the 3D scene" — meshes, cameras, interpolation. The speedometer is 2D DOM that never touches the scene graph, and Phases 5, 6 and 8 add a minimap, run timer, split deltas, medal display, damage indicator and pursuit HUD. Landing all of that in `src/render/` would erase a real boundary to avoid a one-time ten-line test edit. Pay the ten lines now.

**The rule to add** — model it on the existing `src/render/` block, but make it *stronger*, because a HUD needs even less than the renderer does:

| `src/hud/**` may not | Forbidden pattern | Why |
|---|---|---|
| Import `three` | `from "three"` | The HUD is DOM/SVG, not WebGL |
| Import Rapier | `from "@dimforge/rapier3d"` | The HUD receives plain numbers, never engine handles |
| Write simulation state | `world.step` / `applyImpulse` / `setTranslation` / `setRotation` / `setNextKinematic` | Same guarantee `src/render/` already carries |
| Read a wall clock | `performance.` | `dtMs` arrives as a parameter; the existing repo-wide rule already covers this |

This makes `createSpeedometer` a pure `(numbers) → DOM` module and lets `tests/speedometer.test.ts` cover the mph conversion, the needle-angle mapping and the framerate-independent damping as pure functions — exactly the split `profiler-hud.ts` established with `formatHudText`.

**Signature contract** (composition root does the Rapier read, per the rules above):

```
speedo.update(groundSpeedMs: number, dtMs: number): void
// called once per rAF from main.ts's render callback:
//   const v = vehicle.body.linvel();
//   speedo.update(Math.hypot(v.x, v.z), dtMs);
```

## Speedometer Geometry Contract

Exact values. The executor should not need to make a judgement call here.

**Container:** `<svg>` created via `createElementNS("http://www.w3.org/2000/svg", "svg")`, `viewBox="0 0 200 200"`, appended to `document.body`.

```
position:fixed; right:16px; bottom:16px; width:200px; height:200px;
z-index:5; pointer-events:none;
font-family:"Arial Narrow","Helvetica Neue",Helvetica,Arial,sans-serif;
font-stretch:condensed; font-variant-numeric:tabular-nums;
```

| Element | Geometry | Fill / Stroke |
|---|---|---|
| Dial face | `<circle>` cx 100 cy 100 r 92 | fill `#0B0B0C` |
| Bezel ring | `<circle>` cx 100 cy 100 r 94, stroke-width 4, no fill | stroke `#2A2A2E` |
| Redline arc | `<path>` arc at r 84, from 120 mph to 160 mph, stroke-width 6, `stroke-linecap: butt`, no fill | stroke `#E8A33D` |
| Major ticks (0,20…160 — 9 total) | radial `<line>` from r 92 to r 78, stroke-width 3 | stroke `#F2EFE6` |
| Minor ticks (every 5 mph, skipping majors) | radial `<line>` from r 92 to r 85, stroke-width 1.5 | stroke `#6E6E73` |
| Dial numerals (9 total) | `<text>` centred at r 62, 14px / weight 600, `text-anchor:middle`, `dominant-baseline:central` | `#F2EFE6`; **`120`, `140`, `160` are `#E8A33D`** |
| Needle casing | `<line>` (100,112) → (100,26), stroke-width 7, `stroke-linecap:round` | stroke `#0B0B0C` |
| Needle | `<line>` (100,112) → (100,26), stroke-width 4, `stroke-linecap:round` | stroke `#C8402F` |
| Needle hub | `<circle>` cx 100 cy 100 r 6, stroke-width 1.5 | fill `#2A2A2E`, stroke `#F2EFE6` |
| Readout window | `<rect>` x 69 y 124 w 62 h 32 rx 3, stroke-width 1 | fill `#16161A`, stroke `#2A2A2E` |
| Digital readout | `<text>` at (100,140), 28px / weight 600, `text-anchor:middle`, `dominant-baseline:central` | `#F2EFE6`; **`#E8A33D` at ≥120 mph** |
| `MPH` label | `<text>` at (100,168), 11px / weight 600, `letter-spacing:1px`, `text-anchor:middle` | `#9A9AA0` |

**Needle sweep mapping** — the needle is authored pointing straight up, then rotated:

```
SWEEP_START_DEG = -120      // 0 mph, lower-left
SWEEP_DEG       =  240      // total sweep
MAX_MPH         =  160      // D-12
t     = clamp(mph / MAX_MPH, 0, 1)
angle = SWEEP_START_DEG + t * SWEEP_DEG
needle.setAttribute("transform", `rotate(${angle} 100 100)`)
```

Check values: 0 mph → −120° (lower-left) · 80 mph → 0° (straight up) · 120 mph → +60° · 160 mph → +120° (lower-right). The needle **pins** at both ends via the clamp; it must never sweep past 160 or below 0.

**Redline start: 120 mph.** D-12 sets the 0–160 range specifically so the 120 mph ramp-jump target does not pin the needle. Placing the redline at exactly 120 makes hitting the ramp-jump speed a legible visual event — the needle enters amber precisely when the driver is fast enough for the jump. This is the phase's one piece of expressive design and it is free.

**Both colour switches use the same 120 mph threshold** (redline band start, digits amber), so the instrument tells one story rather than two.

## Interaction & Motion Contract

| Behaviour | Contract |
|---|---|
| Update cadence | Once per `requestAnimationFrame`. **Do not throttle to ~7 Hz like `profiler-hud.ts` does** — a needle updating 7×/sec reads as broken hardware. Cost is 2 `setAttribute` calls + 1 `textContent` write per frame, negligible against the frame budget. |
| Needle response | **Instant, unsmoothed** (D-13). |
| Needle CSS transition | **Forbidden.** A `transition` on the `transform` attribute adds refresh-rate-dependent lag between the physics and the display, and would silently reintroduce the framerate-dependence Phase 1 spent seven plans eliminating. |
| Digit damping | `alpha = 1 - Math.exp(-(dtMs/1000) / DIGIT_TAU_SEC)` with **`DIGIT_TAU_SEC = 0.12`** → ~0.36 s to settle within 95%. Genuinely "slight" per D-13. |
| Why exponential-with-dt, not a fixed lerp | `damped += (mph - damped) * 0.2` per frame smooths ~2.4× harder at 144 Hz than at 60 Hz. The `1 - exp(-dt/τ)` form is refresh-rate-independent and is covered by a dedicated unit test (02-RESEARCH.md Validation Architecture, `-t damping`). |
| Digit rounding | `String(Math.round(dampedMph))`. Damping is applied *before* rounding, so the integer cannot flicker between two neighbours. |
| Zero state | At rest the gauge shows needle at −120° and `0`. This is a valid resting state, not an empty state — it needs no placeholder copy. |
| Responsive behaviour | **None required.** Fixed 200×200 at every viewport size; desktop-browser-first is a project constraint and mobile is explicitly out of scope. |
| Animation elsewhere | **No animations ship this phase.** No pulses, no siren flash, no redline glow. Those belong to Phase 8's heat escalation. |

| Live vs deferred binding | Wheel properties on `.onChange()` (per-frame safe). **`mass` and `comOffset` on `.onFinishChange()`** — Pitfall 10: `setAdditionalMassProperties` invalidates the cached principal inertia the assists scale against |
| Reset button | Last control in the root. `Reset to defaults` with the two-click confirm from the Copywriting Contract |
| Persistence | `gui.onChange` → `localStorage.setItem(JSON.stringify(gui.save(true)))` under key `heat-street.tuning.v1` (D-17) |
| **Load-time validation** | `JSON.parse` inside `try/catch`; on failure `removeItem` and surface `Saved tuning was unreadable — defaults restored.` **Then range-clamp every numeric field against the same min/max the sliders use before applying.** `gui.load()` does not validate — a `NaN` mass propagates into `world.step()` and corrupts every body in the world, not just the car. 02-RESEARCH.md names this the highest-value security control in the phase |

| Property | Contract |

| Surface | `position:fixed`, `z-index:11`, `background:rgba(0,0,0,.62)`, `padding:6px 9px`, `border-radius:4px`, 11px/1.45 `ui-monospace` — deliberately identical to `profiler-hud.ts` so the two read as one tool family |

## Accessibility

| Concern | Decision |
|---|---|
| Screen reader | Gauge root gets `role="img"` and a static `aria-label="Speedometer"`. The live digits are **not** exposed as an `aria-live` region — a value changing 60×/sec would flood any assistive technology into uselessness. |
| Colour independence | Speed is carried primarily by **needle angle**; the amber redline and amber digits are redundant reinforcement, never the sole signal. Telemetry results always print `PASS`/`FAIL` as text. |
| Contrast | All values audited in the Color section. Lowest text ratio is 6.9:1 (`MPH` label); lowest graphic ratio is 4.6:1 (needle, a 4px element against a 3:1 requirement). |
| `prefers-reduced-motion` | **No behaviour change.** The needle's motion *is* the data, not decoration, and this phase ships no decorative animation. Documented so this reads as a considered decision rather than an oversight. |
| Keyboard | Nothing in this phase is focusable or keyboard-operable by design: the HUD is `pointer-events:none`, and the two interactive panels are dev-only tools behind `?debug`. |
| Input conflict | The `KeyG`/`KeyT` focus guard (Architecture Call 1) is what prevents debug hotkeys from firing while typing into a lil-gui numeric field. |
