  readonly chassis: { mass, comOffset {x,y,z}, halfExtents {x,y,z}, linearDamping, angularDamping }

Add three exports to `src/core/vehicle-tuning.ts`.

`export const TUNING_STORAGE_KEY = "heat-street.tuning.v1";` — the key 02-UI-SPEC.md fixes.

`export function clampTuning(t: VehicleTuning): VehicleTuning` — walks `TUNING_RANGES`
recursively and, for every leaf, replaces the value with `Math.min(max, Math.max(min, v))`.
A value that is not a finite number (`NaN`, `Infinity`, `null`, a string, a missing key) is
replaced with the corresponding `defaultTuning()` value, not with `min`. Mutates in place
and returns the same object.

`export function parseSavedTuning(raw: string | null): VehicleTuning | null` — the ASVS V5
control. Returns `null` for `null` input, for a `JSON.parse` throw (wrapped in try/catch),
for a non-object or array top level, and for a parsed object missing any of the four group
keys. Otherwise it starts from `defaultTuning()`, copies over only leaves that exist in the
parsed object at the matching path, runs `clampTuning`, and returns the result. It NEVER
throws and NEVER returns a partially-populated object.

`export function serializeTuning(t: VehicleTuning): string` — `JSON.stringify` of the
tuning object. Plan 02-09 persists this rather than `gui.save(true)`. Record the reason as a
`DEVIATION from 02-RESEARCH.md lines 1019-1033 and 02-UI-SPEC.md "Persistence"` comment:
lil-gui's own save format couples the stored blob to controller paths, and
`three/addons/libs/lil-gui.module.min.js` cannot be imported under Vitest's `node`
environment, which would make the D-17 test in this file unrunnable. Persisting the plain
`VehicleTuning` object keeps the same storage key, the same behaviour, and a pure,
Node-testable validation path.

Each of the three carries a doc comment in `parseDebugFlag`'s style: name the ASVS category
(V5 Input Validation), name the concrete failure being prevented (a `NaN` mass reaching
`setAdditionalMassProperties` corrupts every body in `world.step()`, not just the car), and
state that the input string past the parse boundary is discarded.

Create `tests/tuning-persist.test.ts` with an environment-scope header explaining that
