## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tuning panel -> `localStorage` -> next session | Values written here are read back at boot by the composition root |
| panel -> live `VehicleTuning` -> physics solver | Slider values reach Rapier setters on the next fixed tick |
| `?debug` presence -> existence of a tuning surface | Decides whether an attacker-influenceable control surface exists at all |
| telemetry panel -> throwaway Rapier world | A run must not perturb the live simulation or leak memory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Information disclosure / Tampering | tuning and telemetry panels in a production build | mitigate | Both are constructed ONLY inside the `DEBUG_ENABLED` conditional in `src/main.ts`, and `onDebugKey` itself returns before registering any listener when `DEBUG_ENABLED` is false. A shipped build therefore exposes no tuning surface — required both by ASVS V4 and by REQUIREMENTS.md's medal-time comparability constraint (D-15). |
| T-02-01 | Tampering / DoS | persisted tuning blob written by the panel | mitigate | Every slider is bounded by `TUNING_RANGES`, the same table `clampTuning` uses, so the panel cannot write an out-of-range value; and the boot-time read in `src/main.ts` goes through `parseSavedTuning`, which try/catches and re-clamps regardless of what wrote the blob. |
| T-02-02 | Tampering (DOM injection) | telemetry panel row rendering | mitigate | `document.createElement` + `textContent` + `style.cssText` only; no `innerHTML`, no template strings into the DOM, no DOM tables. Enforced by `tests/layering.test.ts`'s repo-wide scan and asserted here. |
| T-02-07 | Tampering | `KeyG`/`KeyT` firing while typing a tuning value | mitigate | `onDebugKey`'s `isTextEntryFocused` guard (plan 02-05); lil-gui's numeric controls are real `<input>` elements, which is precisely the case that guard was added for. |
| T-02-06 | Denial of Service | repeated in-browser telemetry runs | mitigate | `runRoutine` frees its world in a `finally` (plan 02-07); the panel does not auto-run on open, so a run is always a deliberate button press. |
| T-02-21 | Denial of Service | mass/CoM slider drag | mitigate | `chassis.mass`, `comOffset` and `halfExtents` bind on `.onFinishChange`, not `.onChange` — `setAdditionalMassProperties` overrides all previous additional mass properties and invalidates the cached principal inertia the assists scale against (Pitfall 10). |

An acceptance criterion asserts `package.json` is unchanged. |
