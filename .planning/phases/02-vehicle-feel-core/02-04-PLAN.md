export const FL = 0, FR = 1, RL = 2, RR = 3;   // front pair at -Z, rear pair at +Z

export interface VehicleSample {
  position: {x,y,z}; rotation: {x,y,z,w};
  linvel: {x,y,z}; angvel: {x,y,z};
  groundSpeedMs: number;      // hypot(linvel.x, linvel.z)
  forwardSpeedMs: number;     // linvel . chassisForward
  slipAngleRad: number;       // signed, atan2(lateral, forward)
  tiltDeg: number;            // angle between chassis up and world up
  rollDeg: number;            // asin(chassisRight.y)
  contacts: number;           // wheels touching ground, 0..4
}

export interface Vehicle {
  readonly body: RAPIER.RigidBody;
  readonly controller: RAPIER.DynamicRayCastVehicleController;
  readonly inertia: { x: number; y: number; z: number };
  tick(frame: InputFrame, tuning: VehicleTuning): void;   // once per fixed tick, BEFORE world.step()
  applyTuning(tuning: VehicleTuning): void;               // live retune, no rebuild
  dispose(): void;
}

export function createVehicle(world, tuning: VehicleTuning, spawn: {x,y,z}): Vehicle
export function sampleVehicle(v: Vehicle): VehicleSample

`tick(frame, t)` implements 02-RESEARCH.md Pattern 2 in this exact order, with a comment
stating the order is load-bearing:
  1. `const steerAngle = -frame.steer * t.drive.maxSteerLock`; `setWheelSteering(FL/FR, steerAngle)`.
     Comment the derivation: `InputFrame.steer` is -1 = LEFT / +1 = RIGHT; with forward =
     local -Z, up = +Y and `axleCs = {-1,0,0}`, a POSITIVE `setWheelSteering` angle produces
     a POSITIVE yaw rate about +Y, which turns LEFT — measured `setWheelSteering(+0.2618)`
     -> `angvel.y = +0.25 rad/s`. Hence the leading minus.
  2. `const braking = frame.brake > 0;` then
     `setWheelEngineForce(RL/RR, braking ? 0 : -frame.throttle * t.drive.engineForcePerRearWheel)`.
     Comment Pitfall 7 with its measurement: Rapier's friction solver is
     `if engineForce != 0 { rollingFriction = engineForce * dt } else { ...brake path... }`,
     so a non-zero engine force silently disables the brake on that wheel — throttle + full
     brake together measured 40.1 mph -> 41.1 mph after 2 s, versus 40.1 -> -0.2 with brake
     alone. Zeroing engine force while braking is mandatory, not defensive.
  3. `setWheelBrake(i, frame.brake * t.drive.brakeImpulsePerWheel)` on all four wheels.
  4. rear side friction: `frame.handbrake ? t.drive.handbrakeRearSideFriction :

Term 2, D-06 BODY ROLL, gated on `contacts >= 3 && a.bodyRollGain > 0` AND an absolute
cutoff `Math.abs(rollDeg) < a.bodyRollMaxDeg`. Compute `rollDeg` from
`asin(clamp(right.y, -1, 1))` in degrees. Open-loop magnitude
`m = a.bodyRollGain * I.x * (latAccel - a.bodyRollDamping * rollRate)` where
`latAccel = w.y * dot(v, fwd)` (yaw rate times forward speed) and `rollRate = dot(w, fwd)`.
HARD-CAP `m` to `+/- a.bodyRollGain * I.x * 30` before applying it about the forward axis.
Three mandatory comments here: (a) this assist is POSITIVE FEEDBACK — rolling the body
shifts suspension load, which changes lateral force, which feeds the torque; (b) measured
gain 0.10 gives 5.46 deg of roll (the Bullitt range) and gain 0.20 flips the car onto its
roof, so the cap and the cutoff are not optional; (c) the more elegant-looking formulation —
a PD controller driving actual roll toward a clamped TARGET roll angle — was measured and
flipped the car at every gain and cap tried (4/8/20 deg per g, caps 7 and 12 deg; all
reached ~85 deg and inverted). Do not "improve" this into that form.

Term 3, D-03 SLIDE CATCH, gated on `contacts >= 2 && groundSpeed > 2 && a.slideCatchGain > 0`.

`{x: 0, y: (-slip * kp - w.y * kd) * DT, z: 0}` with `kp = a.slideCatchGain * I.y`,

the handbrake is held; what actually makes slides catchable is restoring
`sideFrictionStiffness` on handbrake release. It matters at the recommended deeper 0.01
setting where slides persist for 1.5-2.5 s.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `VehicleTuning` -> Rapier setters | Values that may have originated in a user-editable `localStorage` blob are written into the solver every tick |
| `InputFrame` -> wheel setters | Device-derived values reach `setWheelSteering` / `setWheelEngineForce` / `setWheelBrake` |
| assist impulses -> chassis body | Unbounded torque is a physics-explosion primitive |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering / DoS | `createVehicle` / `applyTuning` reading a persisted tuning object | mitigate | The tuning object is clamped by `clampTuning`/`parseSavedTuning` in `src/core/vehicle-tuning.ts` (plan 02-01) before it ever reaches this layer; the panel in plan 02-09 is the only writer and binds sliders to the same `TUNING_RANGES`. A `NaN` mass reaching `setAdditionalMassProperties` corrupts every body in the world, not just the car. |
| T-02-05 | DoS / Tampering | `tick(frame, …)` | mitigate | `frame.steer`/`throttle`/`brake` are already clamped finite by `LiveInputSource` (plan 02-02); the `powerOversteerGain` lerp factor is additionally clamped to [0,1] here so a hostile tuning value cannot drive rear side friction negative. |
| T-02-12 | Denial of Service | body-roll assist positive feedback | mitigate | Hard torque cap at `bodyRollGain * I.x * 30`, absolute cutoff above `bodyRollMaxDeg`, and `TUNING_RANGES.assists.bodyRollGain.max = 0.15` (below the measured 0.20 flip threshold).
