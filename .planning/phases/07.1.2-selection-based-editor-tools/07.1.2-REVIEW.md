# Phase 07.1.2: Code Review Report

**Reviewed:** 2026-11-14
**Depth:** standard
**Files Reviewed:** 25
**Status:** issues_found

## Summary

The selection mask, road cut (`eraseGraphMask` / `refineAgainstMask`), lock carry-over, hold-to-repeat
bookkeeping and the locked-road padding (D-23) hold up under review. One real defect was found and
reproduced: cancelling an Alt+drag push/pull leaves unrecorded terrain edits. Other findings are
smaller: input-handling gaps in the hold/push-pull interplay and in the map editor's box select.

Checked and found sound:
- Hold-repeat always ends: `stopOpHold` runs on keyup, pointerup, pointerleave, pointercancel,
  lostpointercapture, window blur, mode/arm change, Esc, clear selection, and a vanished selection.
- Repeat and push/pull each produce exactly one undo entry. `applyOperation` raise/lower/smooth goes
  through begin + end of the same repeat session.
- Every new height write path (`setMaskFromBase`, `flattenMaskToAverage`, `smoothRegion` with `selected`)
  goes through `runHeightOp` with the padded `roadMask`, so none bypass the locked-road hold.
  `paintMask` keeps road-flagged pixels.
- `eraseGraphMask` splits edges and carries the lock state (`carryLock` with `splitFrom`) in one diff.
- Alt: the browser menu is suppressed only when no text field or dialog has focus. Hotkeys are skipped
  while Alt is held.

## Critical Issues

### CR-01: Cancelling push/pull leaves unrecorded height changes outside the selection and clears the dirty flag

**Status:** fixed (378a697)

**File:** `tools/terrain-editor/tool-dispatch.ts:1039-1056`, `tools/terrain-editor/editor.ts:1592-1606`
**Issue:** `cancelPushPull` restores the terrain by running `setMaskFromBase(..., 0, undefined, ...)`.
That only rewrites the selected vertices. During the drag, `runHeightOp` runs `limitSlope` over the
expanded `dirty` window, which also moves unselected neighbours beside the cliff (the recorder
captures them, which is why Ctrl+Z works after a committed push/pull). Cancel therefore restores the
selected vertices but leaves every limiter-adjusted neighbour changed. There is no undo entry for
them, and the editor then calls `setDirty(false)` when the map was clean before the drag.

Reproduced with a scratch vitest (240 m flat area, 3 m cells, select 60 m x 60 m,
`beginPushPull(); pushPullTo(20); cancelPushPull()`): 84 vertices differ from the original, and
`canUndo()` is false. Esc, `pointercancel` and `selectTool` / dialog-open all route through this
function, so the effect is silent terrain corruption plus a lost unsaved-changes warning.

**Fix:** Revert from the recorder's own diff rather than re-deriving the heights. Commit the recorder
and apply its inverse, or snapshot the full `dirty` window before the first write. For example:
```ts
cancelPushPull(): ToolResult {
  const pp = pushPull;
  if (!pp) return emptyResult();
  pushPull = null;
  const area = getArea();
  const diff = pp.recorder.commit();
  const res = emptyResult();
  if (!diff?.heights) return res;
  const tmp = createUndoStack(1);
  tmp.push(diff);
  const r = tmp.undo(area);          // writes the `before` values back, including limiter-moved neighbours
  res.dirtyHeights = r ? r.heightsWindow : undefined;
  return res;
}
```
Add a test asserting the entire `grid.heights` array is identical after cancel (the current test only
compares the selection window, which is why it passes).

## Warnings

### WR-01: Alt+drag push/pull and canvas input are not guarded against an active hold-repeat

**Status:** fixed (33b58e5)

**File:** `tools/terrain-editor/editor.ts:1614-1626`, `tools/terrain-editor/tool-dispatch.ts:989-1003`
**Issue:** `startOpHold` refuses while `stroking` or `pushPull`, but the reverse guard is missing. With
a key hold active (hold H), an Alt+pointerdown starts push/pull, and `beginPushPull` only checks
`stroke`, not `repeat`. Two recorders then write the same vertices from different bases, and the two
undo entries no longer compose (the second one's `before` snapshot includes the first one's partial
result). Similarly, `applyOperation` calls `endOpRepeat()` and drops its result while the editor's
`opHold` and repeater stay alive until keyup.
**Fix:** In the editor's Alt branch, return when `opHold` is set (or call `stopOpHold()` first). In
`beginPushPull`, call `this.endOpRepeat()` when `repeat` is set. In the `runToolbarAction` "apply"
branch, call `stopOpHold()` first so the repeater and the dispatcher cannot diverge.

### WR-02: Map editor: Ctrl+drag with no selection selects instead of doing nothing

**Status:** fixed (06277dd)

**File:** `tools/map-editor/editor.ts:1179-1183`
**Issue:** `if (mode === "replace" || boxes.length === 0) boxes = [{ ...entry, mode: "replace" }]`. A
subtract box drawn with an empty selection is rewritten to "replace", so Ctrl+drag on nothing selects
everything in the box. The terrain editor handles the same case correctly (subtract on an empty mask
leaves it empty). `selectionFromBoxes` would already give an empty result for a leading subtract.
**Fix:** Only force replace for the `replace` mode. For `subtract` with no boxes, ignore the drag.
For `add` with no boxes, store it as `replace`.

### WR-03: Map editor: box mode is read from two different events

**Status:** fixed (fd72a09)

**File:** `tools/map-editor/editor.ts:1120-1122`, `tools/map-editor/editor.ts:1179-1181`
**Issue:** The live rubber-band colour uses `liveMode`, captured once at mousedown. The committed
mode uses `modeOf(e)` from the mouseup event. If the user releases or presses Shift/Ctrl during the
drag, the preview shows one operation and a different one is applied. The terrain editor snapshots
modifiers once at pointerdown for both preview and commit.
**Fix:** Use `liveMode` in the mouseup handler instead of `modeOf(e)`.

### WR-04: Map editor: selection boxes persist after Delete, so later edits silently re-select items

**Status:** fixed (dd06bad)

**File:** `tools/map-editor/editor.ts:956-980`, `tools/map-editor/editor.ts:922-935`
**Issue:** `boxAction("delete")` leaves `boxes` populated. `refresh()` now calls `recomputeBox()`
unconditionally, and the empty-result reset only fires when the last box is a subtract. After a delete
the sidebar still shows the box panel with zero items. Undo, or drawing a new road or building through
the old box, re-selects whatever now falls inside it, so a following Delete or Disable can hit items
the user never selected.
**Fix:** Clear `boxes` (call `clearMapSelection()` or `clearBox()`) after a successful delete, and in
`recomputeBox` reset `boxes` whenever the hit set is empty, not only after a subtract.

## Info

### IN-01: Brush mode with no armed operation shows a live footprint ring but clicks do nothing

**Status:** skipped (out of requested scope; UI-state design choice left to the owner)

**File:** `tools/terrain-editor/editor.ts:2290`
**Issue:** `syncToolFromDispatcher` maps "brush mode, nothing armed" to `"raise"`, so the editor draws
the raise footprint ring, grid and zoom hint, while the dispatcher's `activeTool()` is `null`
(status "Pick an operation"). The UI suggests Raise is armed.
**Fix:** Treat unarmed brush mode as a distinct state (no ring, `tool = "select"`-like idle), or arm
Raise by default when the Brush button is first pressed.

### IN-02: Switching mode or tool mid-drag commits the in-progress selection box

**Status:** fixed (c264a8d)

**File:** `tools/terrain-editor/tool-dispatch.ts:622-625`, `tools/terrain-editor/editor.ts:2102-2115`
**Issue:** `setMode` and `armBrush` call `pointerUp(NaN, NaN)`, which for a select stroke applies the
box using the last position. Pressing B or a hotkey during a rubber-band drag changes the selection,
while Esc cancels it. Likely unintended, since the drag has not been released.
**Fix:** For `stroke.tool === "select"`, drop the stroke (as `cancelSelectDrag` does) instead of
committing it on a mode change.

### IN-03: `createRepeater.start` can leave `running()` true with no timers

**Status:** fixed (3ac849b)

**File:** `tools/editor-shell/repeat.ts:36-44`
**Issue:** `on = true` is set and `o.tick()` runs before the timers are created. If `tick` throws, the
repeater reports running but nothing is scheduled.
**Fix:** Schedule the timers first and then call `o.tick()`, or wrap the first tick in `try/catch`
and call `stop()` on failure.

### IN-04: Naming and comments around reused block constants

**Status:** skipped (out of requested scope; naming/comment cleanup)

**File:** `tools/terrain-editor/tool-dispatch.ts:13-14`, `src/core/terrain-cell-mask.ts:55-62`
**Issue:** The Select-mode step limits reuse `BLOCK_STEP_MIN_M` / `BLOCK_STEP_MAX_M` from the removed
Block tool, so a future cleanup of the (kept-only-for-golden-tests) block code would break the step
clamp. `cellBoxFromWindow` is documented as a conversion to a half-open cell box but is an identity
copy (correct, because the maximum vertex index equals the exclusive cell bound), which is confusing.
**Fix:** Define `SELECT_STEP_MIN_M` / `SELECT_STEP_MAX_M` in the dispatcher or core. Reword the
`cellBoxFromWindow` comment to say that vertex max equals the exclusive cell max.
