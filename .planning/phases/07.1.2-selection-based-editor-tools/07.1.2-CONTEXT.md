# Phase 07.1.2: Selection-based Editor Tools - Context

**Gathered:** 2026-11-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Rework the terrain editor into a select-then-act model like SketchUp. A **mode** (Select or Brush) decides *where* an edit applies. One set of **operation** buttons (Raise, Lower, Smooth, Flatten, Terrain) decides *what* it does. These replace today's overlapping single-purpose tools.

Layout follows the user's mockup `screenshots/ToolsLayout.png`:
- Tool buttons float over the top-left of the view.
- The left sidebar stays, with the active tool's name in large text and its options.
- The bottom toolbar is removed.

The map editor adopts the same conventions wherever the same control applies. The phase also fixes the bug where edits next to a locked road warp the road's edges.

07.1.1's shared shell is kept: the sidebar, compact value boxes, tooltips and canvas offset. Its bottom-toolbar arrangement and tool list are superseded. 07.1.1 UAT is skipped; its sidebar, value-box and tooltip behaviours get re-checked in this phase's UAT.

**Out of scope:** the feature palette for buildings, ramps and scenery is Phase 07.1.3.

</domain>

<decisions>
## Implementation Decisions

### Modes: Select vs Brush
- **D-01:** **Select** (renamed from Grid select) and **Brush** are separate mode buttons, side by side in the floating toolbar.
- **D-02:** **Brush mode:** clicking an operation makes it the active brush, and it stays highlighted. Dragging on the map applies it under the cursor, as today's brushes do.
- **D-03:** **Select mode:** operation buttons act on the selection immediately. The buttons look disabled when there is no selection.
- **D-04:** **Selection drawing:**
  - A plain drag replaces the selection with a new box.
  - **Shift+drag adds** a box, so L-shapes and other irregular areas are possible.
  - **Ctrl+drag subtracts** a box.
  - The selection is therefore a union of rectangles minus rectangles, held as a cell mask.
- **D-05:** **Push/pull** (drag up/down to move the selection by hand, today Ctrl+drag) moves to **Alt+drag**. Stop the browser's Alt menu-bar behaviour while the editor has focus.
- **D-06:** The selection **persists across mode switches**. It shows faintly in Brush mode and is live again on return to Select. It is cleared only by **Clear selection** or Esc.
- **D-07:** **Undo** covers terrain and road changes only. Selection changes are not undo steps.

### Operations
- **D-08:** **Raise/Lower** is a big ▲▼ pair with text labels, as in the mockup.
  - In Select mode, each click moves the selection by **Step** metres, and holding auto-repeats.
  - The selection moves with a **hard step**: cells move exactly and a cliff forms at the edge. The user smooths afterwards.
- **D-09:** **Flatten** on a selection levels every selected cell to the selection's **average height**.
- **D-10:** **Smooth** on a selection runs **one pass per click** at the sidebar's Strength. Holding repeats.
- **D-11:** **Terrain** replaces "Paint" and "Paint Terrain". It uses one shared surface picker: swatches for tarmac, gravel, grass and the rest, in the sidebar.
  - In Select mode it fills the selection with the current surface.
  - In Brush mode it is the surface brush.
  - There is no separate Paint Terrain button.
- **D-12:** **Option values are separate per mode.**
  - Select mode's sidebar shows Step (metres per click), plus Strength for Smooth.
  - Brush mode uses Radius, Strength and Falloff.
  - Each value is remembered on its own.
- **D-13:** Operations on a selection never move a **locked road**. Locked road cells and their edges stay put while the terrain around them changes. Unlock a road to move it.

### Road tools
- **D-14:** Road controls are separate floating buttons, in a column under Raise/Lower as in the mockup:
  - **Paint**: the road brush, drag to draw.
  - **Erase**: road eraser under the cursor.
  - **Lock** and **Unlock**: two buttons, each setting every road inside the selection one way.
  - **Delete road**: deletes the roads inside the selection.
- **D-15:** **Delete road cuts roads at the selection edge.** Only the road inside the selection is removed; the parts outside stay and end at the boundary. Undo reverts it in one step.
- **D-16:** Paint and Erase are brushes only. Delete road is the selection version of Erase.

### Removed tools
- **D-17:** **Block**, **Smooth box** and **Stamp/Wedge** are removed. Block and Smooth box are covered by Select plus the operations. The user dropped Wedge, because the other tools cover ramps.

### Layout (mockup)
- **D-18:**
  - **Floating toolbar:** top-left over the view. It holds Select, Brush, the brush controls, Grid, Contours and the operation buttons, with Raise/Lower and the road column below.
  - **Bottom toolbar:** removed.
  - **Sidebar:** the left sidebar from 07.1.1 stays. It shows the active tool or mode name in large text, then its options.
- **D-19:** **Brush size and shape** float next to the Brush button: a compact size value box and a Square/Circle toggle. Strength and Falloff stay in the sidebar.
- **D-20:** **Grid** and **Contours** are toggle buttons in the floating row, each with a small granularity value box beside it, visible in both modes.
  - The Grid value is **line spacing in cells** (1, 2, 5, 10…). It only affects the display; the terrain cell size doesn't change.
  - The Contours value is the contour interval.
  - These controls move out of the right-hand view pad.
- **D-21:** Top-right: Undo and Redo, with **Clear selection beside Clear all** (Clear all keeps its meaning). The view pad and info panel stay on the right.

### Map editor conventions
- **D-22:** The map editor adopts all four shared conventions:
  - Floating tool buttons at top-left, with no bottom toolbar.
  - The same sidebar layout with the big tool name.
  - Box-select of roads and features, with Shift to add and Ctrl to subtract, then Delete removes the selection.
  - The same Grid toggle and spacing control.

### Bug
- **D-23:** **Locked roads must be completely untouched by surrounding edits.** Today, sculpting extreme slopes beside a locked road can warp the road's edges. Root-cause it in research, and fix the car-side logic, not the map. This is the same guarantee as D-13 and applies to every brush and selection operation.

### Orchestrator decisions after research (user away 2026-11-14, pending UAT confirmation)
- **D-24:** Hard step (D-08) still obeys the **slope limiter**. Steps steeper than the limit are clamped, with the existing status message. The limit can be raised in the sidebar.
- **D-25:** Lock and Unlock apply to **whole road edges** that touch the selection, without splitting. Delete road (D-15) does split.
- **D-26:** **Delete road deletes locked roads too**, matching today's Erase. Undo restores them.
- **D-27:** The removed Lock tool's other actions move to a **Roads section in the sidebar**, visible in Select mode:
  - Re-grade unlocked roads in the selection
  - Re-grade all unlocked
  - Lock all
  - Unlock all
  - the locked/unlocked counts

  Single-road click-to-lock and Shift+click road select are dropped; select a box around the road instead. The save guard's "re-grade or lock" message must point to these buttons.
- **D-28:** Flatten's average **includes locked-road vertices**, but those vertices themselves don't move.
- **D-29:** **Hotkeys:**
  - S Select, B Brush
  - H Raise, J Lower, G Smooth, F Flatten, P Terrain
  - R road Paint, E Erase, L Lock, U Unlock, Delete key for Delete road
  - C Contours, plus a Grid key

  The hotkey test keys on `code`.
- **D-30:** The D-23 fix makes a ring about one cell wide beside each locked road untouchable while the road is locked. This is accepted, and it's in the UAT checklist for the user to confirm.
- **D-31:** Per-mode option values persist as today's options do. The map editor's Grid spacing is in metres.

### UAT round 1 layout revision (user, 2026-11-14): supersedes D-14 column, D-18..D-21 placement
- **Guiding principle:** a full editing suite with unobtrusive but accessible controls, each placed next to what it affects.
- **D-32:** **One slim top bar** over the top of the view replaces the multi-row floating block. Left to right:
  - [Select][Clear selection]
  - [Brush]
  - [▲/▼] Raise/Lower as a compact stacked pair
  - [Smooth][Flatten]
  - [Terrain ▾][Road ▾]
  - [Grid][Contours]
  - [Undo][Redo]
- **D-33:** **Road ▾** is one button. Clicking it opens a drop-down below it with Paint road, Erase road, Lock, Unlock and Delete road. The drop-down **closes as soon as one is picked**, and also closes on Esc or an outside click. The button shows which road tool is active.
- **D-34:** **Terrain ▾** opens a surface swatch drop-down in the same way. Picking a surface fills the selection in Select mode, or arms the surface brush in Brush mode. Surface swatches **never** appear in the Brush panel. The sidebar shows the current surface only while Terrain is the active tool.
- **D-35:** **Brush options live in the left sidebar:** Shape (Circle/Square), Size, Strength, Falloff and Slope limit. **No value boxes float on the toolbar.** This replaces D-19.
- **D-36:** **Clear selection sits next to Select.** **Undo and Redo move into the top bar.** The top-right history pad is removed from the terrain editor. The view pad and info panel stay on the right.
- **D-37:** **Grid and Contours are plain toggles** in the top bar. Their spacing and interval values move to the sidebar under a "View" section, shown in every mode. This replaces D-20's floating value boxes.
- **D-38:** The **map editor** follows the same conventions (D-22):
  - one top bar with its tools
  - Select with Clear selection beside it
  - a Grid toggle
  - Undo/Redo
  - Clear all next to Clear selection
  - its "Open in terrain editor" button

  Grid spacing goes in the sidebar View section.

<code_context>
## Existing Code Insights

### Reusable Assets
- `dispatcher.raiseSelection(sign)` and the `selectStepM` option: Raise/Lower on a selection already exists for a single rectangle. Extend it to a mask.
- `brushShape` round/square already exists (`footprintShape`). It becomes the floating Square/Circle toggle.
- The grid and contour overlays and `contourInterval` (plus the dialog) already exist. Expose them as floating toggles with value boxes.
- `setRoadLock(area, ids, locked)` and `lockAll(...)`: lock or unlock a set of road ids. Feed it the ids inside the selection.
- `runLockAction(...)`: the wrapper for one-undo-step actions.
- `createStepper` value box and `createButton` from 07.1.1.

### Established Patterns
- Tool lists are data-only modules (`rail-tools.ts`, `map-tools.ts`) with node unit tests. Hotkeys dispatch through `TOOL_KEYS[e.code]`.
- Pure logic is split out and node-tested. The selection mask union/subtract, the average-height flatten and the road cut-at-edge geometry are good candidates.
- Every control has `data-tip`. All DOM text goes through `textContent`.
- Unlocked roads must be re-graded or locked before saving (save guard).

### Integration Points
- `rail-tools.ts` changes from flat tools to modes plus operations plus road tools. `tool-dispatch.ts`'s `Tool` type changes with it.
- The shell's `createToolRail` dock top/bottom split is replaced by a floating toolbar container over the canvas.
- Road graph edits: Delete road with a cut at the selection edge needs edge splitting in the road graph.

</code_context>
