<task id="1" name="Align ramps">
In the selected-ramp panel add an "Align" group with three actions. Each asks the user to click a
second ramp (info bar: "Click the ramp to align to", Esc cancels), then applies ONE undo step to the
selected ramp only, through the existing ramp guards (a refused result changes nothing and says why):
1. "Face" — turn the selected ramp to point straight at the other ramp, and turn nothing else, so the
   pair forms a jump when the other ramp faces back. Offer "Face each other" as the same action with
   Shift held or as a second button if it fits: it also turns the target to face the selected ramp,
   still as one undo step.
2. "Match heading" — give the selected ramp the same heading as the other ramp (parallel ramps).
3. "Line up" — slide the selected ramp sideways onto the other ramp's centre line (the line through
   the other ramp along its heading) without changing its distance along that line, so two ramps sit
   exactly in line for a jump.
While waiting for the second click, draw a thin accent guide line along the target candidate's centre
line under the cursor. Put the geometry in pure, unit-tested functions (headings wrap correctly,
coincident ramps are refused, the selected ramp's size is unchanged).
</task>

<task id="2" name="Snap to grid; grid shown only with snap">
- Add a "Snap" toggle in the top bar next to Grid, with a grid-size choice (1, 2, 5, 10 m; default
  5 m) in a small drop-down on the same control. Remember both in the existing editor prefs.
- When Snap is on: placing and moving point scenery, buildings, ramps and start points snaps the
  position to the grid; hedge/fence line points snap; building and ramp rotation from the wheel,
  arrows and Rotation field is unaffected. Holding Alt while placing or dragging bypasses snap.
  Snapping happens before the placement guards run, so refusals still apply to the snapped spot.
- Road tools: snap road node placement and node drags too IF the road tools have a single clear
  point where the cursor position enters; if that is not a contained change, leave roads unsnapped
  and say so in the SUMMARY.
- The drawn grid follows the snap size when Snap is on. Grid display defaults to OFF for new
  sessions; turning Snap on turns the grid on, turning Snap off leaves the Grid toggle as the user
  last set it. Do not remove the Grid toggle.
- Game: check whether the game itself draws a grid on terrain maps by default. Do NOT change the
  game; report what you find (where it is drawn, what controls it) in the SUMMARY so the user can
  decide.
- Pure, unit-tested snap helper (negative coordinates, half-way rounding, bypass flag).
</task>

<task id="3" name="Contours-only view">
Add a view mode that hides the terrain surface colours/textures and road paint and shows the
landscape as contour lines only, on a plain dark ground so the shape of the whole map reads at a
glance. Make it a third state of the existing Contours control (Off / Contours / Contours only) or a
View menu entry "Contours only" with a hotkey that passes the existing hotkey audit test — whichever
fits the existing top-bar code with least disruption. In this mode: index contours every fifth line
are brighter/thicker (where line width is not available, brighter), scenery, ramps, start markers and
road centre lines stay visible so the user can still orient, and all tools keep working. It is a
display mode only: nothing about it is saved into the map. Remember the choice in editor prefs.
If the existing contour rendering is a shader/texture overlay on the terrain material, implement
"only" by swapping the terrain base colour to a flat dark colour while contours stay on, rather than
writing a new renderer.
</task>
