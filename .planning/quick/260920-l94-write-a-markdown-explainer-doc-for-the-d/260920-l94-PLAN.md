<objective>
Two debug-only deliverables for the developer's ongoing hand-tuning session:

1. **Export / import on the live tuning panel** — snapshot the current values of all three
   tuning objects to a file and load one back, so a good feel can be saved and a bad experiment
   recovered from without hunting through `localStorage` or re-typing 72 sliders.
2. **`docs/vehicle-tuning-guide.md`** — an explainer covering every control the panel actually
   exposes: what it represents, its live-panel range, and (the part that matters) how it
   interacts with the other controls.

Purpose: the panel exposes 72 numeric controls whose interactions are documented only as long
doc comments scattered across three `src/core/` modules, and whose only persistence is an
auto-overwriting `localStorage` write on every change — no undo, no snapshot, and no single
place to read how `rearSideFriction`, `powerOversteerGain`, `handbrakeRearSideFriction` and the
per-surface `lateralGrip` compose into one final wheel friction value.

Output: one new pure core module, one new debug-panel feature, one new markdown guide, and
three test files (one new suite, one new mirroring gate, one entry added to an existing suite).

NON-GOALS, explicitly: no change to `defaultTuning()`, `defaultSurfaceProfiles()` or
`defaultCameraTuning()` values (the developer owns that hand-tuning directly through the panel);
no change to any physics, render or camera behaviour; no new npm package.
</objective>
