## Decisions Made

See `key-decisions` in the frontmatter above — summarised:
- Import validation reuses the existing per-domain `parseSavedX` pipelines exactly, adding zero new validation surface (re-stringify-and-delegate).
- Per-domain independence (not all-or-nothing) on import, mirroring the shipped three-`localStorage`-key rationale.
- `writeDefaultsOnto` renamed `writeLeavesOnto` since it now serves two callers (reset and import).
- Three `localStorage` writes factored into a shared `persistAll()` helper.
- The guide-sync test's ">=70 controls" floor is met by combining a static-source-text regex extraction (62 literal `addNumber` call sites) with the 12 real per-surface runtime controls derived directly from `SURFACE_TYPES` — a static regex alone cannot see a loop's runtime iteration count.

## Deviations from Plan

None — plan executed exactly as written across all three tasks. Two implementation details were resolved by direct investigation rather than being left ambiguous, both purely internal to the two new test files and not deviations from the plan's stated behavior:

1. Vitest/Biome must be invoked from the worktree root, not the path literally written in the plan's `<verify>` blocks (`D:/Projects 2/Heat Street`) — that path is the main repo checkout, and `vitest.config.ts`'s own `.claude/worktrees/**` exclude means files created inside this worktree are invisible from there. Every verify command was re-run from the worktree root instead; behavior and pass/fail outcomes are unaffected.
2. Two doc-comment phrasings in `src/debug/tuning-panel.ts` (which described `innerHTML` and `writeDefaultsOnto` by their literal old names) initially tripped the plan's own literal-substring grep gates (`grep -c 'innerHTML'` / `grep -c 'writeDefaultsOnto'` must be zero) despite the underlying code already satisfying the rule. Reworded both comments to describe the forbidden pattern/old name by behavior rather than the literal identifier, matching this repo's own established convention (STATE.md's `[Phase 02-03]` decision) for exactly this situation.

## Issues Encountered

The guide-sync test's first draft counted only literal `addNumber(...)` call SITES in the panel source (62), which undercounts the Surfaces folder's loop-generated controls (12 real controls from one call site executed six times) and fell short of the plan's own >=70 floor. Fixed by deriving the Surfaces folder's 12 real per-surface identifiers directly from `SURFACE_TYPES` (matching how the panel itself builds them) and combining that with the regex extraction — final combined count 74, comfortably clearing the floor, and the per-identifier presence assertions now correctly cover all real controls rather than only the two raw literal keys (`forwardGrip`/`lateralGrip`) the loop body's source text contains.
