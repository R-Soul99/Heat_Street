<tasks>

<task id="1" name="Contextual left pane">
When exactly one placed item is selected in Select mode (ramp, building, tree, bush, hedge, fence,
start point), the left pane shows ONLY that item's panel: a title naming the kind, its controls, the
scenery triangle count, and a short hint line. The general Select-mode sections (Step, Slope limit,
box-selection actions, the collapsed Start points list and so on) are not shown while an item is
selected; they come back when the selection clears. When a Place kind is armed the pane shows only
that kind's options (already the case — verify nothing unrelated is appended below it).
The selected-item panel must fit without scrolling at a 900 px tall window for every kind.
Keep the panel-choice logic pure and unit-tested (extend `toolbar-state.ts` or add a small pure
module: given mode, placing kind and selection kind, return which sections to show).
</task>

<task id="2" name="Rotation field">
In the selected-item panel for every rotatable kind (building, ramp, tree, bush) add a "Rotation"
stepper in degrees, 0 to 359, step 1, wrapping, that also accepts a typed value. It goes through the
same pure rotate function and the same refusal rules as the arrow keys, and a held stepper is one
undo step. Show the hint "Left/Right 15°, Shift 1°" beside it. For the Building placement options the
existing Rotation control must accept typed 1-degree values too.
</task>

<task id="3" name="Save As">
Add File > "Save as…" (Ctrl+Shift+S). It opens a dialog asking for a new area name, validated with
the same rules as New area, and refuses a name that already exists (no overwrite). It writes the
current state as a NEW area (sidecar and height file, via the existing save endpoint) and leaves the
original area's files untouched, then switches the editor to the new area so later Ctrl+S saves go
there. Plain Save keeps its current behaviour. If the dev-server terrain plugin needs a small change
to create a new area from the editor's current state, make it there with a test. Do not register the
new area in any generated map list the user has uncommitted changes in (see hard rules); if the game
needs a list entry to drive the new area, say so in the SUMMARY instead.
</task>

<task id="4" name="Always-visible Drive button">
Add a small "Drive" button at the right end of the editor top bar, visible in every mode. Click runs
the existing Drive from behaviour (selected start point, else the default start point). When the map
has no start point it falls back to Drive here at the view centre and says so in the info bar. Its
tooltip names the start it will use and the D shortcut. The existing sidebar "Drive from: …" button
and the File menu entries stay.
</task>

<task id="5" name="Brush applies while held">
For the brush tools that add or remove height or smooth (raise, lower, smooth, and flatten if it is a
brush), holding the pointer button down keeps applying the brush at a steady rate even when the
pointer does not move, using the existing strength setting as amount per second so a moving stroke
and a held stroke feel consistent. The whole press, held and moved, stays ONE undo step. Paint-type
brushes (surface paint, road paint, erase, lock) are unchanged: holding still must not re-apply them.
Put the timing/accumulation in a pure, unit-tested helper (fixed tick, clamp long frames) and stop
the timer on pointerup, pointercancel, pointerleave, Esc, dialog open and window blur.
</task>

</tasks>
