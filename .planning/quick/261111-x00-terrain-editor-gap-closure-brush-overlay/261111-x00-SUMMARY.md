# Quick 261111-x00: Terrain editor gap closure (brush footprint, overlays, dock layout)

Brush footprint and overlays rewired around the exact cursor hit point, plus an opt-in dock layout for the terrain editor.

## Confirmed root cause of the grid offset

Confirmed by reading `rebuildOverlays` / `maybeRebuildOverlays` in `tools/terrain-editor/editor.ts`:

1. **Primary.** The grid was a fixed 64-cell patch centred on `overlayCentre`. `maybeRebuildOverlays` only re-centred it once the cursor had moved more than `OVERLAY_RECENTRE_CELLS` (16 cells, 48 m at 3 m cells). So the patch lagged the cursor by up to 16 cells by design, and it was rebuilt wholesale on each re-centre (the "laggy big patch").
2. **Secondary (half cell).** The patch centre used `Math.round` (nearest vertex) while `blockWindowAt` uses `Math.floor` (containing cell), so the two disagreed by up to half a cell.
3. **Secondary (parallax).** Grid lines sat at +0.05 m with depth test ON; the ring sat at +0.15 m with depth test OFF. At oblique angles the grid was partly hidden and shifted against the ring.
4. **Ruled out.** `raycastTerrain` uses the same triangle diagonal and indexing as the mesh, the renderer size and camera aspect both come from `wrap.clientWidth/Height`, and the hit point lies on the surface. These are not at fault.

Fix: the grid is now computed from the exact hit point under the active footprint only (`footprintGridSegments`), cached on the footprint cell window (cursor quantised to half a cell for round shapes), and drawn with the outline and ring at the same lift (0.15 m) with depth test off. Regression test: "window is centred on the true cursor point (grid-offset regression)" in `tests/terrain-overlay.test.ts`.

## What changed

- `src/core/terrain-brush.ts`: `BrushShape`, `brushDistance`, `stepRadiusCells`; raise/lower/smooth/flatten/paint honour `shape` (square = Chebyshev). Round stays the default, so existing tests and goldens pass unchanged.
- `src/core/terrain-overlay.ts`: `brushFootprintWindow`, `footprintGridSegments`, `footprintOutline`, `contourIntervalForZoom`; `gridLineSegments` gained an optional lift.
- Dispatcher: `brushShape` option (validated to round/square).
- Editor: yellow footprint (amber while the slope limiter clamps), Shape select, separate Grid and Contours buttons with pressed state, Alt+wheel radius in whole cells (block size on Block), zoom-scaled contour interval with "Contours every N m" status, base-interval dialog wording.
- Dock layout (Task 3) as an opt-in `layout: "dock"` of the shared shell.

## Deviations from Plan

- **Square grid segments.** The plan said both "only edges whose midpoint is inside the footprint" and "square count equals gridLineSegments over the same window". For an unaligned cursor these conflict, so square emits every edge of the cells the square touches (matches the window test) and round filters by midpoint.
- **Round grid cache key.** The plan said to cache on the cell window only. A round footprint's edge set also depends on the exact cursor spot, so the key also includes the cursor quantised to half a cell (still no rebuild while moving inside the same half-cell).
- **`OVERLAY_RECENTRE_CELLS`** is gone as named. The plan also said to keep the contour re-centre logic, so it lives on as `CONTOUR_RECENTRE_CELLS` for contours only.
- **Brush-grid skip.** Footprint grid is hidden when cells are below the zoom-hint size or the window exceeds 160 cells per side (T-x00-01).
- RED/GREEN for Task 1 and the dock helpers were written test-and-code together before the first run; the first test run only failed on a wrong `createPaintMap` signature in my test.

## Layout notes for the visual check

- **"Vertically along the bottom".** The user's note said vertically, but the mockup (yellow box 3) shows a wide strip along the bottom, so the other tools are a horizontal row of upright buttons at bottom-left (wraps if the window is narrow).
- **D-01 / D-02.** Dock is an opt-in variant inside the same shared shell module, not a second layout module. The map editor passes no `layout`, stays on the classic D-01 layout, and `tools/map-editor` is untouched.
- `#road-problems` moved to the left edge (top 40 px) because the view pad now owns the top-right.
