  <behavior>
    Tests build small synthetic Uint8Array luminance grids (0 = black road, 255 = white) with helpers in the test file (draw thick line, draw ring, draw polyline with a radius) and assert:
    - threshold: luminance below threshold -> 1, at/above -> 0; threshold is adjustable (same grid with threshold 100 vs 200 gives different masks for mid-grey pixels).
    - skeletonize: a 1 px, 5 px and 15 px horizontal stroke of the same line all reduce to a single row within 1 px of the stroke centre; result is one pixel wide (no pixel has two 4-connected skeleton neighbours that are also 4-connected to each other, i.e. no 2x2 blocks and no staircase corner pixels).
    - thick-vs-thin: a ring drawn at stroke 3 px and 11 px gives skeletons whose pixels are all within 1.5 px of the other's.
    - loop: an isolated ring traces to exactly one closed path with no dead ends, represented as at least two paths between at least two nodes (never a path whose start node equals its end node with no other node), so the compiler sees no self-loop edge.
    - T-junction: traces to 4 nodes (1 degree-3 junction, 3 endpoints) and 3 paths; the junction node lies within 2 px of the true meeting point.
    - crossing (X and +): traces to exactly ONE degree-4 junction node (nearby junction pixels clustered/merged within mergeJunctionPx) and 4 paths.
    - diagonal line: a 45 degree and a 30 degree line each trace to a single path between 2 endpoints; after simplifyPath at 1.5 px the 30 degree line has 2 points (stair-steps gone).
    - spur pruning: a long line with a 4 px side spur loses the spur at minSpurPx 10 and the two halves merge back into one path (degree-2 node removed); a 30 px branch survives.
    - speck removal: isolated black blobs smaller than minComponentPx disappear before thinning.
    - simplifyPath (Douglas-Peucker) keeps endpoints and drops collinear points; smoothPath (Chaikin) keeps both endpoints exactly and reduces the max turn angle of a right-angle zigzag.
    - imageToRoadGraph on a ring with two crossing chords returns only junction and endpoint nodes, all paths have >= 2 points, and path endpoints reference node ids that exist.
    - performance: a 2000 x 1000 grid with ~12 px thick strokes (ring + grid of lines) completes imageToRoadGraph inside the test timeout (set 20 s) — this is the user's real picture size class (1.96 km at ~1 m/px).
  </behavior>
  <action>
Create `tools/map-editor/image-trace.ts`: pure TypeScript, NO DOM, no fs, no new dependency (hand-written algorithms; a dependency is not justified for ~400 lines of classic image processing). Everything is in PIXEL units; metres never appear here. Pixel (col, row) with row 0 at the top of the image; points are `{ x: col + 0.5, y: row + 0.5 }` (pixel centres).

Export types `TraceOptions` and `RoadGraphPx = { nodes: { id: number; x: number; y: number; degree: number }[]; paths: { a: number; b: number; points: { x: number; y: number }[] }[] }` (paths include their endpoint node positions as first/last point) and `DEFAULT_TRACE_OPTIONS = { threshold: 128, minComponentPx: 20, mergeJunctionPx: 4, minSpurPx: 12, simplifyPx: 1.5, smoothIterations: 2 }`.

Functions (each exported for tests):
1. `threshold(lum: ArrayLike<number> /* 0..255 */, w, h, level): Uint8Array` -> mask 1 = road (dark).
2. `removeSpecks(mask, w, h, minPx)`: 8-connected flood fill (iterative stack, not recursion) drops components smaller than minPx.
3. `skeletonize(mask, w, h): Uint8Array`: Zhang-Suen thinning, treating out-of-bounds as 0, iterating only over currently-set pixels (keep a candidate list) so thick strokes on a 2000x1000 image stay fast; then a cleanup pass that deletes redundant staircase pixels (a pixel with two orthogonal 4-neighbours set, e.g. N and E, where deleting it keeps the 8-connectivity of its neighbourhood — standard "remove pixel if its 8-neighbour crossing number stays 1"), so diagonals do not produce false junctions. Stroke thickness is ignored per world-builder-plan decision "Black = road centreline ... stroke thickness in pixels is ignored".
4. `traceSkeleton(skel, w, h): RoadGraphPx`: count 8-neighbours; degree-1 pixels are endpoints, degree >= 3 pixels are junction pixels. Cluster junction pixels that are 8-adjacent OR within mergeJunctionPx of each other into one node at the cluster centroid (this makes a thinned X a single 4-way node; per plan item 4 "every crossing is a junction" by default). Walk from each node along unvisited skeleton pixels until another node pixel/cluster is hit, recording points. Remaining unvisited pixels are isolated closed loops: split each into two paths between two new nodes placed at roughly opposite points of the loop (no self-loop way). Drop duplicate paths (same node pair, same pixel run walked from both ends) and paths shorter than 2 points.
5. `pruneSpurs(g, minSpurPx)`: repeatedly remove paths that touch a degree-1 node and whose polyline length is < minSpurPx (never remove a path whose BOTH ends are degree-1, i.e. a standalone short road, unless shorter than minSpurPx too — then remove it as noise); after each round, merge degree-2 nodes by concatenating their two paths (skip if both paths are the same loop); recompute degrees; stop when stable.
6. `simplifyPath(points, tolPx)`: Douglas-Peucker, iterative, endpoints kept.
7. `smoothPath(points, iterations)`: Chaikin corner cutting with both endpoints pinned exactly (junction and endpoint positions do not move, so shared nodes stay shared).
8. `imageToRoadGraph(lum, w, h, opts?: Partial<TraceOptions>): RoadGraphPx`: threshold -> removeSpecks -> skeletonize -> traceSkeleton -> pruneSpurs -> per path simplify then smooth then simplify again at tolPx/3 to drop near-collinear Chaikin points. Throw a clear Error if w*h != lum.length.

Write the tests first (RED), commit, then implement (GREEN), then refactor if needed.
  </action>
