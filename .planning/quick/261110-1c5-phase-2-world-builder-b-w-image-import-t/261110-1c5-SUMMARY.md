# Quick 261110-1c5: Phase 2 world builder, B&W image import

Black-on-white pictures are thresholded, thinned to a one-pixel centreline (stroke width ignored), traced into a node/path graph with shared junction nodes, pruned, simplified and smoothed in pixels, scaled to a real width in km, and appended to the editor's roads envelope as ordinary raw-OSM ways (width 8 m, surface asphalt by default). Compiler code is unchanged.

## What was built

- `image-trace.ts` (pure, no DOM): threshold, speck removal, Zhang-Suen thinning plus simple-point cleanup, tracing with junction clustering, spur pruning with degree-2 merge, Douglas-Peucker, pinned Chaikin, `imageToRoadGraph`. A 2000x1000 picture with 12 px strokes traces well inside the test timeout (the whole editor suite runs in about 0.5 s).
- `image-import.ts` (pure): `importScale` (km or m/px, aspect locked, coarse warning above 2 m/px), `footprintWarnings`, `pixelToWorld` (image top = north, offset 0,0 = world SW corner), `appendImportedRoads` (one shared raw node id per graph node = junction; ids from `nextNodeId`/`nextWayId`; tags via `setSurface`).
- Sample PNGs (8-bit greyscale) and the deterministic generator `node tools/map-editor/samples/gen-test-images.ts` (regenerates byte-identical files).
- Editor sidebar "Import image": file picker, threshold slider with amber mask overlay, linked km / m-per-px fields with derived height and readout, x/y offset, road width / highway / surface, advanced tracing (spur, simplify, smoothing), amber warnings, Preview (dashed cyan paths plus junction dots, counts in status) and Import roads (one `snapshot()` so undo works, then `refresh`). Images over 25 megapixels are refused. Changing area clears the import state.

## Deviations from Plan

1. **[Rule 1 - Bug] Trace hardening found by the e2e test.** The first implementation (neighbour-count junction detection, plain Zhang-Suen plus an L-corner cleanup) mis-detected junctions along shallow staircase arms and chained them into bogus nodes on the 60 degree crossing sample. Fixed inside Task 2's commit: simple-point skeleton cleanup, junction classification by ring transitions plus surviving 2x2 blocks, stroke-width-aware junction clustering (3x local half width from a distance transform), and dropping tiny hole loops at a junction. Fixed the trace, not the sample.
2. **TDD ordering.** Tests and implementation for Task 1 were committed together (no separate RED commit); the tests were written alongside and all pass. No separate test(...) commit exists for Tasks 1-2.
3. Image-trace test for shallow crossings relies on the e2e sample (crossing.png, 60 degrees) rather than an extra unit case.

## Known limitations

- Junction clustering reach is 3x local half stroke width: very acute crossings (under about 30 degrees) with thick strokes may still produce two nearby degree-3 nodes. The user can merge them in the editor.
- Import is additive and not snapped to existing roads.
- Thinning shortens open stroke ends by roughly half the stroke width.
